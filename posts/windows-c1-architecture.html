Windows 专项第 1 章：Windows 架构：NT Executive、内核与 HAL

Windows 专项2026-11-25 · Windows 专项

模块二第 13 章讲过 Windows 内部结构，这一章把那张图拆开细讲：Windows 最底层是怎么搭起来的，应用程序的一次点击，要经过多少层才落到硬件上。先记住一句话：Windows 不是一块铁板，而是一座分层的大楼，每一层只跟上下两层打交道。

分层的好处是出了问题好定位：程序崩了不一定是系统坏了，驱动出问题不一定是硬件坏了。学安全的人更要懂分层，因为攻击者最爱找的，就是层与层之间的缝隙——比如从用户态想办法钻进内核态。

本章不要求你背下每个组件的名字，而是要建立一张心智地图：用户程序在哪、系统服务在哪、内核在哪、硬件抽象层在哪。下几章讲进程、注册表、服务时，你会不断回到这张地图上。

先分清用户态和内核态

Windows 把 CPU 的运行状态分成两大块：用户态和内核态。你在桌面上打开的记事本、浏览器、微信，都跑在用户态；操作系统最核心的部分跑在内核态。用户态的程序想碰硬件、想读别的进程的内存，必须通过系统调用向内核申请，不能自己直接动手。

为什么这样分？一是保护：一个用户程序写错了内存，最多自己崩溃，不会把整个系统拖垮；二是安全：恶意软件如果只能待在用户态，它能造成的破坏就有限。反过来，攻击者一旦拿到内核态权限，就等于拿到了整台机器的钥匙——这就是为什么驱动签名、内核隔离这些防护那么重要。

你可以把用户态想象成商场里的店铺，内核态是商场的物业和配电房。店铺之间互相不能乱进对方的仓库，要用电、用水都得向物业申请。店铺可以装修得很花哨，但配电房的门必须锁好。

NT Executive：内核之上的管理层

内核（Kernel）本身很小很精，只负责最基础的事：线程调度、中断处理、同步原语。内核之上是 NT Executive，它是一组管理服务：对象管理器、内存管理器、进程管理器、I/O 管理器、安全引用监视器（SRM）、配置管理器（管注册表）、缓存管理器，等等。

打个比方，内核是工地上的塔吊司机，只负责把东西吊到指定位置；NT Executive 是工地的项目经理，管进度、管材料、管安全、管账本。你平时用的任务管理器里看到的进程、内存占用、句柄数，背后都是 NT Executive 在记账。

对安全工作来说，NT Executive 里最值得认识的是两个角色：安全引用监视器（SRM），每次访问文件、注册表、进程时，它都会查一遍访问令牌和 ACL（第 9 章细讲）；对象管理器，Windows 里几乎所有东西——文件、进程、线程、事件、互斥体——都是对象，有名字、有类型、有权限，统一用句柄来访问。

HAL：让同一套系统跑在不同硬件上

硬件抽象层（HAL，Hardware Abstraction Layer）是 Windows 和硬件之间的一层薄薄的翻译。不同的主板、中断控制器、定时器，HAL 把它们的差异藏起来，让上面的内核看到的是一套统一的接口。

这就是为什么同一份 Windows 安装盘能装在不同品牌的电脑上：换主板、换 CPU 型号，大部分工作由 HAL 和驱动消化，内核不用重写。排障时也要记住这一点：蓝屏信息里如果出现 hal.dll 相关字样，往往要先怀疑硬件、固件或驱动，而不是先怀疑应用程序。

HAL 下面是设备驱动：每块硬件都由驱动程序翻译成系统能懂的语言。驱动跑在内核态——这意味着一个有漏洞的驱动，就是一条通往内核的路。第 10 章讲的虚拟化安全和驱动防护，根子就在这里。

一次点击要走多远

以双击打开一个记事本文件为例：桌面程序（用户态）收到点击，调用 Windows API；API 通过系统调用进入内核态，I/O 管理器找到文件系统驱动，驱动再通过 HAL 和磁盘驱动把文件从硬盘读出来；读出来的内容交给内存管理器放进内存，最后显示在屏幕上。

这条链上的每一个环节都可能被攻击者利用，也都可以被防护：API 层有应用控制，内核层有 PatchGuard 和驱动签名，文件系统层有权限和完整性检查。学安全不是学某一招，而是学会沿着这条链一节一节地问：这一节是谁在把关？如果把关的人被绕过，会发生什么？

本章检查清单

□ Windows 分两层：用户态跑应用，内核态跑系统核心，中间靠系统调用联系。

□ 内核很小，只管线程调度、中断和同步；NT Executive 管对象、内存、进程、I/O 和安全检查。

□ HAL 把不同硬件的差异藏起来，让同一套 Windows 能跑在不同机器上。

□ 驱动跑在内核态，有漏洞的驱动就是通往内核的路，驱动安全就是系统安全的一部分。

□ 排障先定位在哪一层：用户态问题和内核态、驱动层问题的查法完全不同。

□ 把本章的命令和检查步骤抄进自己的笔记，下次遇到同类问题直接用。

老师经验：排障时我最常用的一招，就是先问“它在哪一层”。用户说“电脑卡”，我先看是某个应用占满 CPU（用户态），还是系统进程、中断占用高（内核态、驱动层）。有一次一台电脑间歇性蓝屏，换内存、重装系统都没用，最后发现是主板 BIOS 太旧，HAL 和中断控制器配合出问题——升级 BIOS 就好了。记住：层分得越清，定位越快；上来就重装系统，是最贵、最慢的排障方法。

动手做

1. 只在你自己的虚拟机里：打开任务管理器 → 详细信息，看看 System、Registry、Memory Compression 这几个系统进程，再打开资源监视器，观察 CPU、内存、磁盘三栏，把看到的数字记下来。
2. 在虚拟机里以管理员身份打开 PowerShell，运行 Get-Process | Sort-Object CPU -Descending | Select-Object -First 10，看看谁最占 CPU；再运行 systeminfo，看看系统版本和 BIOS 版本，把它们记进笔记。
3. 对照本章的图，画一遍你自己的分层图：把你常用的三个程序放在最上层，把你知道的系统服务放在中间，标出它们要经过哪些层才能碰到磁盘。

避坑

别在真实电脑、公司的电脑上乱试：本章的查看类操作是只读的，相对安全，但任何“关闭服务、卸载驱动、改注册表”的操作都不要在真实系统上练手；别把“内核态”理解成“更高级的用户程序”：内核态没有进程隔离，出错就是蓝屏，这是它和用户态最本质的区别；别以为重装能解决一切：驱动、固件、HAL 层面的问题，重装系统后还在原地等你。

这一章把 Windows 的分层地图铺好了：用户态与内核态的分界、NT Executive 的管理角色、HAL 的翻译作用。下一章我们从地图走到现场：第 2 章讲一开机就在跑的 SMSS、CSRSS、LSASS——那些名字古怪、却一个都不能杀的系统进程。
