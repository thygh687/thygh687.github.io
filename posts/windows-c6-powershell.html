Windows 专项第 6 章：PowerShell 安全实战

Windows 专项2026-11-25 · Windows 专项

前面几章的检查，用图形界面一个个点也能做，但太慢了。PowerShell 是 Windows 的命令行外壳加脚本语言，是安全工程师每天用的主力工具：查进程、查服务、查日志、查网络连接，几行命令就能出结果，还能把结果存下来、反复跑。

这一章不讲 PowerShell 编程大全，只讲安全实战里最常用的那一小套：怎么安全地用它、怎么查系统状态、怎么从日志和网络里抓异常。目标是：学完这一章，你能用 PowerShell 给自己的虚拟机做一次快速体检。

先说安全底线：PowerShell 本身是中性的工具，攻击者也爱用它（无文件攻击、远程下载执行都离不开它），所以 Windows 给它加了很多防护：执行策略、脚本块日志、AMSI。本章先讲怎么用，再讲怎么防它被滥用。

先把 PowerShell 用安全

打开方式：按 Win+X → “终端（管理员）”或“Windows PowerShell（管理员）”。很多检查命令需要管理员权限才能看到完整信息，养成用管理员身份打开的习惯。分清两个版本：Windows PowerShell 5.1（系统自带）和 PowerShell 7（可另外安装），命令大部分通用，本章的命令在 5.1 里都能跑。

执行策略（Execution Policy）是第一道门：它决定能不能运行脚本。默认的 Restricted 是不允许运行脚本，RemoteSigned 是允许本地脚本、远程脚本要签名。查看用 Get-ExecutionPolicy，改用 Set-ExecutionPolicy RemoteSigned。注意：执行策略不是安全边界，它防的是“不小心双击了脚本”，防不住有意绕过的人——真正的安全靠脚本块日志和 AMSI。

两个关键防护要知道：脚本块日志会把运行过的脚本内容记进事件日志（第 8 章），方便事后追查；AMSI（反恶意软件扫描接口）会在脚本运行前让杀毒软件先扫一遍。做安全检查时，脚本块日志是你找“谁在这台机器上跑过什么脚本”的好地方。

快速体检：进程、服务、网络

体检三件套：进程用 Get-Process | Sort-Object CPU -Descending | Select-Object -First 10；服务用 Get-Service | Where-Object Status -eq Running；网络连接用 Get-NetTCPConnection | Where-Object State -eq Listen，看机器在监听哪些端口（对照模块三第 10 章的端口表）。

查启动项和计划任务：Get-CimInstance Win32_StartupCommand 列出启动命令；Get-ScheduledTask | Where-Object State -eq Ready 列出就绪的任务。把输出存成文件方便慢慢看：命令后面加 | Out-File C:\Users\Public\check.txt。

查系统信息：Get-ComputerInfo 看系统版本和硬件；Get-HotFix 看已安装的补丁；Get-WindowsUpdateLog（或直接看设置里的更新历史）看补丁状态。补丁没打全，是体检里最常见的“高风险项”。

从日志和事件里抓异常

PowerShell 读事件日志用 Get-WinEvent 或 Get-EventLog。最常用的两个查询：登录失败用 Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4625} -MaxEvents 20；系统错误用 Get-WinEvent -FilterHashtable @{LogName='System'; Level=2} -MaxEvents 20。4625 是登录失败，4624 是登录成功，4672 是管理员登录——这几个事件 ID 值得背下来。

抓异常的思路是“先看正常，再找异常”：先看看平时登录成功的账号、时间、来源，再找半夜三点、陌生账号、反复失败的记录。一次两次失败可能是输错密码，一分钟内几十次失败就是有人在猜密码。

还可以用 PowerShell 查文件哈希：Get-FileHash 文件路径 -Algorithm SHA256，算出文件的指纹，再去官方公布的哈希值对照——下载的安装包是不是被篡改过，一比就知道。

写个小脚本：把体检自动化

把常用的检查写成一个 .ps1 脚本文件，下次体检双击运行就能出报告。脚本不用复杂：每行一个命令，输出重定向到一个文本文件，最后加一句 Write-Host '检查完成'。比如：Get-Process、Get-Service、Get-NetTCPConnection、Get-HotFix 各写一行，统一输出到 check-日期.txt。

写脚本时注意三点：只在自己的虚拟机里跑自己写的脚本；从网上复制的脚本先读懂每一行再跑，不认识的命令先查清楚；脚本里不要写密码、不要把敏感输出发到网上。脚本本身也是代码，要像对待程序一样对待它。

进阶方向：学 Select-Object、Where-Object、Sort-Object、Export-Csv 这四个命令的组合，就能把“查出来”变成“整理成表格”。比如 Get-Service | Where-Object Status -eq Running | Export-Csv services.csv，就得到一张正在运行的服务清单。

老师经验：我每天上班第一件事，就是跑一遍自己的体检脚本：进程、服务、监听端口、最近 24 小时的登录失败，四样东西十分钟看完。最有价值的一次，是脚本发现一台测试机半夜有几百次 4625 登录失败——有人在用字典猜一个服务账号的密码，及时改了密码、封了来源，才没出事。我的建议是：别追求写多复杂的脚本，先把“每天看一遍”的习惯建立起来；命令记不住没关系，记在笔记里，用的时候翻出来，翻三次就记住了。

动手做

1. 只在你自己的虚拟机里：以管理员身份打开 PowerShell，依次运行 Get-Process、Get-Service、Get-NetTCPConnection，把输出保存下来：Get-NetTCPConnection | Where-Object State -eq Listen | Out-File C:\Users\Public\ports.txt，打开文件，对照模块三的端口表认一认每个端口。
2. 在虚拟机里运行 Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4625} -MaxEvents 10 -ErrorAction SilentlyContinue，看看有没有登录失败记录；再运行 Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 10，看看最近打了哪些补丁。
3. 在虚拟机里写一个体检小脚本 check.ps1：把上面的三条命令写进去，输出到 check.txt，运行它（如果提示执行策略不允许，先运行 Set-ExecutionPolicy RemoteSigned -Scope CurrentUser），打开生成的报告看看。

避坑

别在真实电脑、生产系统上跑来路不明的脚本：先读懂每一行，不认识的命令先查；执行策略不是安全边界：别以为设成 Restricted 就万事大吉，真正靠得住的是日志和 AMSI；别把 PowerShell 的输出随手发到网上：进程列表、网络连接里可能有你的用户名、内网地址等敏感信息；别用 PowerShell 关掉你不认识的服务或进程：先查清那是什么，再决定动不动手。

PowerShell 是把前面几章的检查变成“几行命令就能跑”的工具，也是攻击者爱用的工具——用好它、管好它，是一体两面。下一章我们认识微软官方的排障套件：第 7 章 Sysinternals——Process Explorer、Autoruns、Process Monitor，排障和取证的“三件套”。
