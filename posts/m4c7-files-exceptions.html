模块四第 7 章：文件操作与异常处理

编程基础2026-11-25 · 模块四

前面几章的程序都有一个毛病：数据全靠手工输入，程序一关就全没了。真实的安全工作恰恰相反：数据都在文件里——日志文件、扫描结果、黑名单、配置文件。程序的价值，很大一部分就是替你读写这些文件。这一章讲两件事：怎么用 Python 读写文件，以及文件不存在、格式不对、权限不够时，程序怎么优雅地处理而不是直接崩溃。练手只用自己的虚拟机里的日志文件，绝不碰别人的机器、别人的数据。

打开文件：open 与三种模式

Python 里读写文件的入口是 open()：第一个参数是文件路径，第二个是模式。"r" 是读（read），"w" 是写（write，会清空原有内容），"a" 是追加（append，在末尾接着写）。

f = open("notes.txt", "r", encoding="utf-8")
content = f.read()
print(content)
f.close()

这里有三个细节值得记住。第一，encoding="utf-8" 要写上：中文文件如果不指定编码，在 Windows 上容易读出乱码——模块一第 14 章讲过字符编码的坑，这里就是它在现实里的样子。第二，读完要 close()：打开的文件占着系统资源，不关会越积越多。第三，"w" 模式会毫不留情地清空文件——想往里加东西用 "a"，想写新文件才用 "w"。把 "w" 用在重要文件上，是新手最心痛的一次教训。

路径也有讲究："notes.txt" 这种相对路径，意思是“和程序在同一个文件夹里的 notes.txt”；绝对路径是写全的，比如 Linux 下的 "/home/yufei/logs/app.log"。写程序时优先用相对路径，换台机器也能跑。路径里的反斜杠在 Windows 上要小心："C:\new\test.txt" 里的 \n 会被当成换行符，正确写法是用正斜杠 "C:/new/test.txt" 或者在字符串前面加 r 写成原始字符串 r"C:\new\test.txt"。

with 语句：让 Python 替你关文件

每次 open 都要记得 close，人总会忘。Python 给了一个更省心的写法：with 语句。它保证不管中间出不出错，退出这段代码块时文件一定会被关掉：

with open("notes.txt", "r", encoding="utf-8") as f:
    content = f.read()
    print(content)
# 离开 with 块，文件已经自动关掉了，不用写 close()

从现在起，读写文件一律用 with。它不只是一个省事的写法，更是一种安全习惯：资源（文件、网络连接、数据库）用完要释放，靠人工记忆总会漏，靠语言机制才可靠。后面你会看到，with 的思想会反复出现。

逐行读：处理大日志的正确姿势

日志文件动不动就几十万行，一次 read() 全读进内存，机器吃不消。正确姿势是逐行读：一次只读一行，处理完再读下一行，内存里永远只有一行。

count = 0
with open("app.log", "r", encoding="utf-8") as f:
    for line in f:          # 文件对象本身就是可循环的，一次给一行
        if "ERROR" in line:
            count += 1
print("ERROR 出现了", count, "次")

这几行代码就是一个能用的日志分析器雏形：逐行读，判断某一行里有没有“ERROR”，有就计数。和第 3 章的字典计数器拼起来，就能统计“每个 IP 失败了几次”；和第 6 章的函数拆分拼起来，就能写出“读日志、分析、写报告”三段式的完整工具。写文件也一样简单：

with open("report.txt", "w", encoding="utf-8") as f:
    f.write("扫描报告\n")
    f.write("发现 3 个开放端口\n")

异常处理：出错了怎么办

程序跑起来之后，世界并不总是配合：文件可能不存在、路径可能写错、文件可能被别的程序占着、某一行的格式可能不对。如果不处理，Python 会抛一个异常（exception），程序当场崩溃，之前的结果全丢了。异常处理就是给程序穿上救生衣：可能出问题的地方，用 try/except 包起来，出错时按你写好的办法处理，而不是直接沉底。

try:
    with open("app.log", "r", encoding="utf-8") as f:
        lines = f.readlines()
except FileNotFoundError:
    print("文件不存在，请检查路径是不是写错了。")
    lines = []
except PermissionError:
    print("没有权限读这个文件，换个文件试试。")
    lines = []

try 里放“可能出错的代码”，except 后面跟“出了这种错怎么办”。异常是有名字的：FileNotFoundError 是文件不存在，PermissionError 是权限不够，ValueError 是值不对（比如拿 int() 转一段不是数字的文字）。针对不同的错，写不同的处理——这比笼统地“出了错就跳过”要好得多，因为你能分清“文件不存在”和“权限不够”是两种完全不同的问题。

异常处理还有两个常用的搭档：else（没出错时才执行）和 finally（不管出不出错都执行，常用来做收尾清理）。以及一条重要的经验：except 后面别写空的 pass——出错了却假装没看见，是现场最难查的 bug。至少打印一句日志，说明哪一步出了什么错。

读自己的日志练手

最好的练手材料就是你虚拟机里现成的日志。Linux 虚拟机里，/var/log/syslog 或 /var/log/auth.log 是系统日志（读它们可能需要权限，读不了就换自己造的假日志）；Windows 虚拟机里，可以用自己程序的输出造一份假日志。下面是一份可以直接用的假日志，你可以先把它存成 test.log，再用程序分析它：

2026-11-25 08:01:12 10.0.0.5 登录成功
2026-11-25 08:02:03 10.0.0.9 登录失败
2026-11-25 08:02:15 10.0.0.9 登录失败
2026-11-25 08:03:40 10.0.0.5 登录成功
2026-11-25 08:04:22 10.0.0.9 登录失败
2026-11-25 08:05:10 10.0.0.23 登录失败

分析它的程序，就是把本章和前面几章的零件拼起来：逐行读文件，用 split() 把一行按空格切开，取到 IP 那一段，用字典计数“每个 IP 失败了几次”，最后把结果写进报告文件。完整的写法在“动手做”里，你先自己试，再对照思路。注意：这里用的全是自己造的假 IP、假日志，真实的日志文件里可能有敏感信息，分析之前先想清楚“这份日志该不该我看、能不能存下来”。

老师经验：现场排错，我有一半时间是在读日志，另一半时间是在写读日志的程序。印象最深的一次，是客户的服务器半夜总被登录失败刷屏，日志文件几百 MB。我写了个小程序：逐行读、只统计“登录失败”的行、按 IP 计数、按次数排序输出，前三名 IP 一眼就能看见，剩下的事就是封禁和加固。两个教训：第一，读大文件永远逐行读，别 read() 一把全读进内存——我见过有人这么干，程序直接把内存吃满、机器卡死；第二，写报告之前先确认输出路径——有一次同事把报告写到了系统盘根目录，权限不够，程序跑了半小时最后一步写文件时崩了，之前的结果全白费。从那以后我的习惯是：程序开头先试写一个空的报告文件，确认能写，再开始分析。

动手做

1. 在虚拟机里新建 test.log，把本章那 6 行假日志存进去；写程序逐行读它，数一数“登录失败”出现了几次，再数一数“登录成功”出现了几次。
2. 升级这个程序：用字典统计每个 IP 的失败次数，输出像这样的结果：10.0.0.9 失败 3 次。提示：用 line.split() 切开一行，IP 是第 3 段（下标是 2）。
3. 把统计结果写进 report.txt（用 "w" 模式），再打开文件确认内容对不对；然后故意把文件名写错一个字母（比如 test2.log），跑一遍，看 try/except FileNotFoundError 是不是接住了错误、程序是不是没有崩溃。
4. 试一试 "w" 和 "a" 的区别：先用 "w" 写一行，再用 "a" 追加一行，打开文件看是不是两行都在；再用 "w" 写一行，打开看——之前的内容是不是被清空了。记住这个差别，它能帮你避免一次心痛的数据丢失。

避坑

别用 "w" 打开重要文件：它会先清空再写，想追加用 "a"；别忘了 encoding="utf-8"：中文日志不写编码容易读出乱码；别 read() 一把读进大文件：几十万行的日志要逐行读；别在 except 里写空的 pass：出错了要留一句记录，否则以后查都查不到；别把 Windows 路径里的反斜杠直接写进字符串：用正斜杠或原始字符串；别分析不该看的日志：真实日志可能含敏感信息，先确认权限和范围，只在自己的虚拟机和授权范围内练手。

会读写文件、会处理异常，程序就开始像个真正的工具了。但日志里想找的东西往往不是整行匹配的“ERROR”这么简单，而是藏在行里的某个模式：一个 IP、一个日期、一个状态码。怎么把它们精准地抠出来？下一章：正则表达式就是干这个的。

本课小结
  • open() 打开文件："r" 读、"w" 写（会清空）、"a" 追加；记得写 encoding="utf-8"。
  • with 语句保证文件用完自动关闭，读写文件一律用它；Windows 路径用正斜杠或原始字符串。
  • 大日志要逐行读（for line in f），内存里永远只有一行，别一把 read() 全读进来。
  • try/except 让程序出错时按你写好的办法处理而不是崩溃；不同异常（文件不存在、权限不够）要分开处理。
  • 读日志、字典计数、写报告拼起来，就是一个真正的日志分析工具；练手只用自己造的假日志和自己虚拟机里的日志。
