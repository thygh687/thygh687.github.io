模块二第 2 章：进程

操作系统2026-11-24 · 模块二

程序是存在硬盘上的静态文件，跑起来就是进程。双击打开浏览器，硬盘上的程序被装进内存，操作系统给它分配资源、建一个进程，这个程序才算“活”了。进程是操作系统分配资源的基本单位。上一章说的“大管家分配资源”，分配的对象就是进程：CPU 时间、内存、打开的文件，都是按进程记账的。

进程里有什么

每个进程有一块独立的内存空间（代码、数据、栈、堆），有一套寄存器状态，有打开的文件和网络连接。操作系统用一个叫进程控制块（PCB）的数据结构记录这些信息：进程是谁、状态如何、用了多少资源。进程之间默认互相看不见对方的内存，这就是隔离。

PCB 里到底有哪些字段？PCB 是操作系统管理进程的“档案袋”，进程一创建就建好，进程一结束就回收。常见的字段有下面这些，每一项都是一句话能说清的用途：

  • 进程标识符（PID）：进程唯一的编号，操作系统靠它区分“哪个进程是哪个”。
  • 进程状态：记录进程当前处在新建、就绪、运行、阻塞、终止、挂起中的哪一个状态。
  • 程序计数器：记录下一条要执行的指令在内存里的地址，进程被切走后靠它接着往下跑。
  • 寄存器快照：保存进程被切走那一刻各寄存器的值，轮到它再跑时原样恢复。
  • 内存管理信息：记录进程的内存空间怎么安排，比如页表、段表、代码和数据的起止地址。
  • 打开的文件和设备：记录进程打开了哪些文件、用了哪些设备，进程结束时要按这张表收回。
  • 优先级与调度信息：记录进程的优先级、已用的 CPU 时间等，供调度器决定下一个轮到谁跑。
  • 父子关系：记录父进程是谁、有哪些子进程，排错时靠它追踪进程的来历。
  • 资源使用与记账信息：记录进程已用的 CPU 时间、内存、I/O 次数等，是按进程记账的依据。

记住一个比喻就行：PCB 不是进程本身，它是操作系统手里的“进程档案”——进程在内存里跑，档案在操作系统手里管。查进程出问题时，任务管理器、ps 命令显示的 PID、状态、优先级、内存占用，背后读的都是 PCB 里的字段。

为什么隔离这么重要？两个原因。第一是稳定：一个进程写错了内存、崩了，最多自己死掉，不会把别的进程一起拖下水——浏览器一个标签页崩了，其他标签页还能用，就是隔离在起作用。第二是安全：你的浏览器看不到杀毒软件内存里的东西，普通程序也读不到别的程序的密码。如果没有隔离，任何一个程序都能随便翻别人的内存，权限就形同虚设。隔离不是顺带的优点，它是操作系统存在的理由之一。

但隔离也不是铁板一块：进程想跟别的进程说话，得走专门的通道——第 4 章的进程间通信就是讲这些通道的；进程里干活的单位也不是进程自己，而是第 3 章的线程。进程是“房子”，线程是“住在里面干活的人”，房子之间有墙，房子里的人共用一个客厅。

进程的状态

就绪：等着 CPU 来跑。运行：正在 CPU 上跑。阻塞：等着某件事（比如等硬盘读数据、等用户输入），暂时跑不了。操作系统不停地在这些状态之间切换进程，所以你的电脑能同时开着浏览器、音乐和聊天软件——其实 CPU 在飞快地轮流跑它们。

完整的五态模型：上面三个状态还不完整。完整的五态是新建、就绪、运行、阻塞、终止。新建是进程刚被创建、还没准备好上 CPU 的状态：操作系统正在给它建 PCB、分配内存，建好了才进就绪队列排队。终止是进程已经结束、正在被回收的状态：程序跑完了或被杀掉了，操作系统要收回它的内存、关闭它打开的文件、回收 PCB，收拾干净才算真正消失。画成一条线就是：新建 → 就绪 → 运行 → 终止；运行中途等不到东西就进阻塞，等到了再回就绪，重新排队等 CPU。

为什么要单列“新建”和“终止”？因为创建和收尾都不是一瞬间的事。新建时资源还没配齐，不能直接上 CPU；终止时资源还没收回，也不能立刻把位置让给别人。Linux 里子进程退出后父进程迟迟不来“收尸”，进程卡在终止状态不走，就是上一节说的僵尸进程——状态图上的“终止”，在现实里就是这么被卡住的。

七态模型：多出来的两个挂起状态。五态之外还有七态，多出来的是就绪挂起和阻塞挂起。挂起的意思是：进程被操作系统暂时“换出”到外存（硬盘）上，内存里的位置先让出来。阻塞挂起是原来在阻塞的进程被换出去了——它本来就在等东西，等的东西没来，又不占内存了；就绪挂起是原来在就绪队列里排队的进程被换出去了——它随时能上 CPU，只是因为内存不够，先到外存上等着，等内存腾出来再被换回就绪队列。

什么时候会挂起？最常见的原因是内存不够：同时跑的进程太多，内存装不下，操作系统就把一些暂时不急的进程换到外存上腾地方；另外也可能是用户或系统管理员手动挂起某个进程（比如在任务管理器里挂起一个进程），或者是系统负载太高、要优先保住重要进程。挂起是操作系统主动做的内存管理动作，不是进程自己请求的。

挂起和阻塞不一样，别混了。阻塞是进程自己在等一件事（等硬盘、等输入、等锁），等的东西一来就能回就绪；挂起是操作系统把进程换到了外存，进程想回内存还得等操作系统把它换回来。阻塞挂起的进程要先被换回内存、变成普通阻塞，等的东西到了才能回就绪；就绪挂起的进程被换回内存就直接回到就绪队列。一句话：阻塞是“等事件”，挂起是“被换出内存”，一个进程可以既阻塞又挂起。

状态出错意味着什么？看状态是排错的捷径：一个进程长期卡在“阻塞”，说明它在等的东西一直没来——可能是硬盘太慢、网络没响应，也可能是它在等一把永远等不到的锁（第 5 章的死锁就是这么来的）；一个进程长期占着“运行”不放手，CPU 占用率居高不下，就要怀疑它是不是在空转、死循环，或者是挖矿木马（第 6 章调度会讲调度器怎么对付这种进程）。状态本身不告诉你病因，但它告诉你往哪个方向查。

还有一点容易搞错：“同时运行”其实是轮流跑。一个 CPU 核心同一时刻只能跑一个进程，所谓“同时开着几十个程序”，是操作系统在几毫秒一切换一次，轮流给每个进程一点时间。切换得足够快，你才感觉它们在同时跑。切换本身有代价——保存现场、恢复现场都要花时间——这就是第 6 章要讲的上下文切换。

一次上下文切换要付出什么

上下文切换就是 CPU 从跑进程 A 换成跑进程 B，中间要做的事可以从三个角度看。第一，保存和恢复寄存器：要把进程 A 的程序计数器、各寄存器的值存进它的 PCB，再把进程 B 上次存好的值从 PCB 里取出来装回去——这两步本身就要花 CPU 时间，而且这段时间里 CPU 没在跑任何一个进程的正事。第二，缓存被换掉：进程 A 刚用过的数据还留在 CPU 的高速缓存里，换成进程 B 后，缓存里大多是 B 用不上的旧数据，B 要用的东西得重新从内存读，命中率一下就掉下来了，刚开始跑的那一阵会明显变慢。第三，TLB 被冲掉：TLB 是记录虚拟地址到物理地址映射的小表，切换进程后，旧的映射大多失效，要重新填——每次地址转换都可能要多走一步去查页表，内存访问就变慢了。

所以切换太频繁会拖慢系统：时间片定得太短，CPU 一大半时间都花在切换本身和重新热缓存、重新填 TLB 上，真正干活的时间反而少了；时间片定得太长，交互又会变卡顿。调度器要在“响应快”和“切换少”之间找平衡。至于调度器具体按什么规则决定下一个轮到谁、每个进程分多长时间片，那是调度算法的事，细节在第 16 章：调度深入讲 MLFQ 和 CFS 时展开，这里只要记住：切换不是免费的，进程本身的状态和切换的代价，才是本课要掌握的东西。

进程的创建和结束

新进程由老进程创建：Linux 里是 fork（复制一个自己）再 exec（换成要跑的程序）；Windows 里是 CreateProcess。进程结束有正常退出和被杀掉两种：程序自己跑完，或者被用户、被系统、被另一个进程杀掉。

创建要看“父进程是谁”。每个进程都有一个爹：浏览器是你双击启动的，它的父进程就是资源管理器；系统服务 svchost.exe 的父进程应该是 services.exe。如果一个 svchost.exe 的父进程是某个来路不明的程序，或者干脆没有父进程，那就要警惕了——恶意软件最爱干的事，就是让自己看起来像系统进程，却藏不住父子关系这一关。老师经验里那三样检查，第一样就是这个。

结束也有讲究：进程死了，不等于收拾干净了。Linux 里，子进程退出后，父进程要来“收尸”（回收它的退出状态）；父进程一直不来收，死掉的进程就成了“僵尸进程”——已经死了，进程表里还占着一个位置。僵尸进程本身不占 CPU、不占内存，但攒得太多会把进程表占满，新进程就建不出来了。反过来，父进程先死了，子进程就成了“孤儿”，会被系统收养（交给 init 或 systemd 接着管）。在任务管理器或 ps 里看到一堆僵尸进程，先别急着杀——杀是杀不掉的（它已经死了），要找那个一直不来收尸的父进程。

退出码也值得看一眼：程序正常退出一般返回 0，非 0 往往表示出错。排错时先看退出码，再决定往下查什么，比盲目重装快得多。

老师经验：恶意软件最喜欢伪装成正常进程的名字，比如 svchost.exe、explorer.exe。安全值守查进程，从来不只看名字，要看三样：路径对不对（真的 svchost.exe 在 C:\Windows\System32 下面）、父进程是谁（它的“爹”应该是 services.exe）、启动参数有没有古怪。名字会骗人，这三样很难全骗过去。

动手做

1. 打开任务管理器 → 详细信息，看进程的 PID、状态、用户名。
2. 右键一个进程 → 打开文件所在位置，看它的真实路径。
3. 在虚拟机的 Linux 里输入 ps aux，看进程列表，再输入 ps -ef --forest 看父子关系。

避坑

别把“程序”和“进程”混为一谈：程序是静态的，进程是跑起来的；一个程序可以同时跑出多个进程（比如开两个浏览器窗口）；进程之间默认是隔离的，这是安全的基础，后面讲漏洞还会回来。

本课小结
  • 程序是静态文件，进程是跑起来的程序；进程是操作系统分配资源的基本单位，CPU 时间、内存、文件都按进程记账。
  • 进程之间默认隔离：一个崩了不拖垮别人，别的程序也读不到它的内存——隔离既是稳定性的来源，也是安全的基础。
  • 进程有三种状态（就绪、运行、阻塞），长期卡在阻塞或长期占着运行，都是排错的线索。
  • 查可疑进程不只看名字，要看路径、父进程、启动参数这三样；僵尸进程要找不来收尸的父进程，而不是去杀僵尸本身。
  • 完整的进程状态是五态（新建、就绪、运行、阻塞、终止），七态再加就绪挂起和阻塞挂起：挂起是被换到外存、让出内存，阻塞是等一件事，两者不一样；PCB 里记着 PID、状态、程序计数器、寄存器快照、内存信息、打开的文件、优先级和父子关系。
  • 上下文切换不是免费的：要保存和恢复寄存器、缓存被换掉导致命中率下降、TLB 被冲掉要重新填，切换太频繁会拖慢系统；调度算法的细节见第 16 章：调度深入。
