Windows 专项第 9 章：Windows 安全模型：令牌、SID、ACL 与完整性级别

Windows 专项2026-11-25 · Windows 专项

谁能动什么，由谁说了算？这是所有操作系统的核心问题。Windows 的答案是一套叫“访问控制”的机制，核心是三个概念：SID（你是谁的编号）、令牌（你手里拿的通行证）、ACL（每个东西门口贴的名单）。再加一个完整性级别（你的可信度等级）。

这一章是 Windows 专项里最“原理”的一章，但也是最值得啃的一章：理解了它，前面讲过的 LSASS、权限、UAC、服务账号，全部都能串起来；后面讲的漏洞利用缓解，也是在这套模型上再加护栏。

先给一个生活比喻：SID 是你的身份证号，令牌是你进大楼时领的临时出入证（上面写着你是谁、属于哪些部门），ACL 是每个房间门口贴的“谁能进”名单，完整性级别是你的安全等级（访客只能待在一楼，管理员能上顶楼）。

SID：每个账号和组的唯一编号

Windows 里每个用户、每个组、每台电脑，都有一个唯一的 SID（安全标识符），格式像 S-1-5-21-xxx-xxx-xxx-1001。用户名可以改、可以重名，SID 不会变、不会重。系统认人认的是 SID，不是名字——这就是为什么删了用户再建一个同名用户，旧文件的权限不会自动回来：SID 不同了。

几个有名的固定 SID 值得认识：S-1-5-18 是 LocalSystem（系统账号，最高权限），S-1-5-19 是 LocalService，S-1-5-20 是 NetworkService，S-1-5-32-544 是 Administrators 组，S-1-5-32-545 是 Users 组。查 SID 的命令是 whoami /user，看当前登录用户的 SID；wmic useraccount get name,sid 可以列出所有账号的 SID。

组也是靠 SID 认的：一个用户属于哪些组，就等于他拿到了哪些组的 SID。权限检查时，系统会把用户自己的 SID 和他所属组的 SID 一起算进去。

令牌：登录时领的通行证

你登录时，LSASS（第 2 章）验证密码通过后，会给你发一个访问令牌（Access Token）：里面装着你的 SID、你所属组的 SID、你的权限列表（比如能不能关机、能不能改时间）。之后你打开的每个程序，都会带着这个令牌的副本去访问文件、注册表、进程——系统每次都拿令牌和目标的 ACL 对一遍，才决定放不放行。

令牌有两种：主令牌（登录时发的，跟着你的整个会话）和模拟令牌（服务器程序临时借用客户端身份时用的）。还有一个关键概念是权限（Privilege）和访问权的区别：权限是系统级的特权（比如 SeDebugPrivilege 调试权限、SeShutdownPrivilege 关机权限），访问权是对某个具体文件、某个具体对象的读、写、执行。

UAC（用户账户控制）就是令牌的“分身术”：管理员登录时其实拿的是两个令牌，一个是过滤后的标准用户令牌（平时用这个），一个是完整的管理员令牌（点“是”提权时才用）。这就是为什么管理员平时打开程序也没有管理员权限，要右键“以管理员身份运行”才有。

ACL：每个对象门口的名单

ACL（访问控制列表）是贴在每个对象（文件、目录、注册表键、进程、服务）门口的名单，分两部分：DACL（自主访问控制列表）写着“谁能对这个对象做什么”，SACL（系统访问控制列表）写着“访问这个对象时要不要记日志（审核）”。

DACL 里每一条叫 ACE（访问控制项）：写着某个 SID、允许还是拒绝、读还是写还是执行。检查顺序是：先看有没有明确的“拒绝”，再看有没有“允许”，都没有就默认拒绝。记住：拒绝优先于允许，而且“没有允许”就等于“不允许”——默认拒绝是安全模型的基石。

看 ACL 的办法：文件右键 → 属性 → 安全页；PowerShell 里用 Get-Acl 文件路径 | Format-List。排障时常见的权限问题有两种：权限给多了（普通用户能改系统文件），权限给少了（程序读不到自己该读的文件）。

完整性级别：可信度的等级

完整性级别（Integrity Level）是 Windows 给进程和对象打的“可信度等级”，从低到高是：低（Low）、中（Medium）、高（High）、系统（System）。普通程序跑在中完整性级别，管理员提权后跑在高完整性级别，系统进程跑在系统级别。

规则是：低完整性级别的进程不能写中、高级别的对象——这就是“低不能写高”，和模块六讲过的 Biba 模型“不上写”是同一个道理。浏览器的沙箱就靠这个：浏览器标签页跑在低完整性级别，就算网页里的恶意代码跑起来了，它也写不了你用户目录下的文件。

查完整性级别用 whoami /groups，看当前令牌的完整性级别标签；Process Explorer 里也能看到每个进程的完整性级别。排障时如果一个程序“能读不能写”，先看看它的完整性级别是不是比目标文件低。

本章检查清单

□ SID 是每个账号和组的唯一编号，系统认 SID 不认名字。

□ 登录时 LSASS 发访问令牌，里面装着 SID、所属组和权限列表。

□ ACL 是对象门口的名单：拒绝优先于允许，没有允许就等于不允许。

□ UAC 下管理员平时拿过滤后的令牌，提权时才用完整令牌。

□ 完整性级别分低、中、高、系统四级，低不能写高，浏览器沙箱就靠它。

□ 把本章的命令和检查步骤抄进自己的笔记，下次遇到同类问题直接用。

老师经验：有一次用户说“我是管理员，为什么改不了这个文件”，我一看：文件在系统目录下，所有者是 TrustedInstaller，ACL 里没有 Administrators 的写权限——管理员也不是万能的，ACL 说了算。另一个常见误会是“我是管理员，所以我能干一切”：UAC 下管理员平时拿的是过滤后的令牌，很多操作要显式提权。我的经验是：遇到“权限不够”的报错，别先想着“怎么绕过权限”，先想想“这个权限设计是不是在保护我”——很多提权漏洞，就是攻击者把这句提醒当成了耳旁风。还有，查权限用 Get-Acl 和 icacls，比在图形界面一页页点快得多。

动手做

1. 只在你自己的虚拟机里：打开 PowerShell，运行 whoami /user 看自己的 SID，再运行 whoami /groups 看自己属于哪些组、完整性级别是什么；再运行 whoami /priv 看自己的令牌里有哪些权限。
2. 在虚拟机里新建一个测试文件，右键 → 属性 → 安全，看看有哪些用户和权限；再在 PowerShell 里运行 Get-Acl .\test.txt | Format-List，看看命令行下的 ACL 长什么样。
3. 在虚拟机里以普通用户身份打开记事本，试着保存文件到 C:\Windows\System32\ 下（会失败），再右键记事本 → 以管理员身份运行，再试一次，对比两次的不同，体会 UAC 和完整性级别的作用。

避坑

别在真实电脑上乱改系统文件、系统目录的 ACL：改错了系统可能无法启动，练手只在虚拟机里做；别以为管理员能干一切：ACL 和完整性级别对管理员同样生效，TrustedInstaller 拥有的文件管理员也改不了；别把“拒绝”当成摆设：DACL 里一条拒绝就能盖过十条允许，排障时先看有没有拒绝项；别用管理员账号日常上网、收邮件：管理员令牌一旦被盗就是整台机器，日常用标准用户，需要时再提权。

SID 认人、令牌是通行证、ACL 是门口名单、完整性级别是可信度——Windows 安全模型的四件套齐了。最后一章我们看系统在模型之外再加的护栏：第 10 章漏洞利用缓解——DEP、ASLR、CFG 与虚拟化安全，攻击者就算找到漏洞，也很难得手的那几道防线。
