模块八第 15 章：网络取证与内存取证工作流

安全运营与应急响应2026-11-25 · 模块八

上一章我们在磁盘里找时间，这一章我们看两个更“活”的地方：网络和内存。磁盘取证看的是“过去发生过什么”，网络取证和内存取证看的是“正在发生什么”——数据正往哪传、内存里正跑着什么。攻击者可以删日志、可以改文件时间，但数据要传出去就得走网络，恶意代码要运行就得进内存。这两个地方，是攻击者最难彻底擦干净的地方。边界先说清：本章只用你自己的实验流量和内存镜像——你自己的虚拟机之间产生的流量、你自己的虚拟机的内存快照。绝不在真实网络上抓包，绝不碰别人的机器。

先说为什么网络和内存要放在一起讲：因为它们互相印证。网络抓包看到“某台机器半夜往一个陌生 IP 传了 200MB 数据”，内存镜像里看到“同一个时间点，一个可疑进程正在运行，里面藏着那个陌生 IP 的地址”——两件事一对上，结论就站住了。反过来，只看一边的证据都容易走偏：光看网络，你不知道是哪个进程在传；光看内存，你不知道数据传到哪去了。取证工作流的精髓，就是让不同的证据互相印证，这也是第 6 章证据链思想的延续。

网络取证：从抓包里找故事

网络取证的原材料叫 PCAP（抓包文件），是用 Wireshark 或 tcpdump 这类工具把流过网卡的数据包原样存下来的文件。分析 PCAP 有个固定的顺序：先看统计，再看会话，最后看内容。统计是先看全貌：哪个 IP 流量最大？哪个端口最活跃？有没有平时不出现的境外 IP？Wireshark 的“统计 → 会话”一眼就能看到这些。会话是把一堆数据包按“谁和谁说话”分组：一个会话就是一次完整的连接，比如一次网页访问、一次文件下载。内容是打开可疑的会话，看里面到底传了什么——下载的文件、提交的表单、DNS 查询的域名。

网络取证里最常找的三类痕迹：第一，DNS 异常。攻击者的恶意域名常常是一长串随机字符，或者刚注册没几天的域名；一台机器短时间内查询几百个不存在的域名，可能是域名生成算法（DGA）在找它的控制服务器。第二，异常外联。办公电脑半夜往境外 IP 传大量数据、或者用不常见的端口（比如 4444、8080）对外连接，都值得深挖。第三，明文里的秘密。现在大部分流量是加密的（TLS 1.3 是当前主流，握手过程本身也是加密的），但 DNS 查询、证书里的域名（SNI）、HTTP 明文请求这些“边角料”常常还是可见的——取证时先看这些边角料，往往就能定位问题。当然也要知道边界：加密流量的内容是看不到的，看到“看不到”本身也是信息——比如一台机器突然开始大量使用加密连接，本身就值得问一句“它在跟谁说话”。

内存取证：看正在跑的东西

内存取证的原材料叫内存镜像，是把一台机器内存里的内容原样导出来的文件。内存是易失的——断电就没了，所以第 6 章的易失性顺序里，内存排在很前面：要取证，先抓内存，再关机。分析内存最常用的工具是 Volatility，它能从内存镜像里“还原”出当时正在运行的进程、打开的网络连接、加载的驱动、甚至命令行历史。内存取证最常找的四样东西：进程列表——有没有名字像系统进程、路径却不对的假冒进程（比如本该在 C:\Windows\System32 下的 svchost.exe，出现在了临时文件夹里）；网络连接——当时哪些进程正在对外连接，连的是谁；注入的代码——有没有进程里藏着不属于它的代码段，这是无文件攻击的典型特征；命令行和环境——可疑进程启动时用的什么命令、传了什么参数。

内存取证还有一个独特价值：能看到解密后的东西。磁盘上的文件可能是加密的、网络上传的可能是加密的，但程序要在内存里运行，就必须先解密——密码、密钥、解密后的恶意代码，在内存里常常是明文躺着的。所以内存取证有时候能拿到磁盘和网络都拿不到的东西。但也要注意它的局限：内存镜像是“某一刻的快照”，攻击者如果已经退出了，快照里就什么都没有了——这就是为什么应急响应里要尽快抓内存，等不得。

一套完整的工作流

把两边合起来，一次网络加内存取证的标准流程是这样的：第一步，先抓内存，再抓磁盘。内存断电就没，磁盘关机还在，所以顺序不能反。第二步，抓包和内存要对上时间。抓包文件和内存镜像都要记清楚是什么时间抓的，时间对不上，两边的证据就没法互相印证——第 13 章讲的时间同步在这里又出现了。第三步，两边各找各的异常，再对表。网络这边列出所有可疑外联的 IP 和域名，内存这边列出所有可疑进程和它们的网络连接，两张表一对，相同的 IP 就是高可信度的证据。第四步，写结论。结论要写成“谁、在什么时候、干了什么、证据是什么”：比如“2026-11-25 02:10，虚拟机上的可疑进程 evil.exe（内存镜像，进程号 1234）向 203.0.113.10 传了 200MB 数据（PCAP，会话 88）”。这样的结论，别人拿着你的证据就能复核。

加密流量时代还能看到什么

现在大部分网络流量都是加密的，TLS 1.3 是当前的主流版本：握手过程本身也是加密的，中间人看不到里面传了什么。这对取证是个坏消息，也是个好消息。坏消息是，抓包再也看不到明文密码和明文文件了；好消息是，加密本身留下了新的“边角料”：DNS 查询的域名、TLS 握手里服务器证书的域名（SNI）、连接的目标 IP 和端口、一次会话传了多少字节、持续了多久。这些边角料合起来，常常足够定位问题。

举个例子：一台办公电脑半夜和一个从没见过的境外 IP 建立了 TLS 1.3 连接，传了 200MB 数据，持续了 40 分钟——你看不到传的是什么，但“半夜、陌生 IP、200MB、40 分钟”这四个事实，已经足够让它成为调查的起点。再结合内存取证：如果同一个时间点，内存里有个可疑进程正在运行，里面还藏着那个 IP 的地址，结论就站住了。取证不是非要看到内容才行，很多时候，看到“谁在跟谁说话、说了多久、说了多少”，就已经够了。

老师经验：我第一次用 Wireshark 打开一个真实的 PCAP，看到几十万个数据包，当场就懵了——不知道从哪看起。后来前辈教我一个顺序，屡试不爽：先看“统计 → 协议分级”，确认流量里都有什么协议；再看“统计 → 会话”，按字节数排序，最大的几个会话先看；最后才打开具体的包看内容。还有一个经验是关于内存的：有一次我们抓内存抓晚了——机器已经被重启过一次，内存里的恶意进程早没了，只剩磁盘上的残留，调查难度直接翻倍。从那以后我们应急响应的检查清单第一条就是“先抓内存，再动别的”。另外提醒一句：Wireshark 抓包时，记得只抓你自己的实验网络。公司网络、公共 Wi-Fi 上的包，里面可能有别人的账号、密码和聊天记录，抓了就是越界。

动手做

1. 只在你自己的虚拟机和实验网络里：用 Wireshark 抓一段你自己的虚拟机访问网站的流量，练习按“统计 → 会话”排序，找出流量最大的那个会话，再打开它看看里面传了什么。
2. 在虚拟机里做一次 DNS 查询（比如 ping 一个你自己的实验域名），在抓包文件里找到这次 DNS 查询的包，抄下查询的域名和返回的 IP。
3. 给你的虚拟机做一个内存快照（虚拟机软件自带的“创建快照”或内存转储功能），用 Volatility 的 pslist 插件列出当时的进程，找一找有没有名字可疑、路径不对的进程。
4. 做一次“对表”练习：把第 1 步里看到的对外连接 IP，和第 3 步里进程的网络连接列出来，看看能不能对上同一个 IP，写一句“互相印证”的结论。

避坑

别在真实网络上抓包：只抓自己的虚拟机和实验网络，别人的流量里可能有账号密码；别先关机再取证：内存断电就没了，先抓内存，再关机、再做磁盘镜像；别一上来就看包内容：先看统计、再看会话、最后看内容，否则会被几十万个包淹没；别只看一边：网络和内存要互相印证，单边的证据容易走偏；别忘了记时间：抓包和内存镜像都要写清时间，时间对不上就没法对表。

上一章第 14 章我们学会了从磁盘里排时间线；这一章我们学会了从网络和内存里找正在发生的痕迹，并且让两边的证据互相印证。下一章第 16 章我们换一个方向：这些调查里用到的威胁情报是从哪来的、又是怎么在不同组织之间交换和共享的——STIX/TAXII 与 MISP。

本课小结
  • 网络取证的原材料是 PCAP，分析顺序是先看统计、再看会话、最后看内容；常找 DNS 异常、异常外联和明文里的秘密。
  • 内存取证的原材料是内存镜像，工具是 Volatility；常找假冒进程、网络连接、注入代码和命令行。
  • 内存是易失的：应急响应里先抓内存，再关机、再做磁盘镜像，顺序不能反。
  • 网络和内存要互相印证：网络说数据去哪了，内存说是谁干的，两边对上同一个 IP 才是高可信度的证据。
  • 加密流量（TLS 1.3 是当前主流）的内容看不到，但 DNS、证书域名这些边角料常常可见；只抓自己的实验流量。
