Linux 管理专项小结：管好一台 Linux 服务器

小结2026-11-25 · Linux 管理专项第 1–6 章

六章讲的其实是一件事：管好一台 Linux 服务器。管好，意思是三个方面都做到位：软件从可信的地方来，人只有必需的权限，门只开必需的口，出事了能翻到记录。这六章就是按这个顺序排的：第 1 章管软件来源，第 2 章管人，第 3 章管服务，第 4 章管远程登录，第 5 章管网络大门，第 6 章管日志。

这六章和 Windows 专项是对应的：Windows 的服务对应 systemd，Windows 的事件日志对应 journald，Windows 的 ACL 对应 Linux 的权限与 sudo。两边对照着学，概念记得更牢——操作系统换了一套，安全思路是同一套：最小权限、默认拒绝、多层防护、出事可查。

这六章是怎么连起来的

先管软件来源。第 1 章讲包管理与软件源：apt 与 dnf、官方源、签名验证、依赖，安全更新要尽快装，升级之前先备份、之后先验证——软件从哪来，决定了软件可不可信。

再管人。第 2 章讲用户、组与 sudo：账号存在 /etc/passwd 和 /etc/shadow 里，sudo 是临时借管理员权限的办法，一人一个账号、服务不用 root 跑、root 不直登，是三条红线；第 3 章讲 systemd 服务深入：PID 1、单元、systemctl、journalctl，服务出问题先看状态、再看日志，改完单元文件先 daemon-reload。

然后给远程登录和网络大门上锁。第 4 章讲 SSH 加固：Ed25519 密钥登录、禁 root、改端口、限来源、Fail2ban 自动封禁，改配置永远留一个会话当救生绳；第 5 章讲防火墙 nftables：表、链、规则三层结构，默认拒绝、按需放行，最小规则集只放行回环、已建立的连接、SSH 和网站端口。

最后是日志。第 6 章讲日志与 journald：文本日志与 journald 互补，journalctl 按服务、按时间、按级别过滤，journald 要开持久化才能长期保存，logrotate 防写满，翻日志先定时间、画时间线——出事了能不能查到，就看这一章的功夫到没到家。

现在你能做什么

  • 给自己的 Linux 虚拟机配好软件源，只从官方源装软件，定期升级安全更新并验证。
  • 一人一个账号配好 sudo 规则，关掉 root 直登，服务用低权限账号跑。
  • 用 systemctl 管理服务，服务起不来时先看状态、再看 journalctl 日志定位原因。
  • 给 SSH 配好 Ed25519 密钥登录，禁掉密码登录和 root 登录，装上 Fail2ban。
  • 用 nftables 配一套默认拒绝、按需放行的防火墙，两边验证该通的通、该堵的堵。
  • 用 journalctl 按时间线还原一次登录失败或服务异常的经过，日志开好持久化。

下一步

下一站是模块三：网络。服务器管好了，接下来要看懂服务器之间是怎么说话的：分层模型、IP、TCP 与 UDP、DNS、HTTP 与 TLS——模块三会把网络从物理层讲到应用层。Linux 专项里用到的很多概念（端口、防火墙、SSH、日志）到了模块三会有更深的解释：端口为什么是那个数字，TLS 1.3 的握手为什么比旧版更快更安全，DNS 是怎么被攻击、又怎么防护的。去 课程目录的模块三看一眼，再往前走。
