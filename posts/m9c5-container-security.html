模块九第 5 章：容器安全

进阶与新趋势2026-11-25 · 模块九

上一章讲的云，落到地上跑的常常是容器。你可能听过 Docker：一句话概括，容器就是“轻量版的虚拟机”——它和虚拟机一样把程序和它的环境打包在一起，但它不像虚拟机那样每台都装一个完整的操作系统， 而是大家共用宿主机的操作系统内核，只隔离各自的文件、进程和网络。这带来了极快的启动速度和极高的密度，也带来了一个关键差别：容器的隔离比虚拟机弱。 虚拟机之间隔着一层完整的系统， 容器之间只隔着内核提供的几道“墙”。

容器安全就围绕三件事：镜像（容器里装了什么）、隔离（容器之间、容器与宿主机之间隔得够不够严）、逃逸（攻击者从容器里跑出来会怎样）。

镜像：容器里的东西可信吗

镜像是容器的“模板”：一个镜像里装着操作系统基础层、运行环境、应用代码和依赖库。镜像是一层一层叠起来的，每一层都可能带进问题：基础镜像里有个旧版本的系统库， 应用层里有个带漏洞的依赖包，某一层里甚至可能被人塞了恶意代码——这就是第 11 章供应链安全在容器世界的样子。

管镜像有四条规矩。第一，只用可信来源的镜像：官方镜像、自己组织内部构建的镜像，绝不随手从公开仓库拉一个没人维护的镜像就上生产。第二，扫描镜像：构建时和运行时都扫， 扫出已知漏洞（对照模块六第 8 章的 CVE 与 CVSS）按严重程度修或升级。第三，镜像要签名、验签：确保你拉到的镜像就是构建时那个，没被人中途掉包。第四，镜像越小越好：只装运行必需的东西， 多余的工具（比如调试器、 编译器）留在镜像里，等于给攻击者留了趁手的工具。

隔离：容器之间的墙有多厚

容器的隔离靠 Linux 内核的两个机制：命名空间（namespace）让每个容器只能看到自己的进程、网络、文件系统；控制组（cgroup）限制每个容器能用多少 CPU 和内存，防止一个容器把整台机器的资源吃光。 但这两道墙都立在“共用同一个内核”这个前提上——内核一旦有漏洞，墙就可能被绕过。

所以容器安全的实操要点是“别自己拆墙”：不要用特权模式（privileged）运行容器——特权容器几乎等于宿主机上的 root；不要把宿主机的敏感目录（如 /、Docker 套接字）挂进容器——挂进去等于把宿主机的钥匙递给容器里的程序；容器里的进程不要用 root 跑，能用普通用户就用普通用户；容器的网络要分段，不同用途的容器不要放在同一个扁平网络里随便互访。 这些都是模块六第 13 章基线与加固思想在容器里的落地。

逃逸：从容器里跑出来意味着什么

容器逃逸是容器安全里最严重的场景：攻击者先攻进一个容器，再利用内核漏洞、配置错误（比如特权模式、危险的挂载）或容器运行时自身的漏洞，拿到宿主机的权限。一旦逃逸成功， 同一台宿主机上的所有容器、宿主机本身都暴露了。 这就是为什么上一节的“别自己拆墙”如此重要——很多逃逸不是什么高深漏洞，而是配置把墙拆了。

防守逃逸要分层：镜像要干净、运行要最小权限、宿主机要及时打补丁（内核补丁尤其重要，因为容器共用内核）、运行时要监控（异常的系统调用、异常的进程行为要告警） 、敏感工作负载可以考虑用更强的隔离（比如每个容器配一个轻量虚拟机， 或用 gVisor 这类沙箱运行时加一层）。记住：容器不是安全边界，真正的安全边界在宿主机和编排层——下一章就讲编排层。

镜像扫描报告怎么读

第一次看到镜像扫描报告，很多人会被几百条漏洞吓住。其实报告要分三层读。第一层看严重程度：先看 CVSS 9 分以上的高危漏洞，再看其他的——数量多不可怕， 可怕的是高危的没人管。

第二层看“能不能被触发”：漏洞藏在哪个组件里、这个组件在容器运行时会不会被调用。一个藏在从没被执行的工具里的漏洞，和一个藏在对外监听服务里的漏洞，优先级完全不同。 好的扫描工具会告诉你漏洞在哪个包、 哪个版本、有没有修复版本。

第三层看“修不修得动”：有些漏洞只要升级基础镜像就没了，有些要等上游发补丁，有些根本没有修复版本——这时就要用别的办法补偿，比如限制容器的网络访问、给容器加沙箱。 读报告的目标不是“清零”，而是“高危的、 可触发的，先清掉”。

老师经验：我检查容器环境，第一眼看的永远是“有没有容器在用 root 跑、 有没有开特权模式”。有一次，一个开发团队为了调试方便， 给生产容器开了特权模式还挂了宿主机的 Docker 套接字——这等于把宿主机的 root 交给了容器里的任何人，攻击者只要攻进这一个容器，整台宿主机就是他的。还有一句： 镜像扫描的报告别只看“高危漏洞有几个”， 要看“这个漏洞在不在会被触发的路径上”——一个藏在从没被调用过的库里的漏洞，和一个藏在对外服务里的漏洞，优先级天差地别。修漏洞也要讲顺序，先修能被外部触发的。

动手做

1. 只在自己的虚拟机或实验环境里做，绝不在真实网站、真实网络、真实云账号上练手——云和容器的实验用本地虚拟机或云厂商的免费实验沙箱，绝不拿生产账号做实验： 在虚拟机里装 Docker，拉一个官方镜像（如 nginx），启动一个容器，用 docker ps 和 docker inspect 看它的配置。
2. 用开源镜像扫描工具（如 Trivy）扫一下这个镜像的漏洞报告，挑一个高危 CVE，查它的 CVSS 评分和影响，再换一个更新的基础镜像重新扫，对比结果。
3. 故意用普通用户（非 root）启动一个容器，再试一次特权模式启动， 对比两者在容器里能做的事有什么不同——亲手验证“特权模式就是拆墙”。
4. 写一份容器运行检查清单：不用 root、不用特权模式、不挂宿主机敏感目录、镜像已扫描、 网络已分段——以后每起一个容器都对着清单过一遍。

避坑

别随手拉公开仓库的陌生镜像：只用官方或内部构建的镜像，并签名验签；别让容器以 root 运行：能用普通用户就用普通用户；别开特权模式：除非你清楚它等于交出宿主机权限； 别把宿主机敏感目录和 Docker 套接字挂进容器；别把容器当虚拟机：容器不是安全边界，隔离弱得多，敏感负载要加更强的隔离；别只扫一次镜像：镜像要构建时扫、运行时定期再扫，新漏洞每天都在出。

这一章把模块二的虚拟化和模块六的基线加固合在了一起： 容器快，但隔离弱，安全要靠镜像干净、运行最小权限、宿主机补丁三层一起守。下一章我们再往上一层——第 6 章： 容器与 Kubernetes 安全，当容器从几个变成几千个，编排层面要防什么。

本课小结
  • 容器与虚拟机的关键差别：容器共用宿主机内核，只靠命名空间和控制组隔离，隔离比虚拟机弱。
  • 镜像安全四条规矩：只用可信来源、构建和运行都扫描漏洞、签名验签、镜像越小越好。
  • 运行时别自己拆墙：不用特权模式、不用 root 跑容器、不挂宿主机敏感目录和 Docker 套接字、容器网络要分段。
  • 容器逃逸是最严重的场景：攻进一个容器再拿到宿主机权限，同机所有容器都暴露；防守要分层。
  • 容器不是安全边界，真正的安全边界在宿主机和编排层。
