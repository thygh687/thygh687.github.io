模块一第 2 章：CPU 是怎么执行指令的

组成原理2026-11-24 · 模块一

CPU 的工作就是一个循环，不停重复四个步骤：取指、译码、执行、写回。你打开的每个程序、点的每次鼠标，最后都是这个循环在干活。这一章要把循环的每一步拆开：每一步是谁在干、数据从哪来、到哪去——因为安全问题几乎全发生在这个循环里：指令从哪来，CPU 就执行什么；谁能改掉下一条指令的地址，谁就能让 CPU 去干别的事。

为什么是“取指—译码—执行—写回”这四步

CPU 自己不知道程序要干什么，它只会一遍遍问同一个问题：“下一条指令是什么？”程序计数器（PC）就是记答案的：它存着下一条指令在内存里的地址。循环的起点永远是 PC——CPU 不认识“程序”，只认识“PC 指着的那条指令”。这个设计有个直接后果：程序就是内存里的一串指令和数据，CPU 分不清哪段是指令、哪段是数据，它只执行 PC 指到的东西。攻击者想干的事，归根结底就是一件事：把 PC 拐到自己准备好的指令上去。

四个步骤

取指：程序计数器记着下一条指令在内存的哪个地址，CPU 按这个地址把指令拿来，放进指令寄存器。注意，取指本身要访问内存——指令存在内存里，不在 CPU 里，所以取指的速度受内存速度拖累，这就是第 3 章缓存存在的理由：常用的指令放在缓存里，取指就不用每次都跑内存。

译码：控制单元看懂这条指令是要干什么。它把指令的操作码（干什么）和操作数（对谁干）拆开，翻译成各个部件的控制信号。译码错了，后面全错——不过正常情况下译码是硬件定的，不会错；真正会“错”的是人：程序员以为自己写的是加法，编译出来的指令却是别的，这类错要到第 4 章汇编才能看出来。

执行：让相应的部件去干活，比如让 ALU 做加法，或者让内存读写数据。执行这一步里，真正干活的是 ALU 和内存，控制单元只负责指挥。数据从哪来？大部分时候从寄存器里来——寄存器就是 CPU 手头的小抽屉，速度最快、容量最小，放正在算的数据。

写回：把结果存回寄存器。然后程序计数器指向下一条，循环继续。多数指令执行完，PC 自动加一，指向下一条；跳转指令例外——它会直接改写 PC，让 CPU 跳到别处去执行。这就是循环和判断在机器层面的真相：没有“循环”这个概念，只有“改 PC”。

关键部件：各管什么

程序计数器（PC）：下一条指令的地址。它是全 CPU 最关键的一个寄存器——改了它，就改了程序接下来要干什么。蓝屏和程序崩溃，很多时候就是 PC 被带到了一个不该去的地址：程序想执行的指令不在那里，或者那里的内容根本不是指令，CPU 一取指就 fault，操作系统只能把程序杀掉。

寄存器：CPU 手头的小抽屉，放正在用的数据，速度最快、容量最小。寄存器和内存的区别要记牢：寄存器在 CPU 里面，数量只有十几个，程序员（和编译器）直接点名用它；内存大得多，但访问要慢上百倍。程序跑得快不快，很大程度上看数据能不能尽量留在寄存器里，少跑内存。

ALU：算术逻辑单元，负责加减乘除和比较。它只会算，不会“决定”——决定是控制单元做的。ALU 的内部是第 6 章的逻辑门拼出来的加法器和比较器。

控制单元：指挥，负责把指令翻译成各个部件的动作信号。可以把它想成乐队的指挥：自己不发声，但每个部件什么时候动、动什么，全听它的。

时钟：卡节奏，每跳一下往前走一步。时钟不是“速度”本身，只是节拍器；一拍里能干多少活，看的是 CPU 的设计。3GHz 的意思是每秒 30 亿拍，至于每拍能完成几条指令，那是流水线和并行设计的事，第 10 章会展开。

指令就是二进制数

一条指令本身也是一串 0 和 1，前几位是操作码（干什么，比如加法），后面是操作数（对谁干，比如哪两个寄存器）。程序就是一长串这样的指令，存在内存里等 CPU 一条一条取。指令的长度、操作码怎么编、操作数怎么找，不同的 CPU 各有一套规矩，这套规矩就叫指令集，第 7 章会讲。先记住结论：程序是数据，指令也是数据，存在同一个内存里——这就是冯·诺依曼结构的核心，也是安全上最要紧的一点：数据和指令没有物理上的墙隔着，只有规则在分着它们。

出错意味着什么：循环断在哪里

取指断了：PC 指到了没有指令的地方（比如野指针、被破坏的返回地址），CPU 取到的不是合法指令，程序崩溃。译码一般不会断，硬件是固定的。执行断了：比如除以零、访问了不该访问的内存地址，CPU 会触发异常，交给操作系统处理——蓝屏和程序闪退，很多就是这么来的。写回断了比较少见，多半是前面的错连锁过来的。排错时先问一句：循环断在哪一步？能定位到步，就离原因近了一半。

主频和多核：快，不只看主频

主频比如 3GHz，就是时钟每秒跳 30 亿下。主频越高一般越快，但不是唯一决定速度的：一次能干多少活、缓存够不够大，同样重要。现在的 CPU 都是多核的，等于好几个 CPU 并排干活，一个核跑一个程序，互不耽误。但多核不是万能药：一个程序如果本身就是一条线往下走的（大部分程序都是），多核帮不上它，只有把它拆成多条线并行跑，才用得上多核。还有超线程：一个物理核模拟成两个逻辑核，两个线程轮流用它的部件，适合“你等我、我等你”的场景，不等于真多了个核。

安全上的注脚：CPU 为了跑得快，会“猜”接下来要执行什么（分支预测、推测执行），猜错了再撤销。问题是，猜的过程中访问过的数据会留在缓存里，撤销也抹不掉——这就是“幽灵”（Spectre）和“熔断”（Meltdown）这类漏洞的原理：攻击者从缓存的蛛丝马迹里，把本不该看到的数据推出来。CPU 快的代价，是它留下了痕迹。第 1 课里提过这两个漏洞，第 8 章讲缓存和局部性时，会把这个道理接上。

老师经验：修电脑和看崩溃现场时，我第一眼就找“程序死在哪一步”。程序闪退、蓝屏，先看错误信息里的地址和寄存器：指令指针（RIP/EIP）指到一个明显不对的地址（比如 0 或者一串 0x41414141），八成是控制流被带偏了——返回地址被覆盖，或者指针本身就是坏的。这时候别急着重装系统，先看转储和事件日志：崩溃时的 PC 值、 fault 的指令、最后一次正常执行的模块，这三样对上号，原因就藏在里面。还有一条：CPU 占用率 100% 不一定是 CPU 慢，经常是某个程序在死循环里一遍遍跑同一个循环——先找到是哪个进程，再看它在等什么。

动手做

1. 打开任务管理器 → 性能 → CPU，看自己的 CPU 型号、主频、核心数和逻辑处理器数；逻辑处理器比核心多，说明开了超线程。
2. 打开一个程序（比如浏览器），看 CPU 占用率的变化；再同时打开几个程序，看占用率怎么分；找一个占用率一直很高的进程，记下它的名字——以后排错先从它查起。

避坑

别只盯着主频买电脑，核心数、缓存、架构同样重要；CPU 占用率高先看是哪个进程在跑，别急着加硬件；取指译码执行这个循环是全书最重要的概念之一，一定要真懂；别把“程序”和“指令”当成两样东西——程序就是一串等着被取指的指令，PC 指到哪，CPU 就执行哪。

下一章看循环里最费时间的一步——取指要去的内存，到底是怎么分层的：第 3 章：存储器。回头看第 1 章的补码，到了第 4 章，你能亲手在汇编里算出溢出长什么样。而这四个步骤在硬件里到底是怎么连成一条数据通路的、控制信号又是怎么一路发下去的，是第 19 章：CPU 数据通路和第 20 章：控制器设计的事。

本课小结
  • CPU 的工作是一个循环：取指、译码、执行、写回，起点永远是程序计数器 PC。
  • 指令本身也是二进制数，存在内存里；CPU 分不清指令和数据，只执行 PC 指到的东西。
  • 程序崩溃常常是 PC 被带到了不该去的地址；定位到循环断在哪一步，就离原因近了一半。
  • 主频只是节拍，速度还看每拍干多少活、缓存够不够大；多核只帮得上能并行的程序。
  • CPU 为求快会推测执行，猜过的痕迹留在缓存里——这是“幽灵”和“熔断”漏洞的原理。
