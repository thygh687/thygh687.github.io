模块四第 10 章：Shell 脚本：Bash 与 PowerShell

编程基础2026-11-25 · 模块四

安全工程师每天要做很多重复的活：查一百台机器的补丁、每天看一遍日志、每台新机器装同一套工具、定期备份配置文件。一条一条敲命令能做，但第二天还要再来一遍——人总会敲错、敲漏。Shell 脚本就是把“一串命令”写进一个文件，让电脑自己按顺序跑完：你写一次，它每天替你跑。这章讲两个 Shell：Linux 上的 Bash 和 Windows 上的 PowerShell。你用 Windows 电脑学习，PowerShell 是主场；但安全圈里大量工具和服务器都在 Linux 上，Bash 也必须会读会写。

先分清三个词：Shell 是“命令解释器”，就是你敲命令的那个黑窗口背后的程序；终端是那个黑窗口本身；脚本是写好的一串命令，存在文件里，交给 Shell 一次执行。Bash 是 Linux 最常见的 Shell，PowerShell 是 Windows 自带的 Shell。它们语法不一样，但思路一模一样：变量存东西、判断做选择、循环做重复、管道把命令串起来。

Bash 基础：变量、判断、循环

Bash 脚本的第一行通常是 #!/bin/bash，意思是“用 Bash 来跑我”。变量赋值很简单：name="yufei"——注意等号两边不能有空格，有空格 Bash 会以为你在运行一个叫 name 的命令。取值时在前面加 $：echo "你好，$name"。

判断用 if：

if [ -f /etc/passwd ]; then
  echo "文件存在"
else
  echo "文件不存在"
fi

[ -f ... ] 是在问“这是个文件吗”，-d 问“这是个目录吗”，-z "$var" 问“这个变量是空的吗”。循环用 for：

for ip in 192.168.1.1 192.168.1.2 192.168.1.3; do
  ping -c 1 "$ip"
done

这三行等于把 ping 连敲三遍，换了三个地址。循环加判断，就是脚本的骨架：对一堆东西逐个检查，符合条件的记下来，不符合的跳过——后面第 16 章的日志分析工具，思路就是这个骨架。

PowerShell 基础：cmdlet、管道、对象

PowerShell 的命令叫 cmdlet（读作“command-let”），格式永远是“动词-名词”，比如 Get-Process（取进程）、Stop-Service（停服务）、Get-ChildItem（列文件）。动词只有批准过的一小套：Get、Set、New、Remove、Start、Stop、Test……名词就是你要操作的东西。这种命名法的好处是：没见过的命令，猜也能猜出个大概。

PowerShell 和 Bash 最大的不同是管道里传的是对象，不是纯文本。Bash 的管道传的是一行行文字，下一个命令得自己用 grep、awk 再从文字里抠信息；PowerShell 的管道传的是带属性的对象，可以直接按属性筛选：

Get-Process | Where-Object { $_.CPU -gt 100 } | Sort-Object CPU -Descending

意思是：取出所有进程，只留 CPU 用量大于 100 的，按 CPU 从大到小排好。不用再写正则去抠数字，对象自带字段。安全排错时这招很好用：找“哪个进程占 CPU 最多”“哪个服务没在跑”“最近一小时改过的文件”，都是一行命令的事。

PowerShell 里变量以 $ 开头：$name = "yufei"；判断是 if ($x -gt 10) { ... }，比较符号是英文单词：-eq 等于、-gt 大于、-lt 小于、-ne 不等于。循环是 foreach ($ip in $ips) { Test-Connection $ip }。语法和 Bash 不一样，但“变量—判断—循环”这三件套一个不少。

写一个“每天巡检”的脚本：思路

把“每天巡检”拆成四步，每步一个小命令，脚本就是把它们排好队：

1. 看系统还活着吗：查磁盘还剩多少（Linux df -h，PowerShell Get-PSDrive）、内存用了多少、CPU 忙不忙。
2. 看有没有陌生人：列出当前登录的用户、最近登录失败的记录、正在监听的端口（ss -tlnp 或 Get-NetTCPConnection -State Listen）。
3. 看有没有新变化：关键目录里最近 24 小时改过的文件、新增的开机自启项。
4. 出报告：把结果写进一个带日期的文件，比如 巡检-2026-11-25.txt，异常的标出来。

写脚本的顺序应该是：先在命令行里一条一条试，试通了再粘进脚本；脚本里每一步都加一句 echo 或 Write-Host，说明“现在做到哪一步了”；最后加一个判断：磁盘剩余小于 10% 就多写一行“警告：磁盘快满了”。脚本的价值不在“写得多花哨”，而在“每天跑出来的结果一模一样，不会因为人困了就漏查一项”。

老师经验：我见过最惨的一次事故，不是因为没人巡检，而是巡检脚本里有一行 rm -rf $BACKUP_DIR/*，而那天 $BACKUP_DIR 变量因为前面一行报错没赋值成功——空变量一展开，删的就是根目录下的东西。从那以后我给自己立了三条铁规矩：删东西的命令，变量必须先判空，空了就立刻退出；任何破坏性操作先在测试机上跑，跑三遍没问题再上真机器；脚本开头加 set -e（Bash）或严格的错误处理，让第一步出错就停下来，而不是带着错误继续往下跑。自动化是把双刃剑：它把你的正确放大一百倍，也把你的错误放大一百倍。

动手做

1. 在虚拟机（Linux）里写一个 check.sh：打印今天的日期、磁盘剩余空间、内存使用情况，再加一个判断——磁盘剩余小于 20% 就输出“警告”。给它执行权限（chmod +x check.sh）再运行。
2. 在 Windows 的 PowerShell 里写一个 check.ps1：列出 CPU 占用前 5 的进程，再列出所有处于监听状态的 TCP 端口，只显示本地端口和状态两列。
3. 把第 1 步的脚本改成循环版：对 127.0.0.1 和虚拟机自己的 IP 各 ping 一次，把“通 / 不通”的结果写进一个带日期的日志文件。
4. 故意制造一个小错误：在 Bash 脚本里引用一个不存在的变量，看脚本是继续往下跑还是停下来；再在脚本开头加上 set -e 和 set -u（未定义变量就报错退出），对比两次运行的区别——体会“出错就停”为什么是安全脚本的第一要求。

避坑

别在真机器、真服务器上第一次跑新脚本：先在虚拟机里跑，跑通了再说；别在脚本里写明文密码：密码要另外保管，脚本里只读配置或让使用者现输；Bash 里等号两边别加空格，a = 1 和 a=1 是两回事；PowerShell 里从网上抄来的脚本别直接运行：先读一遍，弄清每一行在干什么，特别是带 Invoke-Expression、DownloadString、-EncodedCommand 的；删文件、改配置、停服务这类破坏性命令，进脚本之前先想好“变量为空时会发生什么”。

脚本写熟了，真正的编程语言就不远了：第 11 章先补编程要用的数学，再回头看第 13 章的 C 语言会轻松很多。回头看第 8 课的 Linux 命令——这一章的 Bash 脚本，用的就是那一课的命令，只是把它们排成了队。

本课小结
  • Shell 是命令解释器，脚本是写进文件的一串命令：写一次，每天替你跑，结果每次都一样。
  • Bash 里变量赋值等号两边不能有空格，取值加 $；判断用 if [ ... ]，循环用 for ... do ... done。
  • PowerShell 的命令叫 cmdlet，格式永远是“动词-名词”；管道里传的是带属性的对象，可直接按属性筛选。
  • 每天巡检的思路是四步：系统状态、陌生登录与监听端口、新变化、出带日期的报告，异常要标出来。
  • 安全写脚本三条铁规矩：先在虚拟机里跑通、删改类操作先判空、出错就停（set -e / set -u），绝不在脚本里写明文密码。
