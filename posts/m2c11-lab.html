模块二第 11 章：动手：进程、线程与系统调用

操作系统2026-11-24 · 模块二

这一章是模块二的综合动手：把前面学过的进程、线程、系统调用，用系统自带的工具亲眼看一遍。看完这一章，你对操作系统的理解就从“知道”变成“见过”了。

先建基线：正常进程长什么样

认异常之前，先把正常记在心里。看一个进程，养成查五样的习惯：

  • 父进程是谁：每个进程都有父亲。正常的 svchost.exe，父亲是 services.exe；正常的浏览器渲染进程，父亲是浏览器主进程。父亲对不上（比如一个文档阅读器生出了命令行），就要警觉。
  • 路径对不对：系统进程住在系统目录里，比如 C:\Windows\System32。同样叫 svchost.exe，住在 C:\Users\你的名字\下面，就是假的。
  • 以谁的身份跑：系统服务多以 SYSTEM 或 NETWORK SERVICE 跑，普通程序以你的账户跑。一个记事本突然以 SYSTEM 身份跑，事情就不对了。
  • 什么时候启动的：半夜三点启动的陌生进程，比白天启动的值得怀疑；开机就自启的，要看它是不是你装过的软件。
  • 有没有签名：正规厂商的程序带数字签名，右键属性能看到。没签名的系统级程序，先打个问号。

这五样对上号，不代表一定安全——恶意软件也会伪装路径和名字——但五样里有一两样对不上，调查就有了起点。安全分析的第一步永远是建立基线：先知道正常是什么样，异常才显眼。

Windows 上看进程和线程

任务管理器 → 详细信息：看进程的 PID、状态、用户名、CPU 和内存占用。右键列标题 → 选择列，勾上“线程”，看每个进程有多少线程。资源监视器（任务管理器 → 性能 → 打开资源监视器）能看到进程和它的子进程、打开的文件、网络连接。Process Explorer（微软官方的免费工具）能看得更细，包括进程的父子关系和加载的模块。

Linux 上看进程和线程

ps aux：看所有进程。 ps -eLf：看进程和它的线程。 top：实时看 CPU 和内存占用，按 P 按 CPU 排序，按 M 按内存排序。 pstree：用树形图看进程的父子关系，一眼就能看出谁是谁生的。

/proc：Linux 把进程变成文件

Linux 有个巧办法：每个进程在 /proc 下面都有一个以 PID 命名的目录，里面全是“文件”——cmdline 是启动命令行，exe 是程序本体所在的路径，status 是状态，fd 是它打开的文件。ps、top 这些工具，其实就是在读 /proc 再排版给你看。明白这一点，排错就多了一个直接的办法：进程看着可疑，直接 cat /proc/PID/cmdline、ls -l /proc/PID/exe，看它到底是谁、从哪启动的。这也是第 9 章“一切皆文件”思想最实在的一次落地：连进程都能当文件来读。

跟踪系统调用

在虚拟机的 Linux 里，用 strace 跟踪一个命令：strace cat /etc/hostname，看它打开了哪些文件、调了哪些系统调用。再试试 strace -e trace=network ping -c 1 example.org，只看网络相关的调用。Windows 上对应的工具是 Process Monitor，能看到进程的每一次文件、注册表和网络操作。

输出太多看不过来的时候，先加过滤再看。strace -f 会跟进子进程（不加它，fork 出来的子进程就跟丢了——第 2 章讲过进程是怎么生出子进程的）；-e trace=openat,read 只看文件操作；-e trace=network 只看网络；-c 只给汇总，不刷屏。Process Monitor 也一样：先设过滤器（只看某个进程、只看某种操作），再点开始，不然一秒几千条，眼睛先投降。跟踪的思路和第 10 章讲的一样：程序想干什么，最后都落在系统调用上；只不过这里不是听概念，是亲眼看。

老师经验：先学会看正常进程长什么样，才能认出异常的。正常的 svchost.exe 有十几个，父进程是 services.exe；正常的 chrome.exe 会开很多个，每个标签页一个。把这些正常样子记在心里，以后看到一个名字正常、但父进程不对、路径不对、启动时间是半夜的进程，马上就能警觉。安全分析的第一步永远是建立基线：先知道正常是什么样。

动手做

1. 在 Windows 上打开任务管理器，把“线程”列加出来，找出线程数最多的三个进程，记下来。
2. 在虚拟机的 Linux 里输入 pstree -p | head -20，找到 PID 为 1 的进程（init/systemd），它是所有进程的祖先。
3. 用 strace ls 跟踪一次 ls，数一数它调了多少次 openat。

避坑

工具只看不改，别随手结束不认识的进程，结束错了系统会出问题；strace 和 Process Monitor 输出很多，先加过滤条件再看；这份“正常进程长什么样”的印象要留着，后面安全运营模块会反复用到。

本课小结
  • 先建基线再认异常：看一个进程，查父进程、路径、运行身份、启动时间、有没有签名，五样对不上就值得查。
  • Linux 的进程就是 /proc 下的文件：cmdline、exe、status、fd 直接读，比工具转述的更可靠。
  • strace 跟踪系统调用，先加过滤再看：-f 跟子进程，-e 只看某一类调用，-c 只看汇总；Process Monitor 也一样。
  • 这份“正常长什么样”的印象要留着，后面安全运营模块会反复用到；下一章对比 Windows 和 Linux 内核有什么不一样。
