模块一第 7 章：指令系统与寻址方式

组成原理2026-11-24 · 模块一

CPU 能听懂的所有指令，合起来叫指令系统，也叫指令集架构（ISA）。它是硬件和软件之间的一份约定：软件按这份约定写指令，硬件按这份约定执行。你的电脑和手机用的指令集不一样，这就是为什么电脑上的程序不能直接拿到手机上跑——不是文件格式不对，是 CPU 根本听不懂对方的指令。

为什么先学指令集

学安全的人迟早要和指令集打交道：木马、病毒最终都是一串按某种指令集写成的机器码；逆向分析就是把机器码翻译回人能读懂的指令；写漏洞利用代码（shellcode）时，每一条指令都得按目标电脑的指令集来写。认不出指令集，就像拿到一份看不懂文字的情报——连从哪下手都不知道。

一条指令长什么样

一条指令由操作码和操作数两部分组成。操作码说“干什么”，比如加法；操作数说“对谁干”，比如哪两个寄存器。按操作数的个数，指令分成几类：零地址指令没有操作数，比如停机；一地址指令有一个操作数，比如取反；二地址指令有两个，比如加法；有些指令集还有三地址指令，一条指令能同时写“把 A 和 B 相加，结果放进 C”。

指令的长度也不一定都一样。有的指令集是定长的，每条指令都是 4 个字节，取指简单、流水线好排，但简单的指令也要占满 4 个字节，浪费空间；有的指令集是变长的，简单的指令 1 个字节，复杂的指令十几个字节，省空间，但 CPU 取指时得先判断这条指令有多长，硬件更复杂。x86 就是变长的，这个特点后面讲安全时会再回来——它意味着从错误的字节开始解码，会得到一串完全不同的指令，攻击者正是利用这一点在程序里“找”出可用的指令片段。

寻址方式：数据在哪

操作数可以来自不同的地方，这就叫寻址方式。立即数寻址：数据直接写在指令里，比如 MOV AX, 5，5 就是立即数——最快，但只能放小数字，放不下一个内存地址。寄存器寻址：数据在寄存器里，比如 MOV AX, BX——也很快，但寄存器就那么几个，装不下大东西。直接寻址：指令里给的是内存地址，比如 MOV AX, [1000]，意思是把内存 1000 号位置的数据拿来——能访问整个内存，但指令本身要带上完整地址，比较长。

还有两种更灵活的方式。寄存器间接寻址：地址本身存在寄存器里，CPU 要先读寄存器，再按里面的地址去内存取数据，比如 MOV AX, [BX]——同一个指令，BX 里换个地址就能访问不同的内存位置，循环遍历数组全靠它。变址寻址：地址等于一个固定值加一个寄存器的值，比如访问数组里第 i 个元素，地址就是“数组开头 + i × 每个元素占的字节数”——不用为每个元素写一条指令，一条指令走完整个数组。相对寻址：地址是“当前指令的位置 + 一个偏移量”，跳转指令常用它，程序搬到内存别处也能正常跑。

为什么要有这么多种？因为每种都是取舍：立即数和寄存器最快但装的东西有限，直接寻址最直白但指令长，间接和变址灵活但要多算一步。指令集的设计，就是在速度、指令长度和灵活性之间找平衡。读汇编时认出寻址方式，就等于知道这条指令的数据到底从哪来——这是读懂程序行为的第一步。

x86 和 ARM

现在主流的指令集有两个：x86 和 ARM。x86 是复杂指令集（CISC），指令多、单条指令能干的事多，你的 Windows 电脑基本都是 x86。ARM 是精简指令集（RISC），指令少而简单、功耗低，手机、平板基本都是 ARM。苹果的电脑现在也用 ARM 了。两者互不兼容，所以程序要针对不同的指令集分别编译。

这两派当初走的是不同的路。CISC 诞生的时候内存很贵，所以希望一条指令干尽可能多的事、程序尽可能短；RISC 出现的时候发现，简单规整的指令更容易做流水线（第 10 章会讲），编译器也能把复杂操作拆成简单指令，反而更快。但今天的界限已经模糊了：x86 内部会把复杂指令拆成简单的微操作再执行，ARM 也加了不少复杂指令。名字还是 CISC 和 RISC，内核早就互相取经了。

还有一个细节叫大小端：一个多字节的数存在内存里，是先存高位字节还是先存低位字节。x86 和主流 ARM 都用小端（先存低位字节），所以你平时感觉不到它的存在。但一旦去读内存转储、分析网络数据包，就会撞上它——同样四个字节，按大端和小端读出来是两个完全不同的数。搞混大小端，是新手分析内存数据时最常见的低级错误。

和安全有什么关系

关系比想象中大。第一，shellcode 是按指令集写的：一段针对 x86-64 的攻击代码拿到 ARM 手机上就是一堆乱码，什么都干不了；反过来也一样。所以判断一个样本是针对什么平台的，第一步就是认指令集。第二，变长指令集会“长”出攻击面：x86 指令长度不固定，从中间某个字节开始解码会得到一串本来不存在的指令，攻击者就用这些“藏”在正常代码里的指令片段拼出攻击链，这就是 ROP（返回导向编程）的原理之一。第三，权限指令只有操作系统能用：关中断、改页表这类特权指令，普通程序执行会直接报错，CPU 靠指令集里的特权级把用户和系统隔开——模块二第 1 章会讲操作系统怎么用这道墙。

老师经验：拿到一个可疑样本，第一件事不是急着跑它，而是先认架构：看可执行文件头里的机器类型——x86-64 和 ARM64 的样本要分开处理，拿错架构的 shellcode 在目标机器上只会直接崩溃，什么都不会发生。平时多留心自己电脑的架构（任务管理器 → 性能 → CPU 就能看到），以后看到“这个程序只支持 x86”之类的提示，就知道它在说什么了。

动手做

1. 对照着写三条指令，说出每条的操作码和操作数分别是什么：MOV AX, 5、ADD AX, BX、MOV AX, [1000]。
2. 说出上面三条分别用了哪种寻址方式。
3. 在任务管理器 → 性能 → CPU，看自己的电脑是 x86 还是 ARM。
4. 在虚拟机里的 Linux 终端跑 file /bin/ls，看输出里的 x86-64 字样——连系统自带的命令，也是按某种指令集编译出来的。

避坑

指令集不用背指令表；知道 x86 和 ARM 的区别、寻址方式有几种就够了；“程序要在不同平台重新编译”这个结论要记住，后面学软件分发还会遇到。还有两个常见误区：一是以为“指令越复杂 CPU 越强”，其实指令集的强弱要看编译器和流水线配不配合；二是读汇编时把 [BX] 当成 BX 本身——方括号的意思是“按里面的地址去内存取”，少了这一步，整条指令的意思就全错了。

本课小结
  • 指令集是硬件和软件的约定：软件按它写指令，硬件按它执行；不同指令集的程序互不兼容，要重新编译。
  • 一条指令 = 操作码（干什么）+ 操作数（对谁干）；x86 是变长指令，从错的字节解码会得到不同的指令。
  • 寻址方式回答“数据从哪来”：立即数在指令里，寄存器在 CPU 里，直接给内存地址，间接和变址先算地址再去内存拿。
  • x86 是 CISC、ARM 是 RISC，但今天的界限已经模糊；大小端决定了多字节数据在内存里的存放顺序，读内存转储时别搞混。
  • 安全上：shellcode 是按指令集写的，认架构是分析样本的第一步；变长指令藏着 ROP 的指令片段。
