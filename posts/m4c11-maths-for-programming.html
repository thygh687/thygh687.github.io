模块四第 11 章：编程需要的数学：离散数学与概率入门

编程基础2026-11-25 · 模块四

一听到“数学”，很多人第一反应是：我数学不好，是不是学不了安全？先把心放下来：安全要用的数学不是高考压轴题那一路，而是一小套“能数得清、能算得准”的工具——逻辑、集合、模运算、概率。密码学靠它们算，防火墙规则靠它们想，入侵检测靠它们判断“这件事正不正常”。这一章只讲入门：每个概念配一个安全里的真例子，讲到“够用、能动手”就停。更深的数学在模块五的密码学和数学基础专项里接着讲。

逻辑：与、或、非与真值表

逻辑是计算机的母语。模块一第 6 章讲过逻辑门：与（AND）是“两个都真才真”，或（OR）是“有一个真就真”，非（NOT）是“真变假、假变真”。编程里的 if 条件，用的就是同一套东西。比如防火墙规则“放行条件是：来自内网 AND 端口是 443”，意思是两个条件必须同时成立，缺一个就拦下。

真值表是把所有可能列出来的表，是检查逻辑有没有想漏的利器。以“与”为例：

A      B      A AND B     A OR B
假     假       假          假
假     真       假          真
真     假       假          真
真     真       真          真

安全里的经典例子是访问控制：一个文件能不能被打开，条件常常是“你是文件主人 OR 你是管理员 AND 文件没有被锁定”——这句话里 AND 和 OR 的优先级不同，意思天差地别。写代码、写规则之前，先把条件画成真值表，把“真真、真假、假真、假假”四种情况都走一遍，漏掉的那一种往往就是攻击者钻的空子。历史上不少权限绕过漏洞，根子上就是程序员把“或”写成了“与”，或者反过来。

集合：属于、不属于、交集与并集

集合就是“一堆东西放在一起”。“所有管理员账号”是一个集合，“所有被封禁的 IP”是一个集合，“所有已知的恶意域名”也是一个集合。集合的基本操作只有几个：属于（∈）、不属于、交集（两个集合共有的部分）、并集（合起来）、差集（在一个里但不在另一个里）。

安全工作里集合无处不在：黑名单就是一个集合——“请求里的 IP 属于黑名单吗？属于就拦”；白名单反过来——“不在白名单里的，一律不放行”。防火墙规则经常要算交集：规则 A 允许的地址和规则 B 允许的地址，交集才是真正能通过的。把“允许谁、拒绝谁”想成集合的加减法，规则写错的概率会小很多。写代码时也一样：Python 的 set、查一个元素在不在集合里、两个集合求交集，都是现成的操作，第 16 章统计高频 IP 时就会用到。

模运算入门：时钟上的算术

模运算（mod）就是“除完取余数”。12 小时制的时钟就是最好的例子：现在 10 点，再过 5 小时是几点？15 点，但钟面上只有 12 个数字，所以是 3 点——也就是 (10 + 5) mod 12 = 3。写成一般形式：a mod n 就是 a 除以 n 的余数，结果永远在 0 到 n-1 之间。

模运算在安全里是主角。第一，密码学：RSA、Diffie-Hellman 密钥交换这些算法，全是建立在模运算上的大数游戏——第 14 课讲过加密的思想，模块五会讲它的数学。第二，哈希：把任意长的数据映射成固定长度的指纹，常常要对一个大数取模，把结果收进固定范围。第三，日常小事：判断一个数是奇数还是偶数，就是看它 mod 2 是 1 还是 0；轮询、取余分桶、循环移位，背后也都是模运算。

模运算有一条很实用的性质：(a + b) mod n = ((a mod n) + (b mod n)) mod n。意思是：大数先取余再加，结果和加完再取余一样。这条性质让计算机可以对天文数字先“缩小”再算——密码学里动不动就是几百位的数，没有这条性质，根本算不动。

概率入门：随机、期望与生日悖论

概率是“事情发生的可能性有多大”。安全几乎全是概率问题：一个密码被猜中的概率有多大？一个随机数够不够随机？一次检测漏掉攻击的概率有多大？先抓三个基本概念。第一，随机：每次结果不可预测，但长期看有规律——抛硬币每次正反难料，抛一万次，正面大约占一半。第二，期望：平均下来会发生多少次——一个漏洞被利用的概率是千分之一，一万台机器里，期望就有十台中招。第三，独立事件的概率相乘：猜对一位数字的概率是 1/10，连猜对 4 位就是 (1/10)⁴ = 1/10000。

最反直觉的是生日悖论：一个屋里只要 23 个人，就有超过一半的概率至少有两个人同一天生日。直觉会说“一年 365 天，23 个人怎么可能撞上”，但算的是“任意两个人撞上”，23 个人能组成 253 对，每对都有 1/365 的撞车机会，机会一多，撞上就成了大概率事件。安全里这就是哈希碰撞的数学根子：一个 64 位的哈希值看起来有天文数字种可能，但按生日悖论的算法，只要收集大约 2³²（四十多亿）个不同的输入，撞出两个相同哈希的概率就过半了——所以哈希输出太短是不安全的，现代标准都要求足够长的输出。密码猜测也一样：攻击者不是在猜“你的密码是什么”，而是在算“试多少次能撞上”，密码长度每加一位，攻击者的工作量就翻几十倍——第 15 章的密码强度检查器，背后的道理就是这个。

老师经验：我刚入行时，有一次给客户解释“为什么 8 位纯数字密码不行”，客户不服：一个 8 位密码有一亿种可能，怎么可能被猜到？我在白板上算给他看：一亿次尝试，现代显卡一秒能试几十亿次，8 位纯数字密码撑不过一秒。他当场改了策略。后来我学乖了：跟人讲安全，永远先算一笔数——概率乘以攻击者的速度，就是真实的风险。还有一次排查误报：入侵检测每天报几百条，真正有问题的一条都没有。问题出在基数上：正常流量是几百万条，哪怕误报率只有 0.1%，一天也有几千条。概率这东西，不算不知道，一算全明白。记住：安全决策不是凭感觉，是凭算出来的数。

动手做

1. 在虚拟机里用 Python 写一个真值表生成器：输入两个布尔值，输出 AND、OR、NOT、XOR（异或：不同才真）的结果；再写一个条件“用户是管理员 OR （是文件主人 AND 文件未锁定）”，把四种组合都跑一遍，看结果和你想的是不是一样。
2. 用 Python 的 set 做一次黑名单检查：造一个含 10 个 IP 的黑名单集合，再造 20 条访问记录，统计有多少条命中的是黑名单；再算一下黑名单和“今天登录失败过的 IP”这两个集合的交集。
3. 写三行代码验证模运算：算 (10 + 5) % 12、算 2**10 % 7，再验证 (a + b) % n 和 ((a % n) + (b % n)) % n 是不是相等。
4. 模拟生日悖论：用 Python 随机生成 23 个 1 到 365 的数，重复一万次，统计有多少次出现了重复——看结果是不是接近 50%。再把人数改成 30、40、50，看概率怎么变。

避坑

别被“数学不好”吓住：这一章的四个工具够你用到模块五，缺了再补，别一上来就啃数论教材；别把 AND 和 OR 写反：权限判断里写反一个词，就是一个漏洞，写完先画真值表验一遍；别以为“可能性很多就等于安全”：生日悖论说明，撞上的概率比直觉大得多，哈希和密码的长度要按算出来的数定，不能凭感觉；别用可预测的数当随机数：时间戳、进程号这类“看起来随机”的东西，攻击者也能猜到，真正的随机要用系统提供的随机源。

数学补到这里，编程的路就通了：第 12 章讲怎么写出靠谱的程序，再到第 13 章的 C 语言指针。模块五讲密码学时会把模运算展开成完整的数学工具箱，数学基础专项则会把逻辑、集合、概率一个一个讲深——这一章是地图，不是终点。

本课小结
  • 逻辑是计算机的母语：AND、OR、NOT 决定条件成不成立，写权限规则前先画真值表，把四种组合走一遍。
  • 集合是安全的基本单位：黑名单、白名单、允许的地址，都是集合；“在不在集合里”就是最常见的检查。
  • 模运算是时钟上的算术：a mod n 是 a 除以 n 的余数，密码学和哈希都建立在它上面，大数先取余再算结果不变。
  • 概率决定真实风险：随机、期望、独立事件概率相乘；生日悖论说明 23 个人里就有一半概率撞生日，哈希太短就不安全。
  • 密码每长一位，攻击者的工作量就翻几十倍——长度的价值是算出来的，不是感觉出来的。
