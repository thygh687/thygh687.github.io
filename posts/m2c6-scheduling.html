模块二第 6 章：调度：CPU 时间怎么分

操作系统2026-11-24 · 模块二

CPU 只有一个（每个核一个），进程却有几十上百个，谁先跑、跑多久，都是调度器说了算。调度做得好不好，直接决定电脑用起来卡不卡。第 2 章讲过，所谓“同时运行”其实是轮流跑——这一章就是来讲这个“轮流”是怎么轮的、轮错了会怎么样。

为什么需要调度

先想清楚调度器要同时满足的三件事，互相之间还是矛盾的：快——你点一下鼠标，界面要马上响应，不能等上几秒；公平——几十个进程都要有份，不能一个独占、别的饿死；效率——CPU 别闲着，也别把时间都花在切换上。这三件事很难同时做到最好，调度算法就是在三者之间找平衡：偏向响应速度，就得多切换；偏向效率，就得少切换、让每个进程一次跑久一点。没有一种算法在所有场景下都是最好的，Linux 和 Windows 才会在时间片轮转的基础上再加优先级、多级队列这些细化手段。

几种调度方法

先来先服务：排队，谁先来谁先跑，简单但后来的短任务会被前面的长任务堵住。短作业优先：先跑预计用时短的，平均等待时间最短，但要预先知道用时，实际很难。时间片轮转：每个进程轮流跑一小段时间（时间片，一般几毫秒到几十毫秒），时间到了就换下一个，大家都有份，这是现在最常用的做法。多级反馈队列：把时间片轮转再细化一层，短任务优先跑，长任务慢慢降级，是 Linux 和 Windows 实际在用的思路。

每种方法的毛病，就是它要解决的问题的反面。先来先服务最公平，但一个长任务排在前面，后面一堆短任务全得等着——就像超市里前面的人推了一车东西，后面只买一瓶水的人也得等半天。短作业优先反过来：平均等待最短，但长任务可能永远排不上——一直有短任务插队，长任务就饿死了。时间片轮转解决了“大家都有份”，但时间片大小是个 trade-off：太短，切换开销吃掉大部分 CPU 时间；太长，等于退回先来先服务，交互程序会发卡。

多级反馈队列是怎么把这些毛病都补上的？它不只用一个队列，而是好几层：新来的进程先放在最上层（时间片短、优先级高），跑不完就降一层，时间片变长、优先级变低。短任务在上层几下就跑完了，不用等；长任务慢慢往下沉，虽然优先级低了，但每次能跑的时间更长，切换次数反而少了；再加上“等了太久就升回来”的规则（防饿死），长任务也不会永远等不到 CPU。Windows 用的就是多级反馈队列类的调度器；Linux 的 CFS 走的是另一条公平调度的路子，但思路相近——分层、动态调优先级、防饿死。名字不用背，记住“分层 + 降级 + 防饿死”这三个动作就行。

优先级和上下文切换

不是所有进程都平等：系统进程和前台程序的优先级更高。优先级可以动态调整，比如一直等不到 CPU 的进程会慢慢升优先级，防止饿死。每次换进程跑，操作系统要保存旧进程的现场、恢复新进程的现场，这叫上下文切换，是有代价的。切换太频繁，CPU 的时间都花在切换上，真正干活的时间反而少了。

优先级出错意味着什么？两种情况都要认得：一种是优先级反转——高优先级进程在等一个低优先级进程手里的锁，低优先级进程又迟迟抢不到 CPU 来放锁，高优先级进程就被一个低优先级进程卡住了；另一种是饿死——低优先级进程一直有更高优先级的插队，永远轮不到。操作系统防饿死的做法是“老化”：等得越久，优先级慢慢往上提，总有一天能轮上。

上下文切换的代价到底花在哪？保存寄存器、换内存映射（第 7 章虚拟内存会讲每个进程有自己的内存映射）、缓存失效——CPU 缓存里还留着上一个进程的数据，换了进程，这些缓存大多作废，得重新从内存里读。所以线程数太多不只是“排队久”，还会让 CPU 不停地切换、缓存不停地失效——第 3 章说的“线程不是越多越好”，根子就在这里。

调度与安全

调度器要保证公平：一个进程不能独占 CPU，否则别的进程都得等着。恶意程序最喜欢干的就是占着 CPU 不放，或者不停地创建新进程，把调度器拖垮——这就是拒绝服务（DoS）的一种形式。

再往深想一层：调度器是资源的守门人，攻击者抢的就是它守的东西。挖矿木马死死占满 CPU，正常程序分不到时间，电脑就卡到没法用；不停创建新进程的恶意程序（fork 炸弹），把进程表和调度队列塞满，新进程建不出来，系统就动不了了。防御的思路也在这里：限制单个用户、单个进程能占的 CPU 和能建的进程数（Linux 的 cgroup 和 ulimit 就是干这个的），让一个坏进程抢不走所有的资源。看电脑健不健康，先看 CPU 占用率最高的进程是谁，再看它是什么时候启动的、藏在哪个路径下——老师经验里那三样检查，放在这里一样管用。

老师经验：挖矿木马最明显的特征就是 CPU 占用率长期居高不下。正常程序的占用率是起起伏伏的，挖矿是死死占满一个核甚至所有核。排查的时候，我先看占用率最高的进程，再看它的启动时间和路径——半夜启动、藏在临时目录、名字模仿系统进程，基本就是它了。DoS 攻击同理，本质上都是抢资源，调度器就是战场。

动手做

1. 打开任务管理器 → 详细信息，右键一个进程 → 设置优先级，看系统允许的优先级有几档（别真的改，看看就行）。
2. 同时打开浏览器、音乐、聊天软件，观察 CPU 占用率的变化，体会“轮流跑”。
3. 在虚拟机的 Linux 里输入 top，按 P 按 CPU 排序，看谁在占 CPU。

避坑

时间片轮转和多级反馈队列是重点，其他方法知道名字和思路就行；上下文切换有代价，线程数不是越多越好；别随便改进程优先级，改错了会让系统卡住。

本课小结
  • 调度器要在快、公平、效率三件事之间找平衡：没有一种算法在所有场景下都是最好的。
  • 时间片轮转是现在最常用的做法：每人轮流跑几毫秒到几十毫秒；时间片太短切换开销大，太长会让别的进程等太久。
  • 多级反馈队列是实际在用的思路：分层、跑不完就降级、等太久就升回来防饿死。
  • 上下文切换有代价（保存现场、换内存映射、缓存失效），线程太多会让 CPU 把时间花在切换上。
