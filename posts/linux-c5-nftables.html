Linux 管理专项第 5 章：防火墙 nftables

Linux 管理专项2026-11-25 · Linux 管理专项

服务器的网络大门，不能谁想进就进。Linux 的防火墙就是守门的：按你写的规则，决定每个网络包是放行还是丢弃。现代 Linux 的防火墙叫 nftables，替代了老一代的 iptables。

这一章讲 nftables 的基本概念：表、链、规则，怎么写一条“只放行 SSH 和网站”的规则，怎么查规则生没生效，怎么排障。目标是：学完这一章，你能给自己的虚拟机配一套“默认拒绝、按需放行”的防火墙。

先记住防火墙的第一原则：默认拒绝、按需放行。不是“先放行、再堵坏的”，而是“先全堵上，再一个个放行需要的”。这个顺序反了，安全就无从谈起。

nftables 是什么：表、链、规则

nftables 的结构是三层：表（table）是最外层，按协议族分（比如 ip 表管 IPv4，inet 表同时管 IPv4 和 IPv6）；链（chain）是表里的处理步骤，分 input（进来的包）、output（出去的包）、forward（转发的包）；规则（rule）是链里的每一条判断：符合条件就放行（accept）、丢弃（drop）或拒绝（reject）。

一个包从网卡进来，先过 input 链，按规则一条条比对：第一条匹配的规则决定它的命运，比对完没匹配上，就按链的默认策略处理。所以链的默认策略一般设为 drop（丢弃），再在前面加放行规则——这就是“默认拒绝、按需放行”的落地。

和 iptables 比，nftables 的语法更简洁、性能更好，还支持集合（set）和映射（map）这些高级功能。Ubuntu 22.04 之后、Debian 11 之后，nftables 是默认的防火墙后端。

写一套基础规则：只放行需要的

一套最小可用的服务器防火墙规则，大概是这样：放行本地回环（lo 接口，127.0.0.1 自己跟自己说话）；放行已建立的连接（ct state established,related，已建立的连接的回包要放行，否则你发出去的请求回不来）；放行 SSH（tcp 22 或你改过的端口）；放行网站（tcp 80、443）；其他全部丢弃。

写规则的命令是 nft（需要 root 或 sudo）：比如 nft add table inet filter、nft add chain inet filter input '{ type filter hook input priority 0; policy drop; }'、nft add rule inet filter input tcp dport 22 accept。规则也可以写进配置文件 /etc/nftables.conf，开机自动加载（systemctl enable nftables）。

写规则之前先想清楚：这台服务器要提供什么服务？每个服务用哪个端口？只放行这些端口，其他全堵上。不知道要放行什么就先看监听端口：ss -tlnp（预备课第 10 课讲过）列出所有监听的端口，再逐个问：这个端口是干什么的？还需要吗？

查规则与排障

查当前规则用 nft list ruleset，一次看全；查某个表的规则用 nft list table inet filter。改完规则要验证：从另一台机器（或虚拟机外）试着连一下该放行的端口（能连上）和不该放行的端口（连不上），两边都验证了才算配好。

排障时最常见的两种情况：第一，该放行的没放行——服务起着，但外面连不上，先看防火墙规则里有没有放行这个端口，再看服务是不是只监听了本地地址（127.0.0.1）；第二，不该放行的放行了——规则写得太宽（比如放行了所有端口），要收紧。

还有一个重要习惯：改防火墙规则之前，先确认你有别的办法进机器（虚拟机控制台），或者设一个定时恢复（比如用 at 或 systemd timer 在 10 分钟后清空规则），防止把自己锁在外面。改 SSH 配置的“救生绳”思路，在这里同样适用。

防火墙不是万能的

防火墙管的是“网络包能不能进出”，管不了“放进来的包里有没有恶意内容”。比如网站的 443 端口放行了，攻击者照样能通过这个端口发恶意请求——那是 Web 应用防火墙和程序本身要管的事。防火墙是第一道门，不是唯一的门。

防火墙要和前几章的措施配合：SSH 加固（第 4 章）管远程登录，包管理（第 1 章）管软件来源，用户管理（第 2 章）管谁能干什么，日志（第 6 章）管出事了能不能查到。多层防护，每层挡一部分，才是纵深防御。

老师经验：我配防火墙的习惯，是先写在纸上：这台服务器要提供什么服务、每个服务哪个端口、谁可以连。写清楚了再敲命令，敲完两边验证（该通的通、该堵的堵）。有一次同事直接在服务器上敲了一条“默认丢弃所有入站”，结果把自己的 SSH 也堵了，只能去机房接显示器才恢复——从那以后我们组里改防火墙都加一条“10 分钟后自动恢复”的保险。记住：防火墙规则写错了，代价是把自己锁在门外；写之前先想好怎么回来。

动手做

1. 只在你自己的 Linux 虚拟机里：运行 ss -tlnp，列出所有监听的端口，把每个端口和它背后的服务对应起来，问一句：这个端口还需要对外开放吗？
2. 在虚拟机里看看 nftables 的状态：sudo nft list ruleset（如果没有规则，会显示空），再运行 sudo systemctl status nftables，看看服务在不在；再 cat /etc/nftables.conf（如果存在），看看默认配置长什么样。
3. 在虚拟机里写一套最小规则练手：放行回环、已建立的连接、SSH 端口，其余丢弃，写进 /etc/nftables.conf，运行 sudo systemctl enable --now nftables 加载它，再从宿主机试着 SSH 登录虚拟机，验证规则生效；练完把规则恢复成原样。

避坑

别在生产系统、别人的服务器上练 nft 命令：动手只在你自己的虚拟机里做；改防火墙前先留好进机器的办法：虚拟机控制台或定时自动恢复，别把自己锁外面；默认策略设 drop 之前，先确认放行规则已经写好了：顺序反了，SSH 立刻就断；防火墙管包不管内容：放行了 443，不等于网站就安全了，应用层还要另外防护。

防火墙是网络大门的守门人：默认拒绝、按需放行，规则写清、两边验证。最后一章我们看出了问题去哪翻记录：第 6 章日志与 journald——Linux 的日志存在哪、怎么查、怎么长期保存。
