模块二小结：大管家是怎么管这台电脑的

小结2026-11-25 · 模块二第 1–21 章

十二章讲的其实是一件事：操作系统这个大管家是怎么管这台电脑的。程序想用 CPU、内存、硬盘、网卡，都不能直接伸手拿，必须通过操作系统。这一个规矩，是整个计算机安全的根基。

这十二章是怎么连起来的

先认清大管家。第 1 章说操作系统夹在硬件和程序之间，管硬件、管进程、给程序提供服务；内核和用户态是分开的，普通程序碰不到硬件。权限、隔离、审计这些词，背后都是操作系统在执行。

管的第一样东西是“谁在干活”。第 2 章的进程是程序跑起来的样子，是操作系统分配资源的基本单位；第 3 章的线程是同一进程里并行干活的执行单位，记住一句话：进程分资源，线程干活。进程之间默认是隔离的，第 4 章的进程间通信就是让它们在操作系统的安排下说话——很多真实的提权漏洞就出在 IPC 上，低权限的程序通过 IPC 通道让高权限的服务替它执行命令。多个线程同时碰同一块数据会出问题，第 5 章讲临界区和锁、死锁、竞态条件，竞态条件是真实存在的漏洞类别，TOCTOU 漏洞就靠“先检查、后使用”中间的时间差。最后 第 6 章的调度器决定谁先跑、跑多久，挖矿木马最明显的特征就是 CPU 占用率长期居高不下——调度器就是战场。

管的第二样东西是“东西放哪”。第 7 章的虚拟内存给每个进程画了一张“假地图”，程序按图索骥，操作系统在背后把虚拟地址翻译成真正的物理地址；页表就是进程隔离的第一道墙，Meltdown 和 Spectre 轰动的原因，就是它们打破了这道墙。第 8 章讲程序要访问的页不在内存里怎么办：触发缺页中断，操作系统去硬盘上把那页找回来；内存不够了，系统会陷入疯狂换页，整个机器都响应不了——内存耗尽是最常见的拒绝服务手段之一。第 9 章讲文件怎么存、谁能动：一个管“找得到”，一个管“动不得”；Linux 提权十次里有九次是从权限配置错误开始的。第 10 章的系统调用是程序请内核帮忙的唯一正规途径，也是用户态和内核态之间唯一的一座桥——恶意软件可以伪装名字、伪装窗口，但它要干坏事就必须调系统调用，所以看系统调用是看穿伪装最直接的办法。

最后动手验证。第 11 章是综合动手：把进程、线程、系统调用用系统自带的工具亲眼看一遍。安全分析的第一步永远是建立基线：先学会看正常进程长什么样，才能认出异常的。第 12 章收尾，对比 Windows 与 Linux 内核：概念相通，设计各有不同；服务器端基本是 Linux 的天下，终端和办公环境是 Windows 的天下，做安全，两边都要能上手。

第 13–21 章：从概念到两个系统，再回到一次真实的卡顿

前 12 章讲的是相通的概念，后 9 章讲的是概念在两个真实系统里长什么样，再把几个难啃的原理讲深，最后用一次实战串起来。第 13 章钻进 Windows 内部：注册表五个根键、服务、UAC、组策略和 Sysmon——蓝队天天打交道的地方，也是攻击者最爱藏身的地方，全程只读不改。第 14 章换到 Linux 这边：systemd 管服务、cron 管定时任务、SSH 管远程登录、journalctl 和 /var/log 管日志——同样的“管一台机器”，换了一套工具。接着是三个原理深挖：第 15 章的分段讲清地址翻译的另一条路，回头更明白分页好在哪；第 16 章讲 Windows 的多级反馈队列和 Linux 的完全公平调度——CFS 不是多级反馈队列，它是靠虚拟运行时间算公平账的另一种思路；第 17 章讲锁之外的同步工具：信号量、管程、条件变量，以及死锁发生后的检测、恢复与银行家算法。最后三章钻进底层：第 18 章的 inode、日志与崩溃一致性解释了删掉的文件为什么能恢复；第 19 章的 I/O 栈、轮询/中断/DMA 与驱动模型解释了操作系统怎么跟硬件打交道；第 20 章的虚拟机、命名空间与 cgroup 解释了一台机器怎么变出很多台。收尾的第 21 章是结课实战：在虚拟机里人为制造一次卡顿，用进程、内存、换页、I/O 的知识一步步定位，再写一份带数字和证据的复盘报告——前面 20 章的知识点，在这一次卡顿里全串成了一条线。

现在你能做什么

  • 打开任务管理器，看进程的 PID、状态、用户名，右键打开文件所在位置，看它的真实路径；查进程不只看名字，要看路径、父进程、启动参数这三样。
  • 在任务管理器里把“线程”列加出来，看每个进程有多少线程；在虚拟机的 Linux 里用 ps -eLf 看进程和它的线程。
  • 在虚拟机的 Linux 里用 strace 跟踪一次 ls，看它调了哪些系统调用、调了多少次。
  • 在任务管理器里看内存的“可用”和“缓存”，理解为什么内存占用率高不一定是坏事；在虚拟机的 Linux 里用 free -h、vmstat 1 看内存和换页情况。
  • 在虚拟机的 Linux 里用 find / -perm -4000 找系统里的 SUID 程序；在 Windows 上看一个文件的访问控制列表。
  • 说出 Windows 和 Linux 在内核结构、文件组织、安全机制上的主要不同。
