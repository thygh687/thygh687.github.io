数学基础专项第 2 章：集合与关系

数学基础专项2026-11-25 · 数学基础专项

上一章我们学会了讲道理：把一句话拆成命题，一步一步证明。这一章讲的是另一件更基础的事：把东西分组、配对。安全工作里到处都是分组：哪些账号是管理员、哪些文件是机密、哪些 IP 在黑名单里；也到处都是配对：哪个用户能访问哪个文件、哪个角色有什么权限。集合就是“分组”的数学名字，关系就是“配对”的数学名字。数据库、算法、访问控制，全都建立在这两个概念上。

集合就是一堆确定的东西放在一起，里面的每个东西叫元素。比如“本机所有管理员账号”是一个集合，“所有监听中的端口”是一个集合。判断一个东西属不属于某个集合，必须有明确的标准——“重要的文件”不是集合，因为“重要”没有明确标准；“标记为机密的文件”才是集合，因为标记是明确的。这个要求听起来较真，其实是安全分类的第一条规矩：分不清的东西，就管不住。

集合的运算：并、交、差、补

集合之间可以做四种基本运算，安全场景里每天都在用。并集：A 或 B 里有的东西都算进来。比如“能访问财务系统的用户”并上“能访问人事系统的用户”，就是“至少能访问其中一个系统的人”。交集：同时在 A 和 B 里的东西。比如“既是管理员、又在最近一周登录过”的账号——交集越小，范围越精确，排查时最有用的往往就是交集。差集：在 A 里但不在 B 里的东西。比如“所有账号”减去“最近 90 天登录过的账号”，剩下的就是长期不用的僵尸账号，清理账号先从差集下手。补集：在全集里但不在 A 里的东西。比如全集是“所有员工”，补集就是“非员工”——访客、合作方、外包人员，他们的访问权限要单独管。

这四种运算对应着数据库查询的四种基本操作：SQL 里的 UNION、INTERSECT、EXCEPT 本质上就是并、交、差。学模块五第 1 章的 SQL 时觉得是语法，到了这里就明白了：SQL 是在用集合的语言问数据库要东西。会画文氏图（几个圆圈互相重叠的图）的人，写 SQL 的 WHERE 条件时很少写错，因为条件之间的“且、或、非”在图上一眼就能看出来。

关系：把两个集合配对

如果说集合是分组，关系就是配对：把集合 A 里的一个元素和集合 B 里的一个元素连起来。比如 A 是“用户”，B 是“文件”，关系“能读取”就是一堆“用户—文件”配对。访问控制表、权限矩阵，本质上就是一张关系表：行是用户，列是文件，格子里打勾的就是“有关系”。

关系有三种重要的性质。自反：每个元素和自己有关系（比如“和自己权限相同”）。对称：A 和 B 有关系，B 和 A 也有关系（比如“在同一个部门”）。传递：A 和 B 有关系、B 和 C 有关系，那么 A 和 C 也有关系（比如“权限包含”：角色 A 包含角色 B 的权限，角色 B 包含角色 C 的，角色 A 就包含角色 C 的）。

满足自反、对称、传递的关系叫等价关系，它能把一个集合切成互不重叠的几块，每块叫一个等价类。比如按“所属部门”把员工分组，每个部门就是一个等价类——同一个部门的人，在“属于哪个部门”这件事上是等价的。安全分类就是在做这件事：把文件按密级分组，把用户按角色分组，分组之后再按组给权限，比一个一个给省事得多，也少出错。

还有一种关系叫偏序关系：自反、反对称、传递，比如“权限不低于”。密级“公开、内部、秘密、机密”就是一条偏序链：机密高于秘密，秘密高于内部。Bell-LaPadula 模型的“不上读”规则，用的就是这种偏序：低密级的主体不能读高密级的数据。理解了偏序，就理解了为什么权限体系一定要是个“层级”，而不是一团乱麻。

函数与映射：一个输入只对应一个输出

关系里有一种特别规矩的叫函数（也叫映射）：每个输入只对应一个输出。比如“根据用户名查出它的角色”，一个用户名不能同时对应两个角色——如果对应了两个，系统就不知道该按哪个角色给权限了。哈希函数也是函数：同一个输入永远算出同一个哈希值，不同的输入最好算出不同的值（模块五第 7 章讲过，哈希是数据的指纹）。

函数有三个有用的性质：单射（不同的输入对应不同的输出——没有两个用户共用同一个账号）、满射（每个输出都有输入对应——每个角色都有人用）、双射（既单射又满射——用户和账号一一对应）。设计账号体系时，心里装着这三个词，就能少犯“两个账号对应一个人”“一个角色没人用”之类的错误。加密算法里，加密必须是双射：能加密就要能解密，还原回来的必须是原来的明文，否则数据就丢了。

老师经验：我第一次做权限梳理，是在一张大表上把几百个用户和几十个系统一个一个打勾，打到眼睛花。后来学了集合，才明白正确的做法是先分组再配对：先把用户按角色分成等价类（一个角色一组人），再把角色和系统配对（一个角色能进哪些系统），最后用户继承角色的权限——表一下子从几百行变成几十行。还有一个教训：清理僵尸账号时，千万别只看“所有账号”这个集合，一定要做差集——“所有账号”减去“最近 90 天登录过”，剩下的才是要处理的对象。有一次我只看总数觉得“账号不多”，做了差集才发现三分之一都是半年没登录的旧账号，其中两个还是管理员权限。从那以后，排查先想“要算哪个集合的运算”，再动手查。

动手做

1. 只在自己的虚拟机或实验环境里做：列出你虚拟机上的用户（Windows 用 net user，Linux 用 cat /etc/passwd），分成“管理员”和“普通用户”两个集合，再列出“最近登录过”的用户，做一次交集和一次差集，写下结果。
2. 画一张文氏图：三个圆圈分别是“管理员账号”“最近一周登录过”“开着多因素认证”，把你的账号逐个放进对应的区域，看看有没有落在“管理员但没开多因素认证”这个区域里的账号。
3. 在你虚拟机里建一个小表（纸上或电子表格都行）：行是三个用户，列是三个文件，格子里打勾表示“能读取”，然后回答：这张表表示的关系满足自反、对称、传递中的哪几条？为什么？
4. 用 SQL 练一次集合运算：如果你在模块五第 1 章建过数据库，写一条带 UNION 和一条带 EXCEPT 的查询，验证它们的结果和你手算的并集、差集是否一致。

避坑

别用模糊的标准分组：“重要的文件”“可疑的用户”不是集合，先定明确标准再分组；别只看总数不看差集：僵尸账号藏在差集里，不在总数里；别把关系和函数混淆：一个用户对应两个角色时，系统按哪个执行？先想清楚再配；别忘了补集：只管“员工能干什么”，不管“非员工能干什么”，访客和外包的权限就成了盲区；别手工一个一个配权限：先按角色分组，再按组配对，出了错也好查。

集合与关系是数据库的底子，也是下一章图论的底子：图就是“点集 + 边集”，边就是点和点之间的关系。模块四第 3 章的数据结构里，集合、映射、图都是最常用的结构，学的时候觉得是三种东西，其实是一家子。下一章第 3 章：图论入门，我们就用点和线把网络、关系和路径画出来。

本课小结
  • 集合是明确标准下的一组东西；并、交、差、补四种运算对应着排查与 SQL 查询的基本操作。
  • 关系是两个集合之间的配对；访问控制表和权限矩阵本质上就是关系表。
  • 等价关系把集合切成互不重叠的组（等价类），是按角色、按密级分组的数学依据。
  • 偏序关系是“不低于”这样的层级关系，密级和权限体系都建立在它上面。
  • 函数是每个输入只对应一个输出的关系；单射、满射、双射决定了账号与加密设计合不合理。
