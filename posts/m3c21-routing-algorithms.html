模块三第 21 章：路由算法深入：链路状态与距离向量

计算机网络2026-11-25 · 模块三

第 4 章讲过，路由器之间要互相通气，交换“路况”，用的就是路由协议；OSPF、BGP 这些名字也已经出现过。这一章把名字背后的算法讲透：路由器到底在算什么？为什么有的协议数跳数，有的协议画地图？先记住一句话：路由算法只有两大家族——距离向量和链路状态，其他的都是它俩的变体或组合。

距离向量：只告诉邻居“我到各处有多远”

距离向量（Distance Vector）的思路像打听路：每台路由器只知道“我到各个目标的距离”，以及“这个距离是从哪个邻居那里听来的”。它定期把自己的整张距离表发给直接相连的邻居，邻居收到后算一算：“经由你到目标 X 的距离，是你说的距离加上我到你的距离；如果比我现在知道的更近，我就更新。”这个计算就是 Bellman-Ford 思想：到目标的最短距离，等于“经由某个邻居走”的所有选择里最小的那一个。

最典型的距离向量协议是 RIP：距离就是跳数（hop count），经过一个路由器算一跳。RIP 规定 15 跳是能到的最远距离，16 跳就是“到不了”（无穷大）。这个规定看起来很怪，其实是给“数到无穷”问题上的一道保险：链路断了之后，路由器们会互相传“经由你、经由我”的旧消息，距离一跳一跳往上涨，永远数不到头；有了 16 跳封顶，数到 16 就停，判定为不可达，环路也就收敛了。代价是 RIP 的网络直径不能超过 15 跳——小网络够用，大网络不行。

距离向量的优点是简单：路由器不用知道整张网的地图，只和邻居交换一张表，配置和计算都轻。缺点也正来自“只和邻居交换”：消息一跳一跳传，收敛慢；坏消息传得比好消息更慢（“好消息传得快，坏消息传得慢”是距离向量协议的经典毛病）；而且路由器只知道距离、不知道路径，容易形成环路。为了压住环路，人们加了不少补丁：水平分割（从哪个邻居学来的路由，不再发回给那个邻居）、毒性逆转（明确告诉邻居“经由我到不了那里”）、触发更新（有变化立刻发，不等定期）。这些补丁能缓解，不能根治——根治的办法是换一种思路：链路状态。

链路状态：每台路由器都有一张全网地图

链路状态（Link State）的思路完全相反：每台路由器把“我和谁相连、链路代价是多少”这条本地信息（链路状态通告，LSA）洪泛到整个网络——不是只告诉邻居，而是让全网每台路由器最终都拿到同一份“全网地图”。拿到地图之后，每台路由器在本地用 Dijkstra 算法算出从自己出发到所有目标的最短路，写进路由表。

Dijkstra 算法的思路可以一句话说清：从起点开始，一圈一圈向外扩，每次先确定离起点最近的那个还没确定的节点，因为“最近的那个不可能再有更短的路了”（所有代价都是正数，绕路只会更远）。确定一个，再用它去更新它邻居的距离，如此反复，直到所有节点都确定。最典型的链路状态协议是 OSPF：它把网络划分成区域（area），区域内部跑 Dijkstra，区域之间再汇总——这样大网络也不用每台路由器都算整张图。

链路状态的代价是“贵”：洪泛要带宽、存地图要内存、算最短路要 CPU；好处是收敛快、环路少，因为每台路由器看到的都是同一张地图，算出来的路是一致的。OSPF 的“代价”（cost）一般按带宽算：带宽越大，代价越小——所以 OSPF 会优先选带宽大的链路，而不是跳数最少的链路，这和 RIP 数跳数的做法正好形成对比。

动手算一次：4 节点网络的最短路

拿上图练手，从 A 出发，边上的数字是链路代价。第一步：A 的邻居是 B（代价 1）和 C（代价 4），最近的是 B，确定 B 的最短距离是 1。第二步：经由 B 能到 C（1+2=3），比直连的 4 更近，把 C 的距离更新为 3；经由 B 到 D 是 1+5=6，先记下。现在还没确定的节点里 C 最近（3），确定 C 的最短距离是 3。第三步：经由 C 到 D 是 3+1=4，比之前记的 6 更近，更新为 4；确定 D 的最短距离是 4。结果：A 到 B 是 1，到 C 是 3（走 A→B→C），到 D 是 4（走 A→B→C→D）。

算完对照两个点。第一，直连不一定最短：A 到 C 直连是 4，绕经 B 反而是 3——“最近的路”要算出来，不是看出来的。第二，Dijkstra 每确定一个节点就不再改它：B 确定为 1 之后，不会再有更短的路到 B，因为所有代价都是正数，任何绕路都只会更远。这个“确定了就不改”的性质，就是 Dijkstra 正确的根。

把这个小例子放大，就是 OSPF 在真实网络里做的事：每台路由器对着同一张全网地图跑同样的算法，算出自己的最短路。距离向量协议则完全不同：它不画地图，只一遍遍问邻居“你到那儿多远”，再加一跳算自己的距离——简单，但慢，而且容易在环路里打转。

层次路由与 BGP：网太大了，要分层

全世界的路由器不可能都跑同一个算法、共享同一张地图——规模太大，算不动，也没人愿意把自己的内部结构告诉全世界。所以路由是分层的：一个管理域内部（比如一个公司的网络、一个运营商的网络）叫一个自治系统（AS），内部用内部网关协议（IGP），比如 OSPF、RIP；自治系统之间用外部网关协议（EGP），实际上就是 BGP。

BGP 是策略路由，不是“最短路”路由。它交换的不是代价数字，而是“到某个网段，可以经过哪些自治系统”这样的路径信息，外加各自治系统自己定的策略：比如“我的流量不经过某个运营商”“优先走便宜的链路”“这条路只给某些客户用”。BGP 选路看的是一串策略规则的优先级（本地优先级、AS 路径长度等等），而不是谁的代价数字最小——因为自治系统之间没有统一的“代价”标准，商业关系和政策比纯粹的距离更重要。

这个分层也解释了一个常见现象：你访问一个网站，包走的路不一定是地理上最短的——运营商之间的商业协议、策略和价格，都会影响 BGP 的选择。排错时也要分清层次：公司内网的问题看 OSPF，跨运营商、跨国访问的问题往往在 BGP；两个层次的工具和排查思路完全不同。

老师经验：现场最经典的故障是“内网通、外网不通，内网路由表看着都对”。一查，内网 OSPF 没问题，问题在出口的 BGP：运营商那边收敛还没完成，或者策略把我们的网段过滤掉了。还有一次，两个路由器之间链路抖动，OSPF 不停地重新算路、洪泛 LSA，全网的 CPU 都被拖高——链路不稳时，链路状态协议的“全网都知道”反而成了放大器。记住：RIP 的问题是慢和环路，OSPF 的问题是抖动会全网扩散，BGP 的问题是策略错了路就绕远。三者排错的第一步，都是先问“这是哪一层的路由问题”。

动手做

1. 手算一次最短路。在纸上画一个 4 节点网络，自己定 5 条链路的代价，用 Dijkstra 从一个节点出发算到其余三点的最短距离和路径；再换一个起点重算一遍。算完对照本章的例子，检查“直连不一定最短”是不是也出现在你的图里。
2. 在虚拟机里看真实的路由表。Linux 虚拟机跑 ip route，Windows 虚拟机跑 route print，找到默认路由（0.0.0.0/0）那一行：目标网段、下一跳、走哪块网卡、度量值（metric）各是多少。再改一下虚拟机的网络（比如断开再重连），看路由表哪一行变了。
3. 对比两种思路。用本章的 4 节点图，假装自己是距离向量路由器：只和邻居交换距离表，模拟链路 C–D 断掉之后，距离是怎么一跳一跳传开的；再假装自己是链路状态路由器：洪泛一次“我和谁断了”，全网立刻都知道——体会两种算法收敛速度的差别。
4. 看一次 BGP 的影子（只看公开信息，不做任何操作）。在虚拟机里对 example.org 做一次 traceroute（Linux：traceroute example.org，Windows：tracert example.org），数一数经过了多少跳，想一想：这些跳里，哪些属于同一个自治系统、哪些是跨运营商的交接点。只观察，不对任何真实网络做探测之外的操作。

避坑

别把 RIP 和 OSPF 的“距离”混为一谈：RIP 数跳数、15 跳封顶，OSPF 算代价、一般按带宽来，跳数最少不等于代价最小；别以为 Dijkstra 算的是“看起来最近的路”：它算的是代价总和最小的路，直连常常不是最优；别忘了距离向量收敛慢：链路断了之后，坏消息要一跳一跳传，期间可能出现环路，别在收敛完成前下结论；别把 BGP 当成“更大的 OSPF”：BGP 是自治系统之间的策略路由，选路看策略和商业关系，不是单纯的最短路；别在真实网络里乱动路由配置：路由实验只在自己的虚拟机里用静态路由练手，动生产路由器的配置是事故的起点。

路由算法讲完，模块三的“路怎么走”这条线就彻底通了：第 3 章的 IP 选路、第 4 章的子网与路由协议、这一章的两种算法家族，拼起来就是路由器每天在做的事。下一章回到应用层：除了 DNS 和 HTTP，网络上还跑着哪些协议，顺手写一个只在自己虚拟机里跑的 Socket 程序：第 22 章：应用层协议：SMTP、FTP、SNMP、NTP 与 Socket 编程。

本课小结
  • 路由算法分两大家族：距离向量只和邻居交换距离表，链路状态洪泛全网地图、本地算最短路。
  • 距离向量用 Bellman-Ford 思想迭代更新；RIP 数跳数，15 跳是最远、16 跳等于到不了，收敛慢、易环路。
  • 链路状态用 Dijkstra 算法：从起点一圈圈向外扩，每次先确定最近的节点；OSPF 按带宽算代价，分区域管理大网络。
  • 4 节点手算结果：A 到 B 是 1，到 C 是 3（经 B），到 D 是 4（经 B、C）；直连不一定最短。
  • 路由是分层的：自治系统内部用 OSPF、RIP，自治系统之间用 BGP；BGP 是策略路由，选路看策略而不只是最短路。
