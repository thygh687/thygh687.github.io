模块一第 4 章：汇编入门

组成原理2026-11-24 · 模块一

汇编是离机器最近的语言：一条汇编指令，基本对应一条机器指令。看懂汇编，就等于能直接读懂 CPU 在干什么。以后学漏洞和逆向的时候，都要看汇编——恶意软件不会给你源代码，能看的只有汇编；崩溃转储里能看的，也只有汇编。这一章的目标不是让你会写汇编程序，而是让你会读：看到一段汇编，能一行一行跟出寄存器里的值在怎么变。

为什么学汇编：高级语言藏起来的东西

你写 if (a == b)，电脑里没有“如果”这个概念，只有比较和跳转；你写 for 循环，电脑里没有“循环”，只有跳转回上一行；你调用一个函数，电脑里没有“函数”，只有把返回地址压进栈、跳过去、再跳回来。高级语言把这些全藏起来了，汇编把它们全摊开。学安全的意义就在这里：漏洞不发生在高级语言的抽象层，发生在机器层——返回地址被覆盖、比较用的标志位被误解、循环的边界差了一位，全是汇编层面才看得见的东西。读不懂汇编，就只能在漏洞的门外猜。

寄存器和基本指令

AX、BX、CX、DX 是通用寄存器，相当于 CPU 手头的四个小抽屉。64 位电脑里它们还有更大的名字（RAX、RBX 等），先知道有这回事就行：RAX 是 AX 的 64 位版本，EAX 是 32 位版本，AX 是低 16 位——同一个抽屉，按多大去用，名字就不一样。几个最常用的指令：MOV 是搬数据，把一个值放进寄存器；ADD、SUB 是加减；CMP 是比较两个值；JMP 是无条件跳转，跳到别处去执行；JNE 是“不相等就跳”，用来做循环和判断。

CMP 是关键：CMP CX, 0 本身不改变 CX，它只是做一次减法、把结果记在标志位上——相等了，零标志 ZF 就置 1；不相等，ZF 是 0。然后 JNE（Jump if Not Equal）就看 ZF：ZF 是 0 才跳。也就是说，判断不是“指令在思考”，是“比较改了标志位，跳转去读标志位”。第 1 章的补码在这里会再现：有符号比较和无符号比较，读的是不同的标志位（符号位、溢出位 vs 进位位），用的跳转指令也不一样——同一个 CMP，后面跟 JG（有符号大于）和 JA（无符号大于），结果可能完全相反。符号混淆的漏洞，就是在这里埋下的。

64 位寄存器：RAX、EAX、AX、AL 是同一个抽屉

上面一段是先拿 16 位的名字（AX、BX、CX、DX）入门，好认、好记，但这只是历史遗留的讲法：现在的电脑都是 64 位，日常读汇编、看调试器，见到最多的是 RAX、RBX 这样的 64 位名字，16 位名字反而少见。关键要记住：RAX、EAX、AX、AL 不是四个寄存器，是同一个寄存器的四种宽度——
RAX：64 位，整个寄存器；EAX：32 位，RAX 的低 32 位；AX：16 位，RAX 的低 16 位；AL：8 位，RAX 的最低一个字节。
打个比方：RAX 是一整个抽屉，EAX 是抽屉的下半截，AX 是再下一小截，AL 是最底下的一格——往 AL 里写一个字节，只改 RAX 最低的 8 位，上面几位不动。反过来要小心：往 EAX 里写一个 32 位的值，会把 RAX 的高 32 位清零——读汇编时看错宽度，算出来的值就全错了。RBX、RCX、RDX 也是一样的道理，各自有 EBX/BX/BL、ECX/CX/CL、EDX/DX/DL 这几档宽度。

读这张图从右往左看：最右边的 AL 只有 8 位，往左一档是 16 位的 AX，再往左是 32 位的 EAX，整条是 64 位的 RAX——宽度不同，寄存器是同一个。

一个完整的例子：求 1 到 5 的和

MOV CX, 5：把 5 放进 CX，当计数器。
MOV AX, 0：AX 清零，用来存结果。
loop: ADD AX, CX：AX 加上 CX。
SUB CX, 1：CX 减 1。
CMP CX, 0：比较 CX 和 0。
JNE loop：不相等就跳回 loop 继续。
跑完之后 AX 是 15，也就是 1+2+3+4+5。这就是循环在机器层面的样子：没有“for”这个概念，只有跳转。

单步跟一遍（别跳过这一步）：初始 AX = 0，CX = 5；第一轮 ADD 后 AX = 5，CX = 4；第二轮 AX = 9，CX = 3；第三轮 AX = 12，CX = 2；第四轮 AX = 14，CX = 1；第五轮 AX = 15，CX = 0。CX 到 0 时 CMP CX, 0 让 ZF 置 1，JNE 不跳，循环结束。

再看一个 64 位例子：两个数相加

上面的例子用的是 16 位寄存器，是为了好跟；真正的 64 位代码长下面这样——只三行，照着读就行：

; 64 位例子：3 + 4，结果留在 RAX 里
    mov rax, 3      ; RAX = 3
    add rax, 4      ; RAX = 3 + 4 = 7
    ret             ; 返回，调用者从 RAX 里取结果

注意三点：第一，指令和寄存器名都写成了小写，汇编不区分大小写，MOV 和 mov 是一回事；第二，分号后面是注释，CPU 不执行；第三，ret 不是“结束程序”，是“回到调用我的地方”——结果怎么带回去，看下一节的调用约定。

顺带认一个词：mov rax, 3 里的 3 是直接写在指令里的数，叫立即数；操作数除了立即数，还能从寄存器、内存里来，具体分法第 7 章系统讲，这里知道有这回事就行。

调用约定入门：参数放哪，返回值放哪

函数之间传参数不能靠“心有灵犀”，得有一套所有人都遵守的规矩，这套规矩就叫调用约定。Windows 上的 64 位程序用的是 Windows x64 调用约定，一句话就能记住：前四个参数依次放进 RCX、RDX、R8、R9，返回值放进 RAX；第五个起的参数放栈上。所以上面那个小例子如果写成一个“加法函数”，调用者会先把两个数放进 RCX 和 RDX，函数里 mov rax, rcx 再 add rax, rdx，最后 ret，结果就在 RAX 里等着被取走。

调用约定是学汇编绕不开的，因为读反汇编时，函数开头几行经常就是从这几个寄存器里取参数——不知道这个规矩，就不知道函数吃进去的是什么，也就看不懂它在干什么；以后调系统函数、看漏洞利用代码，也都要按这个规矩传参。还有一句提醒：这套规矩是 Windows 的，Linux 上的 64 位程序用的是另一套（前两个参数放 RDI、RSI），别混着用。操作数除了放寄存器，还能直接写在指令里、放在内存里——数据到底从哪来，第 7 章会系统讲寻址方式。

调用者那边长这样——先把参数放进约定的寄存器，再 call：

; 调用者：把 3 和 4 交给加法函数
    mov rcx, 3      ; 第一个参数 → RCX
    mov rdx, 4      ; 第二个参数 → RDX
    call add_numbers ; 调完回来，答案在 RAX 里

对照着看：调用者按约定把参数放进 RCX、RDX，函数按约定从 RCX、RDX 里取、把结果放进 RAX——两边都守同一套规矩，函数调用才能对上号。四个寄存器放满了才用栈，所以只有参数很多的函数，才会在反汇编里看到往栈上写参数的指令。

练手要用的两个工具：NASM 与 x64dbg

只看书学汇编是学不会的，得有两个工具配合：一个汇编器，一个调试器。汇编器用 NASM（Netwide Assembler），一个免费开源的汇编器，能在 Windows 上装、能跑——你把上面那几行汇编存成文件，NASM 就能把它汇编成机器能跑的程序。调试器用 x64dbg，一个免费开源的 Windows 调试器，支持 32 位和 64 位程序，同样能在 Windows 上装来练。

为什么学汇编一定要配一个调试器？因为汇编是“一步一世界”的语言：光看代码，你很难想象每条指令之后寄存器里到底变成了什么；调试器能让你单步执行——一次只跑一条指令，每跑一条就停下来，亲眼看 RAX、RCX 和标志位变成了什么值，错在哪一步一目了然。逆向分析、崩溃分析，靠的也正是这个本事：程序跑偏了，在哪条指令上跑偏的，调试器里单步跟一遍就知道了。两个工具都只在虚拟机或自己的实验环境里装来练，别拿到别人的电脑、别人的程序上去试。

再多一句：NASM 的活就是“把汇编翻译成机器码”，刚入门不用管它中间还分几步；x64dbg 里除了单步，还有断点——在某一行设个断点，程序跑到那行就停住，不用一步一步按到底，长程序就靠断点定位。在 x64dbg 的寄存器窗口里，你会同时看到 RAX、EAX、AX、AL 这几个名字——改其中一个，另外几个跟着变，因为它们本来就是同一个寄存器。

栈：后进先出，函数和返回地址的家

栈是一块后进先出的内存，PUSH 是压进去，POP 是弹出来。函数调用、返回地址都存在栈里。以后讲缓冲区溢出的时候，栈是主角，现在先混个脸熟。

调用一个函数时，CPU 先把“做完回哪去”（返回地址）压进栈，再跳到函数开头；函数做完执行 RET，把返回地址弹出来，跳回去继续。栈顶指针（SP）永远指着栈顶，栈是往低地址方向长的——新压进去的东西，地址比原来的小。这两个细节现在记下来：缓冲区溢出攻击的核心，就是往栈上写太多数据，把挨着的返回地址盖掉，RET 弹出来的就不再是原来的地址，而是攻击者写进去的地址，CPU 一跳，就跳到攻击者准备好的代码上去了。栈这个“脸熟”，以后会变成主角。

栈和返回地址的故事到这里先告一段落：缓冲区溢出完整的讲法——怎么溢出、攻击者怎么改写返回地址、系统有哪三道防线——在模块九第 1 章：汇编与缓冲区溢出，那一章会把这课的栈、寄存器和调用约定全用上。

什么时候用汇编，什么时候不用：日常写程序几乎不用手写汇编，编译器生成的比人写的好；但读汇编是安全工作的日常：逆向一个可疑程序、分析一次崩溃、确认一个补丁到底改了什么，都要读汇编。寻址方式（操作数从哪来：寄存器、内存、立即数）是读汇编的另一半，第 7 章会系统讲。

老师经验：看可疑程序，我从不先看它“长什么样”，先看它调了哪些关键函数、栈上放了什么。逆向的头三分钟最值钱：找到程序的入口，顺着 CALL 一层层跟，看到它读文件、连网络、改注册表的地方先做记号。读汇编最忌讳一行一行死磕——先抓结构：哪几行是一个循环、哪几行是一个判断、返回地址在哪，结构清楚了，细节再慢慢对。还有一条：崩溃转储里看到 RIP 指到一串 0x41（字母 A 的 ASCII），别怀疑，先想想是不是哪里的输入没做长度检查，把返回地址盖成了输入的内容。

4. 进阶（在虚拟机里做）：装一个调试器，单步执行一段小程序，亲眼看 AX、CX 和标志位每一步怎么变——纸上跟和亲眼看，完全是两回事。
5. 进阶（只在虚拟机或自己的实验环境里做）：装 NASM 和 x64dbg，把上面那个 64 位小例子（3 + 4）汇编出来，用 x64dbg 单步执行，亲眼看 RAX 从 3 变成 7，再看一眼 RCX、RDX 里有没有东西——调用约定的规矩，在调试器里是能直接看到的。

避坑

这一章不用背指令，先看懂 MOV、ADD、CMP、JMP 这几个就行；汇编是工具，不是目的，学到后面逆向课还会再见；读汇编要一行一行跟寄存器的值，别凭感觉猜；最容易错的是把 CMP 当成“比较完就完了”——它改的是标志位，真正的判断在后面的跳转指令里；还有，别把有符号和无符号的跳转混着用，JG 和 JA 不是一回事；最后，别在 64 位代码里只盯着 AX 想问题——写 EAX 会把 RAX 的高 32 位清零，读错宽度，值就全错了。

下一章看 CPU 是怎么跟外面的世界打交道的：第 5 章：总线与输入输出。栈和返回地址的故事，到了第 9 章中断与 DMA还会再续上——中断发生时，CPU 也要把现场压进栈。

本课小结
  • 汇编是离机器最近的语言，一条汇编基本对应一条机器指令；学安全的意义在于读，不是写。
  • 循环和判断在机器层面都不存在，只有比较改标志位、跳转读标志位、改 PC 跳回去。
  • 有符号和无符号比较读不同的标志位，JG 和 JA 不是一回事——符号混淆是真实存在的漏洞来源。
  • 栈是后进先出的内存，函数调用时返回地址压进栈，RET 再弹出来；返回地址被盖掉，CPU 就会跳到别处去。
  • 读汇编的方法：先抓结构（循环、判断、调用），再一行一行跟寄存器的值。
  • RAX、EAX、AX、AL 是同一个寄存器的四种宽度；现在的电脑都是 64 位，读汇编要按 64 位想问题，写 EAX 会把 RAX 的高 32 位清零。
  • Windows x64 调用约定：前四个参数放 RCX、RDX、R8、R9，返回值放 RAX——不知道这个规矩，就看不懂函数吃进去的是什么；学汇编要配调试器（x64dbg），单步执行、亲眼看寄存器每一步怎么变。
