模块二第 21 章：动手：综合实战——在一台机器上复现并解释一次卡顿

操作系统2026-11-25 · 模块二

模块二的结课实战只有一件事：在虚拟机里人为制造一次卡顿，再用前面 20 章的知识，一步步定位它为什么卡，最后写一份复盘报告。真实的安全工作里，排错和取证就是这样的流程：先复现，再定位，再解释，再写报告。能把一次卡顿讲明白，你就把模块二学活了。

先说安全边界，这件事只能在虚拟机里做。虚拟机是你的实验沙箱（第 20 章）：卡顿发生在虚拟机里，宿主机的 Windows 不受影响；实验结束，关掉虚拟机、恢复快照，一切归零。不要在自己的主力电脑上、不要在别人的电脑上、不要在任何真实服务器上人为制造卡顿。

实验设计：制造一次可控的卡顿

卡顿有三种经典成因，对应三种不同的制造方法，你可以三种都试，也可以先试一种。第一种是吃内存：写一个 Python 程序，一次分配一大块内存并且一直不释放（比如每 0.5 秒往一个列表里追加 100MB），虚拟机的内存被吃光后，系统开始疯狂换页，整个机器响应变慢——这是第 7 章虚拟内存和第 8 章缺页与换页的现场版。第二种是吃 CPU：跑几个 yes > /dev/null 或者一个死循环程序，把 CPU 占满——这是第 6 章调度和第 16 章多核调度的现场版。第三种是吃磁盘 I/O：用 dd 不停地往磁盘写大文件，或者同时开很多个读文件的程序——这是第 19 章 I/O 栈的现场版。

本章以第一种——吃内存——为主线走完整流程，因为它牵扯的知识点最多：内存、换页、进程、调度、I/O 全会露面。实验前先做三件准备：给虚拟机拍一个快照（出问题一键恢复）；记下虚拟机的内存大小（比如 4GB），吃内存的程序要控制在“能让系统难受、但不至于彻底死机”的量——比如每次追加 100MB、最多追加到 3GB，留一点余地；准备好两个观察窗口：一个看任务管理器（Windows 虚拟机）或 top/htop（Linux 虚拟机），一个看命令行，方便随时停掉实验程序。

第一步：复现卡顿

在虚拟机里的 Linux 上，新建一个文件 eatmem.py，内容只有几行：一个空列表，一个循环，每 0.5 秒往列表里追加 100MB 的数据（用 bytearray(100 * 1024 * 1024)），并打印当前已占用的 MB 数。跑起来：python3 eatmem.py。在 Windows 虚拟机上也一样，用 Python 写同样的程序，或者用任务管理器自带的“吃内存”思路——打开十几个大网页也能达到类似效果，但 Python 程序的好处是“吃多少、吃多快”完全可控，复盘时数字写得出来。

复现时注意观察“卡顿是怎么一点一点来的”：一开始机器没感觉，内存占用慢慢爬；内存快满的时候，打开新程序开始变慢；内存彻底满了之后，连鼠标移动都卡——因为系统在疯狂换页：把内存里的页换到磁盘上、再把需要的页换回来，磁盘 I/O 被换页占满了，真正要干的活反而排不上队。这就是第 8 章讲的“颠簸”（thrashing）：系统把时间都花在换页上，没时间干正事。

第二步：观察四项指标

卡顿出现后，别急着下结论，先看四项指标，顺序是：进程、CPU、内存、磁盘 I/O。进程：任务管理器（Windows）或 top / htop（Linux）里按内存排序，哪个进程占内存最多？它的 PID 是多少？父进程是谁？命令行是什么（第 2 章：查进程不只看名字，要看路径、父进程、启动参数）？CPU：这个进程的 CPU 占用高吗？如果 CPU 占用不高但机器很卡，说明瓶颈不在 CPU；如果某个核跑满了、其他核闲着，说明是单线程程序占满了一个核（第 16 章）。内存：可用内存还剩多少？“已提交”或“缓存”是多少？Linux 上跑 free -h 和 vmstat 1，看 si（换入）和 so（换出）这两列是不是一直在涨——换页频繁是内存瓶颈的铁证。磁盘 I/O：资源监视器（Windows）或 iotop / iostat -x 1（Linux）里，磁盘读写是不是被换页占满了？

这四项看完，定位基本就清楚了：吃内存的程序内存占用一路涨、可用内存见底、换页指标狂涨、磁盘 I/O 被换页占满、CPU 占用却不一定高——这就是内存瓶颈的典型画像。如果换成吃 CPU 的实验，画像会完全不同：CPU 一个核或所有核跑满，内存和磁盘都很平静。不同的瓶颈有不同的画像，学会认画像，就学会了定位。

第三步：用原理讲清因果链

定位到“是哪个进程”还不够，复盘报告要讲清“为什么它会让整台机器卡”。以吃内存实验为例，因果链是这样的：吃内存的程序不断申请内存（第 7 章：每次申请都是一次虚拟内存分配）；物理内存不够了，操作系统启动页面置换，把不常用的页换到磁盘上的交换区（第 8 章）；其他程序要用的页被换出去了，下次要用时触发缺页中断，再从磁盘换回来（第 10 章：缺页中断是一次系统调用层面的事件）；磁盘比内存慢几万倍，换页越频繁，程序等得越久；最后系统陷入颠簸，大部分时间在换页，真正的工作反而做不出来。

把因果链再往前推一层，还能串上更多章节：这个吃内存的程序是一个进程（第 2 章），它里面的分配循环跑在一个线程上（第 3 章）；调度器（第 6、16 章）还在公平地给它分 CPU 时间，所以它能一直跑下去；它申请的每一块内存都要经过页表翻译（第 7 章）；它的文件读写如果有的话，还要走 I/O 栈（第 19 章）；它跑在虚拟机里，虚拟机本身的内存是 hypervisor 从宿主机上切出来的（第 20 章）——虚拟机的内存上限，就是 hypervisor 划给它的那一份。一次卡顿，能把模块二从头串到尾。

第四步：写一份复盘报告

复盘报告不用长，一页纸就够，但要有这六项：现象（什么时候、什么操作下、卡成什么样）；复现步骤（虚拟机配置、吃的什么资源、程序代码或命令）；观察数据（卡顿前后四项指标的数字，截图或抄下来）；定位结论（哪个进程、哪项资源是瓶颈，证据是哪几个数字）；因果解释（用原理讲清从“程序吃内存”到“整台机器卡”的链条）；验证（停掉程序后，指标是不是恢复正常、卡顿是不是消失——消失了才算验证通过）。

写报告时注意两个习惯。第一，写数字不写感觉：不写“内存占用很高”，写“内存占用从 1.2GB 涨到 3.8GB，可用内存剩 120MB，vmstat 的 si/so 从 0 涨到每秒几千”；不写“磁盘很忙”，写“iostat 显示磁盘利用率 98%，读写全是换页”。第二，写证据链不写猜测：每一个结论后面跟一个证据——“瓶颈是内存，因为换页指标在涨、停掉程序后换页指标归零、卡顿消失”。安全工作的报告就是这样写的：结论、证据、验证，三件套缺一不可。

老师经验：真实世界里的卡顿，十次里有九次不是病毒，是正常程序失控：浏览器开了几十个标签页、某个软件更新后开始漏内存、备份程序在上班时间全速跑。定位的顺序我永远是“先看资源、再看进程、最后才怀疑恶意软件”——因为资源和进程的数字不会说谎，恶意软件的怀疑没有数字支撑就是瞎猜。有一次用户说电脑“中午就卡、下午就好”，我一看任务管理器，定时任务里有个中午 12 点跑的备份程序，把磁盘 I/O 吃满了——改到半夜跑，问题就没了。还有一次是内存泄漏：一个程序的内存占用每天涨一点，从不回落，重启就好、过几天又卡——泄漏的特征就是“只涨不回落”，和我们实验里“主动吃内存”的曲线一模一样，只不过泄漏是程序自己不知道自己在漏。记住复盘的最后一问：停掉它，好了吗？好了，定位就对了；没好，说明凶手另有其人，继续查。

动手做

全部在虚拟机里做，做完恢复快照。1. 给虚拟机拍快照，记下虚拟机的内存大小；在虚拟机里写 eatmem.py（每 0.5 秒追加 100MB，打印已占用 MB 数），跑起来，观察机器从“没感觉”到“开始卡”到“很卡”的全过程，把每个阶段的内存占用数字记下来。2. 卡顿出现后，打开任务管理器或 top/htop，按内存排序找到吃内存的进程，记下它的 PID、内存占用、CPU 占用；Linux 上再跑 free -h 和 vmstat 1（看 si/so 两列），Windows 上看资源监视器的磁盘活动。3. 按 Ctrl+C 停掉 eatmem.py，观察指标多久恢复正常、卡顿是不是消失了——把恢复的时间也记下来。4. 换一种卡顿再试一次：跑 yes > /dev/null & 吃 CPU，对比它的画像（CPU 跑满、内存平静）和吃内存的画像有什么不同；做完用 pkill yes 停掉。5. 按“现象、复现步骤、观察数据、定位结论、因果解释、验证”六项，写一份一页纸的复盘报告，存在自己的笔记里。

避坑

只在虚拟机里人为制造卡顿，不要在主力电脑、别人的电脑或真实服务器上做；吃内存要留余地：不要一次把全部内存吃光，留一点给系统自己用，不然连停掉程序的终端都打不开；实验前先拍快照，实验后恢复快照；不要把“卡顿”等同于“中毒”：先看资源和进程的数字，数字指向哪里、凶手就是哪里；复盘报告写数字不写感觉，每个结论后面跟一个证据；停掉程序后卡顿消失，才算验证通过——没消失说明定位错了，继续查。

本课小结
  • 卡顿定位五步：复现、观察、定位、解释、复盘；停掉可疑程序后卡顿消失，才算验证通过。
  • 观察四项指标：进程（谁占得多）、CPU（哪个核满了）、内存（可用剩多少、换页指标涨不涨）、磁盘 I/O（是不是被换页占满了）。
  • 内存瓶颈的画像：内存占用一路涨、可用内存见底、换页指标狂涨、磁盘被换页占满、CPU 不一定高；CPU 瓶颈的画像完全不同。
  • 因果链要讲清：程序申请内存 → 物理内存不够 → 页面置换 → 缺页中断 → 磁盘比内存慢几万倍 → 颠簸，系统忙着换页、没时间干正事。
  • 复盘报告六项：现象、复现步骤、观察数据、定位结论、因果解释、验证；写数字不写感觉，每个结论跟一个证据。
