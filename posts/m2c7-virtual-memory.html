模块二第 7 章：内存管理：虚拟内存与分页

操作系统2026-11-24 · 模块二

每个程序都以为自己独占了全部内存，其实它们都在用虚拟内存。操作系统给每个进程画了一张“假地图”，程序按图索骥，操作系统在背后把虚拟地址翻译成真正的物理地址。

虚拟地址和物理地址

程序看到的地址是虚拟地址，从 0 开始，好像整块内存都是它的。真实的物理内存只有一份，由操作系统统一分配。翻译的工具叫页表：内存被切成一页一页（一般 4KB），页表记录每一页虚拟地址对应哪一页物理地址。CPU 里有个叫 MMU 的部件，专门干翻译的活，程序每次访问内存都要经过它。

为什么不直接用物理地址

如果程序直接用物理地址，三个问题马上就来了。第一，程序得知道自己被放在内存的哪个位置，换台机器、换个启动顺序，地址全变了，程序没法写。第二，程序之间会互相踩：一个程序写错一个地址，就能改掉另一个程序的数据。第三，内存会越用越碎：程序来来去去，空闲的地方被切得七零八落，大块的连续空间拼不出来。虚拟内存把这三个问题一次解决了：每个程序都以为自己从 0 开始独占全部内存，真实的落点由操作系统说了算。

但翻译也不是免费的。程序每访问一次内存，原则上都要查一次页表，查表本身也要访问内存——等于一次访问变成两次，慢了一倍。所以 CPU 里还有一个小缓存叫 TLB（快表），专门缓存最近用过的翻译结果：命中了就直接用，不用再查表。程序有个特点叫局部性——刚用过的地址附近，马上还会再用（模块一第 8 章讲过），TLB 的命中率很高，翻译的开销才被压了下来。

页表本身也要占地方。64 位系统的地址空间大得吓人，如果用一张平铺的大表，表本身能占掉好几个 GB。所以实际用的是多级页表：像查字典先查部首再查页码一样，一级一级往下找，用不到的地址范围，连表都不建。代价是翻译要多走几步——这又是 TLB 存在的理由。

访问出错意味着什么？如果程序访问的虚拟地址在页表里根本没有对应的页（比如访问了一个空指针 0x0，或者越界写到了不属于自己的地方），MMU 翻译失败，CPU 触发异常，操作系统直接终止这个程序。Linux 上你会看到“段错误（Segmentation fault）”，Windows 上是“访问冲突”——这不是内存坏了，是程序访问了不该碰的地址。调试的时候，看到段错误，先想“哪个指针是空的、哪个数组越界了”，而不是先怀疑硬件。

分页的好处

隔离：每个进程有自己的页表，看不见别的进程的内存，一个进程崩了不会拖垮别的。共享：同一份代码（比如系统库）可以映射到多个进程的虚拟地址里，物理上只存一份，省内存。灵活：程序要多少内存就给多少页，不够了再向操作系统要。

还有一个省内存的巧办法叫写时共享：父进程用 fork 创建子进程时，两个进程先共享同一份物理页，都只读；谁要改了，才真正复制一份给它（第 2 章讲过 fork 是怎么创建进程的）。这样创建进程又快又省内存。安全上还有一招：地址空间布局随机化（ASLR）让每个程序每次启动时，代码和库加载的虚拟地址都不一样——攻击者猜不到关键代码在哪，漏洞利用就难了很多。虚拟内存这套机制，既是性能设计，也是安全设计。

但虚拟内存不是无限内存。程序申请的内存最终还是要落在物理内存或硬盘上：内存泄漏的程序会一直占着页不放，虚拟内存再大也会被它吃光。任务管理器里“已提交”比物理内存大是正常的，真正要盯的是物理内存是不是长期贴着上限跑。

虚拟内存和硬盘

物理内存不够的时候，操作系统会把暂时不用的页挪到硬盘上的交换空间（Windows 叫页面文件，Linux 叫 swap），等要用的时候再搬回来。程序感觉不到，好像内存永远够用——但硬盘比内存慢上万倍，挪来挪去多了，电脑就卡了。至于操作系统怎么决定牺牲哪一页、缺页时到底发生了什么，下一章专门讲。

老师经验：进程隔离是安全的第一道墙，靠的就是页表。每个进程只能看到自己的内存，攻击者想偷看别的进程的数据，首先要突破这道墙。Meltdown 和 Spectre 这两个漏洞之所以轰动，就是因为它们打破了这道墙：普通程序能读到内核和其他进程的内存。补丁打了这么多年，根子还是硬件设计上的问题。所以内存管理不是纯理论，它是安全攻防的前线。

动手做

1. 打开任务管理器 → 性能 → 内存，看“已提交”和“分页池”这两个数字，体会虚拟内存比物理内存大。
2. 在虚拟机的 Linux 里输入 free -h，看内存和 swap 的使用情况。
3. 打开很多程序把内存占满，观察电脑变卡的过程——这就是在频繁换页。

避坑

虚拟地址和物理地址一定要分清，这是全章的核心；页表是翻译用的，不是存数据的；swap 是应急用的，不是内存的替代品，依赖它电脑会很卡。

本课小结
  • 虚拟地址是程序看到的假地图，物理地址是真实落点，页表 + MMU 负责翻译，TLB 缓存翻译结果。
  • 每个进程有自己的页表：隔离是安全的第一道墙，共享和写时复制省内存，ASLR 让地址每次启动都不一样。
  • 多级页表省空间，页表本身也要占内存；翻译失败就是段错误 / 访问冲突，意思是程序碰了不该碰的地址。
  • swap 是应急：物理内存不够才用，频繁换页电脑就卡；下一章讲缺页和置换。
