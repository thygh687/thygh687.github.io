模块三第 7 章：DNS、HTTP 与 TLS

计算机网络2026-11-25 · 模块三

你在浏览器里敲下一个网址、按回车，到页面出现，中间其实发生了三件大事：DNS 把名字变成地址，TCP 把路连通，TLS 把这条路加密，最后 HTTP 才在上面传网页。这一章把这三件大事串起来：每一件是干什么的、什么时候出问题、出问题长什么样。学安全的人要对这条链敏感，因为每一次“网站打不开”“浏览器报不安全”，都是这条链上某一环断了——而攻击者最爱断的，也正是这条链。

DNS：先把名字变成地址

人记名字，机器认地址。DNS 就是互联网的查号台：你给它一个域名，它还你一个 IP 地址。解析的全过程是这样的：浏览器先看自己的缓存，有没有刚查过的记录；没有就问操作系统，操作系统问配置好的递归解析器（通常是运营商或你自己配的 DNS 服务器）；递归解析器先看自己的缓存，没有就从根服务器开始一层层问下去——根服务器告诉它管 .org 的服务器在哪，.org 的服务器告诉它管 example.org 的服务器在哪，最后权威服务器给出 example.org 的 IP 地址，答案一级级传回来，沿途每一级都缓存一份，下次再问就不用跑全程了。

这个过程里有两个细节值得记住。第一，缓存无处不在：浏览器、操作系统、递归解析器都有缓存，所以同一个域名第二次打开快得多；但缓存也有过期时间（TTL），过期了就要重新问。第二，DNS 查询默认走 UDP（第 5 章讲过：一个问一个答，丢了再问一次就是了），只有回答太长装不下时才改走 TCP。

什么时候用 DNS 排错？第 6 课的 nslookup 就是专门干这个的：nslookup example.org 直接问 DNS 要地址。如果 ping 域名报“找不到主机”，但 nslookup 查得到地址，说明 DNS 没问题，问题在路上；nslookup 也查不到，那 DNS 本身就有问题——可能是 DNS 服务器挂了，也可能是名字根本不存在。更完整的解析过程，第 4 课已经讲过一遍，这一章是把它放回整条链里看。

出问题意味着什么？DNS 错了，错得最彻底：地址错了，后面 TCP 连得再稳、TLS 加密得再好，连的都是错的服务器。这就是 DNS 投毒和 DNS 劫持的原理：攻击者让你查到的地址是他的服务器，你的浏览器毫无察觉地把账号密码交给了冒牌货。第 12 章会讲这类攻击具体怎么做、怎么防。

HTTP：请求与响应，一问一答

地址有了、路连通了，浏览器和服务器之间说的话就是 HTTP。HTTP 的结构很简单，就是一问一答：请求（request）和响应（response）。请求分三部分：请求行（方法 + 路径 + 版本，比如 GET /index.html HTTP/1.1）、请求头（Host、User-Agent、Cookie 这些附加信息）、请求体（POST 提交的数据，GET 一般没有）。响应也是三部分：状态行（版本 + 状态码，比如 HTTP/1.1 200 OK）、响应头（Content-Type、Content-Length、Set-Cookie）、响应体（真正的网页内容）。

状态码是最值得记的排错信号：2xx 是成功（200 最常见），3xx 是重定向（301 永久搬家、302 临时跳转），4xx 是客户端的错（404 找不到页面、403 不许看），5xx 是服务端的错（500 服务器内部出错、502 网关收不到后端响应）。看到 404，先别怪网：路是通的，是你要的东西不存在；看到 502，问题在服务器那一头，和你的电脑没关系。HTTP 的完整讲法在第 5 课，这一章只取排错时最要紧的部分。

还有一点：HTTP 本身不加密。请求行、请求头、Cookie，路上任何一个节点都能看得明明白白。这就是为什么需要 TLS——不是 HTTP 不好，而是它天生就是明文协议。

TLS：给 HTTP 穿上加密外衣

浏览器地址栏里那个小锁，锁的就是 TLS。TLS 干三件事：加密（路上的人看不懂内容）、认证（确认对方真是你要找的服务器，靠证书）、完整性（内容被改过能发现）。没有 TLS，你的登录密码、Cookie 就是明文飘在路上；有了 TLS，中间人只能看到你在和哪个服务器说话，看不到你们说了什么。

这一章以 TLS 1.3 为主讲，因为它是现在应该用的版本。TLS 1.3 的握手只需要一次往返（1-RTT）：客户端发一个 ClientHello，里面带上自己支持的加密算法和一份密钥材料；服务端回 ServerHello，带上选定的算法、自己的密钥材料和证书；客户端验证证书没问题，算出会话密钥，发一个 Finished，握手完成，接下来就是加密的 HTTP。整个过程一次往返就够了，所以 HTTPS 首次打开的速度比以前快得多。

TLS 1.3 还有一个关键改进：前向保密。每次会话用的密钥都是临时生成的，用完就扔——哪怕服务器的私钥很多年后泄露了，攻击者也解不开以前录下来的流量。以前的版本里，会话密钥和服务器私钥挂钩太紧，私钥一丢，历史流量全能解开。1.3 把这个口子堵上了。

对照提一句 TLS 1.2：它是上一代版本，握手需要两次往返（2-RTT），还保留了一些现在已经淘汰的旧加密套件和算法（比如 RSA 密钥交换、不支持前向保密的套件）。理解 1.2 只需要记住这两点差别：多一次往返、旧套件不安全。实际工作中，服务器应该优先用 1.3，1.2 只作为兼容老客户端的备选，而且要关掉那些已淘汰的旧套件。

三者怎么串起来：从敲网址到页面出现

把三件大事按顺序排好，就是一次完整访问的全过程：输网址 → DNS 查地址 → TCP 建连 → TLS 握手 → HTTP 发请求、收响应。哪一环断了，页面就停在哪一环，报错也各不相同：DNS 断了，浏览器说“找不到服务器”；TCP 断了，浏览器一直转圈最后超时；TLS 断了，浏览器报“连接不是私密连接”或证书错误；HTTP 断了，浏览器能连上但拿到的是 404、500。

老师经验：用户报“网站打不开”，我按这条链从前往后查，十次有九次三分钟定位：先 nslookup——查不到就是 DNS 的问题，换个 DNS 再试；查得到就 curl 看能不能连上 443——连不上是 TCP 或防火墙；连上了但浏览器报证书错误，别急着点“继续访问”，先看证书是过期了、域名对不上，还是签发者根本不认识——域名对不上是最危险的信号，说明你可能连到了冒牌服务器。还有一条：证书过期是最常见的“突然打不开”，服务器管理员忘了续期，网站本身一点没坏，续上证书立刻就好。排错按链走，别跳步，跳步就会把 DNS 的问题当成网站的问题修半天。

动手做

1. 在虚拟机里用 OpenSSL 搭一个本地 TLS 服务：先生成一张自签名证书（openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 1 -nodes -subj "/CN=localhost"），再跑 openssl s_server -accept 8443 -cert cert.pem -key key.pem -tls1_3；另开一个终端跑 openssl s_client -connect 127.0.0.1:8443 -tls1_3，看握手输出里协商出来的是不是 TLS 1.3，以及用的是哪个加密套件。
2. 在刚才的 s_client 会话里输入 GET / HTTP/1.1 加一行 Host: localhost 再空一行，看加密通道里 HTTP 请求长什么样——TLS 加密的是这段对话，但对话本身还是 HTTP。
3. 在虚拟机里跑 nslookup example.org，把返回的地址记下来，再跑 curl -v http://127.0.0.1:8000/（本地服务，见第 5 章动手做），对比 DNS 查地址和 HTTP 发请求分别是哪一步——DNS 只给地址，不传网页。

避坑

别把“有小锁”等同于“网站可信”：TLS 只证明连接加密、证书有效，不证明网站本身不是钓鱼站，钓鱼站也能有合法证书；别忽略证书错误继续访问：域名对不上、证书过期、签发者不认识，都是“可能连错了服务器”的信号，点“继续”之前先确认；别以为 DNS 查到地址就万事大吉：地址可能是被投毒的假地址，DNS 本身不验证真假；别在真实网站上练握手和抓包：所有实验只在虚拟机和自己的电脑上做，只连 127.0.0.1 这类本地地址。

HTTP 还有下一代：一个页面要几十个文件，HTTP/1.1 一次只能传一个，慢在哪里、新协议怎么解决，是第 8 章：HTTP/2、HTTP/3 与 QUIC的事。回头看第 5 章的握手和第 6 章的窗口：TLS 握手跑在 TCP 连接上，HTTP 跑在 TLS 之上，每一层都踩着下一层的肩膀。

本课小结
  • DNS 把域名变成 IP 地址：浏览器缓存、递归解析器、根到权威一级级问下去，沿途都缓存。
  • HTTP 是一问一答：请求行 + 请求头 + 请求体，对应状态行 + 响应头 + 响应体；状态码先看百位：2 成功、3 跳转、4 客户端错、5 服务端错。
  • TLS 1.3 握手只要一次往返（1-RTT），每次会话密钥临时生成、用完就扔，前向保密；TLS 1.2 要两次往返，还留着已淘汰的旧套件。
  • 一次访问的顺序是 DNS 查地址 → TCP 建连 → TLS 握手 → HTTP 发请求，哪一环断了就停在哪一环。
  • 有小锁只代表连接加密，不代表网站可信；DNS 查到的地址可能是假的，证书报错不要随手点继续。
