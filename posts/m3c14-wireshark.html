模块三第 14 章：动手：Wireshark 抓包

计算机网络2026-11-25 · 模块三

前面十三章讲的包、握手、DNS、端口，全是纸上的东西。这一章把它们亲眼看一遍：Wireshark 是网络分析的标准工具，它把网卡上流过的每一个包都抓下来、拆开给你看。先立一条铁规矩：只抓自己的虚拟机流量——虚拟机之间互相 ping、访问自己搭的服务。抓别人的网络、抓真实网络上的流量，是偷窥别人的通信，绝对不做。

装 Wireshark，选对网卡

去 Wireshark 官网下载安装包，安装时勾上 Npcap（抓包用的驱动，没有它 Wireshark 抓不到包）。装好打开，主界面是一张网卡列表：以太网、Wi-Fi、虚拟机网卡都在上面。选哪张？看你要抓谁的流量——在虚拟机里抓，就选虚拟机的网卡；在宿主机上抓虚拟机之间的流量，选宿主机上那块连着虚拟机的网卡。选错网卡，抓到的要么是空的，要么是别人的流量。

点网卡名字旁边的蓝色鲨鱼鳍图标就开始抓，红色方块停止。刚开始抓，包会像瀑布一样刷屏，别慌：那是正常的网络背景噪音，第一件事永远是先过滤，再看。

过滤：先缩小，再细看

不设过滤，满屏都是噪音。顶部的过滤栏就是用来缩小范围的，常用的几个记下来：

  • icmp：只看 ping 的包。
  • tcp.port == 80：只看走 80 端口的包（第 10 章的端口表在这里就用上了）。
  • dns：只看 DNS 查询。
  • ip.addr == 192.168.56.11：只看和某台虚拟机有关的包（把地址换成你自己的虚拟机地址）。
  • tcp.flags.syn == 1：只看带 SYN 标志的包，也就是握手的第一步。

过滤栏变绿说明语法对了，变红说明写错了。还有一个细节：抓包时也可以设“捕获过滤器”，抓之前就只抓想要的，适合流量大的时候；初学先用显示过滤器就够了，抓全了再慢慢筛。

读懂一次 TCP 三次握手

让一台虚拟机去访问另一台虚拟机上搭的服务（比如一个简单的网页服务），过滤 tcp，你会看到握手的三步，跟第 5 章讲的一模一样——只不过现在是真的包：

点开第一个包的 TCP 层，看 Flags：只有 SYN 是 1，这就是“我要建连”。第二个包 SYN 和 ACK 都是 1，第三个包只有 ACK 是 1。三个包的序号（Sequence Number）是连起来的：第二个包的确认号（Acknowledgment Number）等于第一个包的序号加一——这就是 TCP“可靠”的底子：每个字节都有编号，丢了能发现，乱了能排好。

握手出问题意味着什么？只看到 SYN、没看到 SYN, ACK 回来：对方没在监听这个端口，或者防火墙把包挡了，或者对方根本不在线。看到 SYN, ACK 之后没有第三个 ACK：发起方有问题，或者中间有设备把包丢了。看到一堆 RST（复位）：对方明确拒绝连接，端口没开是最常见的原因。

读懂一次 DNS 查询

过滤 dns，在虚拟机里 nslookup example.org，抓到的一般是两个包：一去一回。去的包是查询（Standard query），问“example.org 的地址是多少”；回的包是响应（Standard query response），带着答案回来。点开 DNS 层看：查询里有个 Transaction ID，响应里同一个 ID——靠这个把一问一答配成对。答案在 Answers 段里，A 记录就是那个 IP 地址。

再看传输层：DNS 查询走的是 UDP 53 端口（第 7 章讲过为什么 DNS 喜欢 UDP：一次问答就完事，没必要建连）。如果看到 DNS 走的是 TCP 53，也别慌——答案太长、一个 UDP 包塞不下的时候，DNS 会改走 TCP，这很正常。抓包时还有一个常见发现：你明明只查了一个域名，DNS 查询却有一串——那是系统在帮你补全、或者浏览器在预取，不是中毒。

老师经验：排错时我有一句口头禅：“别猜，抓包看。”用户说“网站打不开”，ping 也通、DNS 也对，猜半天没头绪，一抓包：三次握手卡在第二步，SYN, ACK 没回来——防火墙规则把回程包吃了。还有一次更典型：网页时好时坏，抓包一看满屏 TCP 重传（Retransmission），最后查到是网线接触不良，包丢了一小半。Wireshark 不会告诉你“问题是什么”，它只会把真相摊在你面前——看包的时候，先看有没有握手、再看有没有重传、最后看应用层回了什么，这三步能解决八成网络问题。

动手做

1. 在两台虚拟机之间互相 ping，过滤 icmp，数一数一次 ping 对应几个包，点开一个看：Echo 请求和 Echo 回复的源地址、目标地址是怎么互换的。
2. 在一台虚拟机上搭个最简单的网页服务（比如 python3 -m http.server 8000），另一台虚拟机用浏览器访问它，过滤 tcp.port == 8000，把三次握手的三个包找出来，逐个点开看 Flags 和序号。
3. 过滤 dns，在虚拟机里跑 nslookup example.org，找到一问一答两个包，对一下 Transaction ID 是不是同一个，答案里的 IP 和 nslookup 输出的对不对得上。
4. 把抓到的包存成一个 .pcapng 文件，下次排错直接打开接着看——抓包文件就是网络现场的“录像”。

避坑

只抓自己的虚拟机流量，绝不抓别人的网络、绝不在真实网络上练手；选错网卡抓到的全是噪音，开始抓之前先确认网卡选对了；不设过滤就直接看包，等于在瀑布里找一滴水，先过滤再细看；ping 不通别先怪 Wireshark，先看是不是防火墙把 ICMP 挡了；抓包文件里可能有密码、会话信息，别随手发给别人，自己的实验流量也要当敏感数据对待。

会抓包，网络就从“黑盒”变成了“透明盒”：第 5 章的握手、第 7 章的 DNS、第 10 章的端口，全都能亲眼验证。下一章把实验台再搭大一点：用两台虚拟机搭一个真正的局域网。而抓包这门手艺不会只用一次——到了第 16 章排错，Wireshark 就是最后的“真相机器”：命令都查不出问题的时候，抓包看。

本课小结
  • Wireshark 只抓自己的虚拟机流量，界面分三栏：包列表、包详情、原始字节。
  • 先过滤再细看：icmp、tcp.port、dns、ip.addr 是最常用的四个过滤器。
  • 三次握手是三个包：SYN、SYN, ACK、ACK，序号和确认号连起来就是 TCP 可靠的底子。
  • 一次 DNS 查询是一问一答两个包，靠 Transaction ID 配对，平时走 UDP 53 端口。
  • 只看到 SYN 没回包、满屏重传、收到 RST，各自指向不同的故障位置。
