模块三第 3 章：IP、子网与路由

计算机网络2026-11-25 · 模块三

上一章留了个问题：MAC 地址只在同一个局域网里管用，出了这个网就失效了。可你每天打开的网站都在另一个城市、另一个国家——数据包是怎么跨过一个又一个网络、找到那台服务器的？答案在网络层：IP 地址给每台联网的设备一个全球可寻址的“门牌号”，路由器一跳一跳地把包往目标送。这一章讲的就是这套寻路系统：地址怎么编、包怎么走、走错了怎么办。

IP 地址：网络里的门牌号

IPv4 地址是 32 位，写成 4 组十进制数字，比如 192.168.1.10。它和 MAC 地址的区别再强调一次：MAC 地址是“你是谁”，跟着网卡走；IP 地址是“你在哪”，换个网络就换一个。正因为 IP 地址带位置信息，路由器才能拿它寻路——看到目标地址，就知道大概往哪个方向送。

地址分两段：网络号 + 主机号。网络号是“你住哪个小区”，主机号是“你是小区里第几户”。同一个网络里的设备网络号相同，主机号不同。怎么分？靠子网掩码——下一节讲。还有一类特殊地址要认出来：192.168.x.x、10.x.x.x、172.16.x.x–172.31.x.x 是私有地址，只在局域网里用，出不了互联网；127.0.0.1 是本机回环地址，指自己；169.254.x.x 是没拿到地址时系统自己编的临时地址——在 ipconfig 里看到它，就说明 DHCP 没配上，见第 6 课。

子网掩码与网关：怎么判断“在不在同一个网”

子网掩码就是用来划出“网络号到哪结束”的尺子。比如掩码 255.255.255.0 的意思是前 24 位是网络号，后 8 位是主机号。你的电脑要发包时，先拿自己的 IP 和掩码算出自己的网络号，再拿目标 IP 和掩码算出目标的网络号：一样，就在同一个网，直接发（靠 MAC 地址找对方）；不一样，就在别的网，交给默认网关——网关就是这个网通往外面的“大门”，一般是路由器的地址，比如 192.168.1.1。

什么时候会出问题？网关配错了（比如写成了 192.168.1.2，而路由器其实是 .1），包就出不去——ping 网关会报“无法访问目标主机”；掩码配错了，电脑会把“在别的网”的目标误判成“在同一个网”，直接发 ARP 问全网，没人应答，包就死在本地。这两类错在 第 6 课的排错链里都能对上号：ping 网关不通，先看 ipconfig 里的网关和掩码对不对。

路由表：每台设备心里的“路牌”

路由器和你的电脑心里都有一张路由表：每一行写着“去这个网段，往这个方向走”。表里的每一行有三样东西：目标网段、下一跳（下一个路由器的地址）、出接口（从哪个口出去）。电脑发包时查自己的路由表：目标在同一个网，走直连那一行；目标在别的网，走默认路由那一行（目标 0.0.0.0/0，意思是“所有不知道去哪的包都走这里”），下一跳就是默认网关。

路由表是动态的还是静态的？小网络里可以手写静态路由；大网络里路由器之间互相交换路由信息，自动学出最优路径——这就是路由协议干的事，第 4 章会讲 OSPF 和 BGP。先记住结论：路由表决定了包往哪走，表错了，包就走错路，甚至原地打转。

数据包怎么一跳一跳找到路

把上面的图走一遍：电脑 A 要访问服务器 B（203.0.113.50）。A 先算：目标和自己不在同一个网，于是把包交给默认网关 192.168.1.1——链路层上，这个包的帧是发给路由器的 MAC 地址的。路由器收到，拆开帧，看 IP 头里的目标地址，查自己的路由表，决定下一跳是哪个路由器，从哪个口发出去——同时把帧头换掉：源 MAC 换成自己的，目标 MAC 换成下一跳的。就这样一跳一跳，每一跳都只做两件事：查表、换帧头往下送，直到某个路由器发现“目标就在我直连的网里”，直接把包交给 B。

两个细节决定了这套系统能不出大乱子：第一，IP 地址从头到尾不变，变的是每一跳的帧头（MAC 地址）——所以 IP 层是端到端的，链路层是逐跳的；第二，TTL（生存时间）：IP 头里有个数字，每过一个路由器减 1，减到 0 包就被丢掉。没有 TTL，一个配错的路由环路会让包永远在几个路由器之间转圈，转到天荒地老。排错时 ping 显示的 TTL 值也能告诉你大概经过了几跳。

出错意味着什么：包死在哪一跳

ping 不通，先分清包死在哪一跳：ping 网关通、ping 外网 IP 不通，问题在路由器往外那一段；ping 外网 IP 通、ping 域名不通，问题在 DNS，不在路上（第 6 课的排错链就是这个逻辑）。tracert（Windows）或 traceroute（Linux）能把每一跳都列出来：哪一跳开始超时，问题就出在那一跳附近。还有一种常见死法：路由环路——两个路由器互相指着对方当下一跳，包在它们之间来回转，直到 TTL 耗尽被丢掉，表现就是 ping 超时、tracert 里同一段地址反复出现。

老师经验：网卡收到数据要靠中断通知 CPU 来处理，模块一第 5 章讲过中断和 DMA——网卡收到包就发中断，CPU 停下手头的事来收包。正常上网时这没什么感觉，但有一次客户的电脑一联网就卡死，CPU 占用率 100%，查下来是网卡驱动有问题，每秒发几万个中断，CPU 光处理中断就忙不过来了。换个驱动立刻好了。所以“网卡”和“CPU”不是两回事：网络层面的风暴（比如广播风暴、SYN 泛洪）最终都会变成 CPU 和内存的压力。做安全防护时别只盯着“包能不能进来”，还要看“进来的包会让机器付出多大代价”——这就是为什么防火墙要放在流量前面，先挡掉再说。

动手做

1. 在自己的电脑上跑 ping 192.168.1.1（把地址换成你自己的网关，见 ipconfig 里的“默认网关”）：通了，说明你到网关这一跳是好的；再跑 ping 8.8.8.8：通了，说明你到外网的路是通的；两个结果一对比，就知道问题在哪一段。
2. 在虚拟机里跑 tracert example.org（Windows）或 traceroute example.org（Linux），数一数到 example.org 一共经过了几跳，把每一跳的地址和延迟记下来。
3. 在虚拟机里看路由表：Windows 跑 route print，Linux 跑 ip route，找到目标 0.0.0.0 的那一行——那就是你的默认路由，下一跳就是你的默认网关。

避坑

别把 IP 地址当成设备的“身份证”：IP 会变，换个网就换一个，真正跟着硬件走的是 MAC 地址；网关配错一个数字，包就出不去——排错先看 ipconfig 里的网关对不对；别以为 ping 通了就万事大吉：ping 通只说明 ICMP 能走，网站的端口可能还被防火墙挡着；私有地址（192.168.x.x、10.x.x.x）出不了互联网，别拿它当公网地址去访问别人；TTL 不是“时间”，是“跳数”，减到 0 包就被丢掉，路由环路就靠它兜底。

这一章的 IP 地址和掩码只是入门——192.168.1.0/24 这样一个网段，怎么切成几个更小的网段、每个网段能装多少台电脑？这就是下一章的活：第 4 章：子网划分实战与路由协议。回头看模块一第 5 章的中断和 DMA：网卡收到包是怎么通知 CPU 的，理解了那一章，这一章的“包到了”才算落了地。

本课小结
  • IP 地址是网络里的门牌号，带位置信息，所以路由器能拿它寻路；MAC 地址是网卡的出厂身份，只在局域网里有效。
  • 子网掩码划出网络号和主机号，目标和自己不在同一个网，包就交给默认网关。
  • 路由表决定包往哪走：每行写着目标网段、下一跳和出接口，默认路由是“不知道去哪的包都走这里”。
  • 包一跳一跳往目标送：每一跳只查表、换帧头，IP 地址从头到尾不变，TTL 每跳减 1 防死循环。
  • 排错先分清包死在哪一跳：ping 网关、ping 外网 IP、ping 域名，三步定位到具体一段。
