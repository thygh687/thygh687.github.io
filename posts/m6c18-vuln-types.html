模块六第 18 章：漏洞类型深入：溢出、竞态、注入与供应链

网络安全基础2026-11-25 · 模块六

第 8 章讲过漏洞是怎么编号（CVE）和打分（CVSS）的，但那只是“户口本”：知道一个漏洞叫什么名字、多少分，还不够。真正要会的是：一看到“缓冲区溢出”“竞态条件”“注入”这些词，脑子里能立刻浮现出它是怎么发生的、长什么样、该怎么防。这一章把最常见的六类漏洞按机理拆开，每类讲清楚“程序员哪里写错了、攻击者怎么利用、现实里出过什么事”。只讲公开信息，不讲利用细节——我们的目标是看懂和防御，不是学会攻击。

先建立一个总框架：漏洞几乎总是三件事之一出了问题——边界没守住（多写了、越界了）、顺序没排好（两件事抢着发生）、信任没分清（把不可信的输入当成了指令）。溢出是第一类，竞态是第二类，注入是第三类，配置错误和供应链问题则是“人和管理”层面的漏洞。零日是时间维度的概念：漏洞存在，但还没人公开、还没补丁。

缓冲区溢出：写多了，写到别人家去了

程序在内存里给每块数据划一块“缓冲区”，好比给每个住户分一间房。缓冲区溢出就是：程序往一间房里塞的东西超过了房间大小，多出来的部分溢到了隔壁房间——而隔壁住的可能是程序下一步要执行的指令地址。攻击者精心构造超长输入，溢出的部分正好覆盖掉“返回地址”，让程序执行完当前函数后，不回原来的地方，而是跳到攻击者指定的代码上去。1988 年的莫里斯蠕虫（Morris Worm）就利用了这类问题，是互联网历史上第一次大规模蠕虫事件；后来无数次远程代码执行漏洞，根子上都是这一个机理。

怎么防：写代码时永远检查长度（不用不检查长度的危险函数）、用现代语言的内存安全机制；编译时开栈保护（Canary）、数据执行保护（DEP，让数据区不可执行）、地址随机化（ASLR，让攻击者猜不到代码在哪）。这三样是第 13 章安全基线里“系统加固”的一部分。防溢出的核心思想和第 17 章的 Biba 模型是通的：不可信的输入必须先过检查、限长度，才能进系统。

竞态条件：两件事抢着发生，中间那一瞬间就是漏洞

竞态条件（Race Condition）发生在“检查”和“使用”之间有一段时间差的时候。经典模式叫 TOCTOU（Time Of Check, Time Of Use，检查时与使用时）：程序先检查“这个文件是安全的吗？”——是；然后过了一小会儿才真正去用它——就在这一小会儿里，攻击者把文件换成了恶意的。检查的结果是真的，但用的时候东西已经不是检查过的那个了。

例子：一个有特权的安装程序，检查某个临时文件的所有者是不是当前用户，检查通过后才去读取它。攻击者在检查通过的瞬间把这个临时文件换成一个指向系统密码文件的符号链接，安装程序读到的就变成了系统文件。现实里这类问题常出现在文件操作、权限检查、银行转账的并发处理上：两个请求同时扣同一笔钱，如果没有锁，余额可能只扣了一次。防御的办法是：检查和使用之间不要留空隙（用原子操作、加锁），或者干脆“用的时候再检查一次”。

注入：把数据当成命令来执行

注入是第 17 章 Biba 模型被打破最直观的样子：程序把用户输入的“数据”当成了“指令”来执行。三兄弟长得不一样，根子是一个：

SQL 注入：网站把用户在搜索框里输入的内容直接拼进数据库查询语句。用户输入的不是“张三”，而是一段 SQL 代码，数据库照单执行，就能绕过登录、拖走整张表。公开案例很多：早年间不少网站的登录框输入 ' OR '1'='1 就能以管理员身份登录，就是因为查询语句被拼接改写了。防御：参数化查询（预编译），永远不把用户输入拼进 SQL 语句。

跨站脚本（XSS）：攻击者把一段 JavaScript 塞进网页的评论区、留言板，其他用户打开页面时，这段脚本在他们的浏览器里执行，能偷 Cookie、冒充身份。预备课第 12 课讲钓鱼时提过“别乱点链接”，XSS 是更进一步：你什么都没点，只是打开了一个正常页面，里面的恶意脚本就跑起来了。防御：输出时转义（把 < > 这类字符转成文本显示，不当代码执行）、内容安全策略（CSP）。

命令注入：程序把用户输入拼进操作系统命令去执行。比如一个“ping 一下这个地址”的小工具，把用户填的地址直接拼进 ping 命令，用户填的却是“地址 + 删除文件的命令”，系统就照做了。防御：不用 shell 拼接命令，用安全的 API 调用，并对输入做白名单校验。

配置错误：不是代码错了，是摆错了

很多泄露事件里代码一点问题没有，错的是配置：云存储桶设成了公开可读、数据库端口直接暴露在公网、管理后台用了默认密码、调试接口忘关。公开报道里反复出现的“某公司几亿条数据在网上裸奔”，十有八九是配置错误。这一类漏洞的特点是：发现它不需要高深技术，只需要有人去检查清单。这正是第 13 章安全基线和第 14 章动手安全检查存在的意义：上线前按清单一项项核对，默认密码改了没有、不必要的端口关了没有、存储权限是不是最小的。

供应链攻击：你用的东西里藏着东西

现代软件没有人是从零写起的：一个程序依赖几十上百个开源库、构建工具、第三方组件。供应链攻击就是攻击这些“上游”：往一个流行的开源包里投毒、篡改软件的安装包、攻破开发者的构建服务器，让恶意代码随着正常的更新、分发流进成千上万台电脑。2020 年公开报道的 SolarWinds 事件就是典型：攻击者污染了这家公司的软件更新，受影响的客户装上“官方更新”就等于装上了后门。防御：只从官方渠道拿软件并校验签名和哈希、锁定依赖版本、关注上游组件的安全公告、关键软件做来源审查。这和第 16 章“安全新闻与漏洞情报怎么跟”是直接接上的：供应链风险很多时候是靠情报先发现的。

零日漏洞：还没公开、还没补丁的漏洞

“零日”（Zero-day）不是一种漏洞类型，而是一个时间状态：漏洞已经被发现（可能被攻击者发现了），但厂商还没发布补丁、公众还不知道，防御方是“零天”准备时间。零日之所以可怕，不是因为它技术上更难，而是因为所有常规防御——打补丁、按已知特征拦截——都对它暂时无效。应对零日的办法不是“等补丁”，而是纵深防御：行为检测、最小权限、网络分段，让一个未知漏洞就算被利用，也走不远、拿不到关键东西。这正是第 17 章纵深防御存在的理由：任何一层都可能被零日打穿，但所有层同时被打穿要难得多。

老师经验：我处理过的真实事件里，注入和配置错误占了绝大多数，缓冲区溢出反而少——因为现代系统默认开了栈保护、DEP、ASLR，纯溢出越来越难成事。但有一次，一个客户的网站被拖库，查到最后不是什么高级漏洞，是开发图方便把用户输入直接拼进 SQL，五年都没人改。还有一次，云存储桶公开，客户第一反应是“我们被黑客攻击了”，其实是当初搭环境的人随手点了“公开”，之后三年没人复查。记住这个比例：现场最常见的漏洞不是最难的那种，而是最“懒”的那几种——没检查长度、没做转义、配置随手一点。做防御，先把这些懒出来的洞堵上，收益最大。

动手做

1. 只在虚拟机里：写一段有意的坏代码（比如 C 语言里用一个 8 字节的数组接收 32 字节输入，或 Python 里把用户输入直接拼进一条假想的 SQL 字符串打印出来），亲眼看到它怎么越界、怎么改写查询；然后改成安全写法（检查长度、参数化拼接），对比两次输出。
2. 在虚拟机里打开一个本地的文本文件，用符号链接做一次 TOCTOU 思想实验：先写个脚本检查“文件 A 存在且属于我”，在检查和读取之间手动把 A 换成指向另一个文件的链接，看看脚本读到的是什么——体会“检查时”和“使用时”之间的空隙。
3. 打开 OWASP Top 10 的公开页面（只读公开资料），把注入、配置错误、供应链这三类在榜单上的位置记下来，对照本章的机理，写一句话说明每一类为什么上榜。
4. 在虚拟机里给自己做一张“配置检查清单”：列出你虚拟机上五个最容易配错的地方（默认密码、开放端口、共享文件夹权限、自动登录、远程桌面），逐项核对并记下结果——这张清单就是第 23 章结课实战报告里要用的那张。

避坑

别把“零日”当成一种漏洞类型：它是“还没补丁”的时间状态，任何类型的漏洞都可以是零日；别以为“我的程序小，没人盯”：自动化扫描不挑目标，配置错误和注入是机器批量扫出来的；别在真实网站上“试一试”注入：往别人的登录框、搜索框里填注入语句是攻击行为，只能在自己的虚拟机、自己的实验代码里做；别只防代码、不防配置：公开泄露事件里配置错误的占比一点不比代码漏洞低；别把防御押在一种技术上：防溢出要长度检查加编译器保护加系统缓解措施一起上，单靠任何一样都兜不住。

漏洞分了类，下一站是看攻击者最爱用的通道之一——邮箱：第 19 章讲 SPF、DKIM、DMARC 怎么给邮件验明正身，以及商务邮件诈骗是怎么绕过人的防线的。回头看第 8 章的 CVE 与 CVSS：从现在起，读到任何一份 CVE 公告，先问一句——它属于本章六类里的哪一类？机理是什么？这个习惯，会让你读漏洞情报的速度快一倍。

本课小结
  • 缓冲区溢出是写超了边界，溢出的部分盖掉返回地址，让程序跳到攻击者的代码上；防法是长度检查加栈保护、DEP、ASLR。
  • 竞态条件是“检查”和“使用”之间的时间差被利用，经典模式是 TOCTOU；防法是原子操作和加锁。
  • 注入是把不可信输入当成指令执行：SQL 注入、XSS、命令注入根子相同，防法是参数化查询、输出转义、不用 shell 拼接。
  • 配置错误和供应链攻击不靠高深技术：前者是摆错了，后者是上游被污染，都要靠清单和来源审查来防。
  • 零日是“还没补丁”的时间状态，对付它靠纵深防御，而不是等补丁。
