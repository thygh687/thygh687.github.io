模块三第 16 章：网络故障排查方法

计算机网络2026-11-25 · 模块三

网络出问题的时候，最怕的不是问题本身，是不知道从哪开始查。瞎试一通，重启路由器、重装驱动、换根网线全来一遍，问题可能好了，也可能只是碰巧——下次再出，还得从头瞎试。这一章给一套固定的方法：一条排错链加一张排查清单，走到哪一步断了，问题就在哪一段。

排错链：五步，哪一步断了问题就在哪一段

沿用第 6 课的三条命令，展开成五步。顺序不能乱：每一步通了再往下一步走，断在哪一步，就只查那一段，别去动别的：

第 1 步断了（ipconfig 看不到地址，或者地址是 169.254 开头）：本机根本没拿到地址。先看网线插紧了没有、Wi-Fi 连上没有，再看 DHCP 服务是不是正常——重启路由器是最常见的有效操作，因为它同时重启了 DHCP。

第 2 步断了（ping 网关不通）：包连家门都出不去。网线、Wi-Fi、网卡驱动、网关地址配错，都在这个范围。先 ping 127.0.0.1：如果连自己都 ping 不通，问题在网卡或协议栈本身；自己通、网关不通，再看线缆和网关地址。

第 3 步断了（ping 8.8.8.8 不通，但网关通）：家里通、外面不通。问题在路由器到外网那一段：宽带断了、路由器拨号失败、运营商线路故障。看一眼路由器上的指示灯（los 灯红了就是光纤断了），再打电话问运营商之前，先确认邻居家是不是也断了。

第 4、5 步断了（ping IP 通、ping 域名不通，或者 nslookup 查不到）：路是通的，名字解析坏了。见下一节。

往深讲：五种常见故障各长什么样

DNS 问题。症状最有迷惑性：QQ、微信能用，网页打不开——因为聊天软件直接连 IP，不走域名。判断方法：ping 8.8.8.8 通，ping example.org 报“找不到主机”，nslookup 也查不到。处理：换一个 DNS 服务器试试（比如把 DNS 改成 8.8.8.8），再查是不是本地 DNS 缓存脏了（ipconfig /flushdns 清掉重查）。

网关问题。网关地址配错、网关设备挂了，症状是“全网都不通，但本机看着一切正常”。ipconfig 里看默认网关那一行：是 0.0.0.0 就是没配网关；地址对但 ping 不通，就是网关设备本身的问题。虚拟机实验里最常见的网关问题是：仅主机模式本来就没有网关，却有人硬给它配了一个。

防火墙挡包。最容易误判的一类：路全通，某个服务就是连不上。ping 通不等于服务通——防火墙可以放行 ICMP、挡住 TCP 80 端口，这时候 ping 看着好好的，网页就是打不开。判断方法：换端口试、临时放行规则试，或者直接看防火墙日志。第 14 章的抓包在这里最管用：只看到 SYN、没看到 SYN, ACK 回来，八成就是中间有防火墙把包吃了。

MTU 问题。MTU 是链路上一个包最大能有多大，常见值是 1500。症状很怪：小网站能开，大文件、带图片的页面打不开——小包能过，大包在某个环节被丢了。判断方法：ping -f -l 1472 example.org（Windows）或 ping -M do -s 1472 example.org（Linux），从大到小试，看多大的包开始丢。VPN 和 PPPoE 拨号最容易出 MTU 问题，因为隧道头占了包里的空间。

线缆和网卡问题。最底层、最容易被忽略。症状是“时好时坏”：ping 的延迟忽高忽低、丢包率一会儿 0% 一会儿 30%、网速一会儿正常一会儿掉到底。判断方法：换一根网线、换一个网口、换一块网卡，一个一个排除。抓包看到满屏 TCP 重传，十有八九就是物理层在丢包——包不是被挡了，是在路上碎了。

老师经验：远程修电脑，客户说的“上不了网”十次有八次不是一句话能定位的，我的办法永远是先让他把 ipconfig 和 ping 网关的结果念给我听——三分钟，问题在哪一段就清楚了，剩下的才是具体修。还有一条现场教训：一次客户说“网页打不开”，我让他重装浏览器、清缓存折腾了一小时，最后抓包一看：DNS 被劫持到了一个假地址，ping 域名解析出的 IP 根本不是网站的。从那以后我排错多了一条铁律：先看 nslookup 返回的 IP 对不对，再怀疑浏览器。排错不是比谁懂的命令多，是比谁先找到“断在哪一段”。

动手做

1. 在自己的电脑上把五步排错链完整跑一遍，把每一步的结果记下来——正常时候的结果，就是以后出问题时的对照组。
2. 在虚拟机实验里故意制造一次故障：把虚拟机 B 的 IP 改到另一个网段，再从 A ping 它，看第几步断了、报错长什么样；改回来，再故意把 B 的防火墙打开挡住 ICMP，看 ping 和实际连通性怎么不一样。
3. 在虚拟机里把 DNS 改成一个不存在的地址，再 ping example.org，看报错怎么变；改回来，用 ipconfig /flushdns 清一次缓存，再查一次。

避坑

排错不按顺序、东一榔头西一棒子，修好了也不知道为什么好；ping 不通别先下结论，先看报错长什么样——超时、不可达、找不到主机是三种不同的问题；ping 通不等于服务通，防火墙可以放行 ping、挡住业务端口；别一出问题就重装系统、重装驱动，先定位到段再动手；MTU 和物理层丢包最容易被误判成“网速慢”，大包和小包的表现不一样时，先怀疑它们。

排错链是模块三的收尾技能：从第 6 课的三条命令出发，经过第 14 章的抓包验证，到这一章的完整方法，网络从“会用”变成了“会修”。下一站是第 18 章综合实战：给一个小网络做完整的安全体检——到时候排错链和抓包都会再上场，只不过问题从“网不通”变成了“网安不安全”。

本课小结
  • 排错按五步链走：ipconfig → ping 网关 → ping 8.8.8.8 → ping 域名 → nslookup，哪一步断了问题就在哪一段。
  • ping IP 通、ping 域名不通是 DNS 问题；聊天软件能用、网页打不开也是 DNS 问题的典型信号。
  • ping 通不等于服务通，防火墙可以放行 ICMP、挡住业务端口，抓包看握手最可靠。
  • 小包通、大包不通先查 MTU；时好时坏、丢包忽高忽低先查线缆和网卡。
  • 正常时的排错结果要记下来，它就是以后出问题时的对照组。
