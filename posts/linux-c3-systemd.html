Linux 管理专项第 3 章：systemd 服务深入

Linux 管理专项2026-11-25 · Linux 管理专项

电脑开机后，谁负责把一个个服务拉起来？现代 Linux 的答案是 systemd：它是系统的第一个进程（PID 1），也是服务管理器、日志管理器、定时任务管理器——很多活儿都归它管。

systemd 是现在最主流的 init 系统，Ubuntu、Debian、RHEL、Fedora 都在用。学会 systemctl、journalctl 这两个命令，就等于学会了 Linux 服务管理的一大半。这一章讲 systemd 的核心概念：单元、服务管理、排障、定时器。

先说一句：systemd 争议不少，老派用户更喜欢简单的 SysVinit。但对初学者来说，先学会主流的 systemd，再去了解别的，才是省时间的路。

PID 1 与单元：systemd 的基本概念

开机时内核启动的第一个用户态进程就是 systemd，PID 是 1。之后所有的进程，都是 systemd 的子孙（直接或间接）。systemd 用“单元（Unit）”来管理一切：服务是 service 单元，挂载点是 mount 单元，设备是 device 单元，定时任务是 timer 单元，目标状态是 target 单元。

服务的配置文件叫单元文件（unit file），放在 /lib/systemd/system/（系统自带的）和 /etc/systemd/system/（管理员自己写的、覆盖系统默认的）。一个服务单元文件里写着：服务叫什么、用什么命令启动、依赖哪些服务、崩了要不要重启、以哪个用户身份跑。

目标（target）是“一组服务的状态”：比如 multi-user.target 是多用户命令行状态，graphical.target 是图形界面状态。开机进哪个目标，决定了拉起哪些服务。

systemctl：服务的开关与状态

管理服务用 systemctl：systemctl status 服务名看状态，systemctl start/stop/restart 服务名是启动、停止、重启，systemctl enable/disable 服务名是设开机自启、不自启，systemctl is-enabled 服务名看自启状态。注意 start 和 enable 是两回事：start 是现在就跑，enable 是下次开机自动跑。

看所有服务的状态：systemctl list-units --type=service --state=running 列出正在跑的服务，systemctl list-unit-files --type=service 看所有服务的自启设置。排障时先跑 systemctl status，再看它说“失败”还是“正在运行”。

改完单元文件要跑 systemctl daemon-reload，让 systemd 重新读配置，再重启服务。忘了 daemon-reload 就重启服务，改的是旧配置——这是新手最常见的 systemd 排障坑。

服务出问题怎么查

服务起不来，先看三处：第一，systemctl status 服务名，看它最后几行报错；第二，journalctl -u 服务名，看这个服务的全部日志（第 6 章细讲 journalctl）；第三，服务依赖的服务是不是也挂了——单元文件里的 After= 和 Requires= 写着依赖关系。

常见故障有：端口被占了（另一个程序已经在用这个端口）、配置文件写错了（改配置前先备份、改完先检查语法）、权限不对（服务用的账号读不到文件）、依赖的服务没起来。按这个清单逐项排查，比漫无目的地重装快得多。

服务崩了自动重启，是 systemd 的一个重要功能：单元文件里 Restart=always 就是“崩了就重启”，Restart=on-failure 是“失败了才重启”。但自动重启不是万能的：如果配置错了，重启一百次还是失败——先修配置，再谈重启策略。

定时器：systemd 的定时任务

systemd 的 timer 单元是新一代的定时任务，可以替代传统的 cron（当然 cron 也还在用）。定时器的好处是：能精确控制“开机后多久跑”“错过时间要不要补跑”，日志直接进 journald，方便查。

一个定时器配一个服务：timer 决定什么时候跑，service 决定跑什么。比如每天凌晨备份的任务，就是 backup.timer + backup.service 两个文件。查看所有定时器用 systemctl list-timers，看看下次运行时间、过去运行结果。

初学者不必马上把 cron 全换成定时器，先学会看、学会查：系统自带的定时器（比如日志轮转、软件源更新）长什么样，再决定自己的任务用哪种方式。

本章检查清单

□ systemd 是 PID 1，用单元管理服务、定时器、挂载点和目标状态。

□ systemctl 管服务的开关与自启：start 是现在跑，enable 是开机自启。

□ 服务出问题先看 systemctl status，再看 journalctl -u 服务名的日志。

□ 改完单元文件要先 systemctl daemon-reload，再重启服务验证。

老师经验：我排障时最常用的一句话就是“先看 systemctl status，再看 journalctl”。有一次 Web 服务起不来，status 只说 failed，journalctl 里写着“端口 80 已被占用”——原来是另一个测试服务没关，占着端口。我的经验是：systemd 的报错信息一般都写得很清楚，问题是你有没有去看。还有，改单元文件一定要先备份原文件，改完跑 daemon-reload，再重启验证——我见过太多人改完配置直接重启服务器，结果服务起不来，才发现是配置写错了一个字母。

动手做

1. 只在你自己的 Linux 虚拟机里：运行 systemctl status ssh 或 systemctl status sshd，看看 SSH 服务的状态；再运行 systemctl list-timers，看看系统里有哪些定时器、下次什么时候跑。
2. 在虚拟机里练习服务的开关：sudo systemctl status cron，再 sudo systemctl stop cron，等几秒再 sudo systemctl start cron，观察状态变化；练完确认 cron 回到运行状态。
3. 在虚拟机里看一个单元文件：cat /lib/systemd/system/cron.service（或 sshd.service），找出 ExecStart、After、Restart 这几行，说出这个服务是用什么命令启动的、依赖谁、崩了会不会重启。

避坑

别在生产系统、别人的服务器上练 systemctl stop/start：动手只在你自己的虚拟机里做；start 和 enable 别搞混：start 是现在跑，enable 是开机自启，两个都要设才算“现在跑、以后也跑”；改完单元文件别忘了 systemctl daemon-reload，否则改的是旧配置；服务崩了先看日志、修配置，别只会反复重启——配置错了重启一百次也没用。

systemd 是现代 Linux 的服务总管：PID 1、单元、systemctl、journalctl，四个概念就够上手。下一章我们给远程登录上锁：第 4 章 SSH 加固——远程登录怎么才安全，密钥、端口、Fail2ban 全套讲清楚。
