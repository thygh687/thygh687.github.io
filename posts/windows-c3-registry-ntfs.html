Windows 专项第 3 章：注册表与 NTFS：配置单元、MFT 与备用数据流

Windows 专项2026-11-25 · Windows 专项

Windows 的配置存在哪？答案是注册表。一个程序开机自启、一个文件用什么打开、系统长什么样，几乎都写在注册表里。而文件本身，存在 NTFS 文件系统里。这一章把这两样东西放在一起讲，因为安全工作里它们总是一起出现：注册表是攻击者最爱留后门的地方，NTFS 是藏东西和找证据的地方。

先打个预防针：注册表改错一个值，系统就可能起不来。所以这一章的动手部分只做“看”和“备份”，不做“改”。看懂结构，比会改更重要——会看，你就能在排障时找到是谁改了什么；不会看，改一百次也是碰运气。

NTFS 这边要讲三个概念：MFT（主文件表）、备用数据流（ADS）和权限。MFT 是 NTFS 的账本，ADS 是文件背后可以贴的小纸条，权限决定谁能读、谁能改。第 9 章的 ACL 会在这里先打个照面。

注册表：五个根键，一张配置总表

注册表在逻辑上是五个根键：HKEY_LOCAL_MACHINE（HKLM，本机配置，硬件、驱动、服务都在这里）、HKEY_CURRENT_USER（HKCU，当前登录用户的配置）、HKEY_USERS（所有用户的配置）、HKEY_CLASSES_ROOT（文件关联和 COM 组件）、HKEY_CURRENT_CONFIG（当前硬件配置）。

物理上，注册表存在几个叫“配置单元”（Hive）的文件里：SYSTEM、SOFTWARE、SAM、SECURITY、DEFAULT，放在 C:\Windows\System32\config\ 下；每个用户的配置存在用户目录下的 NTUSER.DAT 里。理解“逻辑上是一棵树，物理上是几个文件”这个对应关系，取证时很有用：关机状态下也能把这些文件拷出来分析。

注册表里的值有类型：字符串（REG_SZ）、可扩展字符串（REG_EXPAND_SZ）、二进制（REG_BINARY）、DWORD（32 位数字）、多字符串（REG_MULTI_SZ）。排障时最常见的操作是看 DWORD 开关：比如某个功能开还是关，往往就是一个 0 或 1。

开机自启藏在哪：排障必查的几个位置

程序想开机自启，最常用的注册表位置有：HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run、HKCU\Software\Microsoft\Windows\CurrentVersion\Run、RunOnce，以及服务（第 4 章）和任务计划（第 4 章）。除此之外还有启动文件夹、Winlogon 的 Shell 值、IFEO（映像劫持）等冷门位置。

安全工作的基本功，就是会列出“这台机器上所有能让程序自动跑起来的地方”，再逐个问：这个程序是谁？谁把它放这的？不认识的，就要查。Sysinternals 的 Autoruns 工具（第 7 章）干的就是这件事：一张表列出全部自启项，带签名验证。

还要知道：注册表不是唯一藏自启的地方。恶意软件也会用计划任务、服务、浏览器扩展、WMI 事件订阅来持久化。只查注册表 Run 键就宣布“干净了”，是新手最常见的误判。

NTFS 与 MFT：文件的账本

NTFS 是 Windows 的主流文件系统。它的核心是一张叫 MFT（主文件表，Master File Table） 的账本：磁盘上的每个文件和目录，在 MFT 里都有一条记录，写着文件名、时间戳（创建、修改、访问）、大小、权限、数据存在磁盘的哪些扇区。文件删了，MFT 里的记录只是被标记为“空闲”，数据往往还在——这就是数据恢复和取证能找回“已删除文件”的原理。

MFT 记录里的时间戳是取证的金矿：一个文件什么时候创建、什么时候被改过，都写在里面。但也要注意，时间戳是可以被伪造的（timestomping），不能只凭时间戳下结论，要和日志、注册表时间交叉验证。

NTFS 还支持日志（Journal）：文件系统的每次改动先记日志再落盘，断电后能靠日志恢复一致性。取证里还有一个 $LogFile 和 $UsnJrnl（更新序列号日志），记录了文件最近的增删改——第 8 章查日志时还会遇到它们。

备用数据流 ADS：文件背后的小纸条

备用数据流（ADS，Alternate Data Stream）是 NTFS 的一个特性：一个文件除了主数据，还可以挂上额外的数据流，平时在资源管理器里看不见。比如记事本 test.txt 可以挂一个 test.txt:secret.txt，里面藏一段文字，文件大小、图标看起来都正常。

ADS 最初的正经用途，是给从网上下载的文件打标记：浏览器下载的文件会挂一个 Zone.Identifier 流，写着“这个文件来自互联网”，Windows 打开它时就会弹安全提示。攻击者则反过来用 ADS 藏恶意代码、藏窃取的数据，因为普通用户和很多杀毒软件不会去翻 ADS。

查 ADS 的办法：PowerShell 里用 Get-Item -Stream * 看一个文件挂了哪些流；Sysinternals 的 streams 工具可以批量扫描一个目录。记住，ADS 本身不是病毒，它是一个功能；看到陌生的流，先问里面是什么，再下结论。

权限：谁能读，谁能改

NTFS 的每个文件和目录都有一个安全描述符，里面是 ACL（访问控制列表，第 9 章细讲）：谁可以读、谁可以写、谁可以执行。注册表的每个键也有类似的权限。权限配错了，要么是普通用户能改系统配置（提权漏洞），要么是程序读不到自己该读的文件（故障）。

两个实用知识点：第一，文件被复制到 FAT32 的 U 盘上，NTFS 权限就丢了——因为 FAT32 不支持 ACL；第二，管理员取得文件所有权（Take Ownership）后可以改任何权限，所以“只有管理员能改”不等于“改不了”，等于“改之前要先拿到管理员”。

本章检查清单

□ 注册表逻辑上是五个根键，物理上是 SYSTEM、SOFTWARE 等几个配置单元文件。

□ 开机自启常藏在 Run 键、服务、任务计划里，查持久化要查全套，不能只看一处。

□ MFT 是 NTFS 的账本，记录文件名、时间戳和数据位置；删文件只是把记录标为空闲。

□ 备用数据流 ADS 能把数据挂在文件背后，平时看不见，可用 PowerShell 的 -Stream 查看。

□ 改注册表前先导出备份；时间戳可以伪造，要和日志交叉验证。

老师经验：取证时我最常看的两样东西就是注册表和 MFT。有一回用户说“有个程序每天定时弹广告，杀毒查不到”，我翻 Run 键没发现，最后在计划任务和 WMI 里找到它——注册表只是持久化的其中一条路。另一回是 ADS：一个看起来只有 1KB 的 txt 文件，挂了 2MB 的数据流，里面是窃取的文档。教训是：查持久化要查全套（注册表、服务、任务计划、启动文件夹、WMI），查文件要看流、看 MFT 时间戳，别只看资源管理器里那点信息。另外，动注册表之前先导出备份，这条规矩我遵守了十年，一次都没后悔过。

动手做

1. 只在你自己的虚拟机里：按 Win+R 输入 regedit，先点 文件 → 导出，备份整个注册表（或至少备份 HKCU），存到桌面；然后展开 HKCU\Software\Microsoft\Windows\CurrentVersion\Run，看看有哪些开机自启项，把名字记下来。
2. 在虚拟机里打开 PowerShell，运行 Get-ItemProperty HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run，列出本机自启项；再新建一个测试文件，在 PowerShell 里用 Set-Content -Path .\test.txt -Stream secret -Value '藏起来的纸条' 写一条 ADS，再用 Get-Item -Stream * .\test.txt 查看它。
3. 在虚拟机里用 fsutil fsinfo ntfsinfo C: 看看 NTFS 信息；再打开一个文件的属性 → 安全页，看看有哪些用户和权限，试着说出“谁能读、谁能改”。

避坑

别在真实电脑上改注册表练手：改错一个键值可能导致系统无法启动，动手只在虚拟机里做；别乱删 Run 键里的东西：有些是显卡、声卡、输入法的正常自启，删了会出小毛病，先查清再动手；别把 ADS 当成病毒的代名词：下载文件的 Zone.Identifier 就是合法的 ADS，看到流先看内容；别只信 MFT 时间戳：时间戳可以伪造，要和日志交叉验证。

注册表是配置的总表，NTFS 是文件的账本，ADS 是账本边角能贴的小纸条——三样东西合起来，就是 Windows“状态”的大部分。下一章我们看是谁在后台默默干活：第 4 章讲服务与任务计划，Windows 里那些不用你管、却一直在跑的活儿。
