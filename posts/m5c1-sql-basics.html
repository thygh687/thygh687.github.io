模块五第 1 章：SQL 基础 —— 增删改查

数据库与密码学2026-11-25 · 模块五

学安全的人迟早要跟数据库打交道：网站的用户账号存在数据库里，日志存在数据库里，漏洞清单也存在数据库里。攻击者想偷数据，瞄准的常常就是数据库；防御者想查“谁在半夜三点登录了”，也要去数据库里问。问数据库用的语言叫 SQL（Structured Query Language，结构化查询语言）。这一章只讲最核心的四件事——增、删、改、查。会了这四件，你就能跟任何一个数据库对话了。

先建立一个直觉：数据库不是什么神秘的东西。你在第 2 课里见过文件和文件夹——数据散在一个个文件里，找起来要自己翻。而数据库是把数据放进一张张整齐的表里，再给一个“管理员”（数据库软件）帮你找、帮你改、帮你保证不出错。SQL 就是你跟这位管理员说话的方式。

表、行、列：数据的样子

一张表（table）就像一张电子表格。每一列（column）是一种属性，有固定的名字和类型；每一行（row）是一条记录，代表一个真实的东西。举个例子，一张“漏洞清单”表可以长这样：

记住三个词就够了：数据库里装着多张表，表由列（属性）和行（记录）组成。一个数据库可以有很多张表，比如一张存用户、一张存漏洞、一张存日志，表和表之间还能互相引用——那是第 3 章的事。

查：SELECT，最常用的语句

查数据用 SELECT，意思是“把符合条件的行给我看”。最简单的查法是把整张表都拿出来：

SELECT * FROM vulns;

逐词拆开：SELECT 是“查”，* 是“所有列”，FROM vulns 是“从 vulns 这张表里”，分号表示一句话说完了。结果就是上面那张表的全部三行。

但整张表全拿出来很少是你真正想要的。通常你只关心某几列、某几行。只看名称和严重程度两列：

SELECT name, severity FROM vulns;

只看“高”严重程度的行，就要加 WHERE（条件）：

SELECT * FROM vulns WHERE severity = '高';

WHERE 后面是条件，= 是“等于”。注意：文字要用单引号包起来，数字不用——WHERE id = 1 就不用引号。这个单引号，后面第 4 章会讲到它怎么变成安全漏洞的，先留个印象：单引号在 SQL 里有特殊含义。

条件还可以组合：WHERE severity = '高' AND status = '待修复'（两个都满足），WHERE severity = '高' OR severity = '中'（满足一个就行）。想按顺序看结果，用 ORDER BY：

SELECT * FROM vulns ORDER BY severity DESC;

ORDER BY severity 是按严重程度排序，DESC 是从大到小（降序），不写就是从小到大（ASC）。不过要注意：按文字“高/中/低”排序排出来的是字典顺序，不是你心里那个“高比中严重”的顺序——想按严重程度排，得用数字等级列，或者在设计表的时候就想好，这是第 3 章数据库设计要解决的问题。

增：INSERT，往表里加一行

INSERT INTO vulns (name, severity, status) VALUES ('过期证书', '中', '待修复');

INSERT INTO 是“插进”，括号里写列名，VALUES 后面写对应的值，一一对应。id 这一列没写——因为建表时会让它自动编号（自增），下一章建表时你会亲手设置它。

改：UPDATE，改掉已有的数据

UPDATE vulns SET status = '已修复' WHERE id = 1;

SET 后面写改成什么，WHERE 写改哪一行。这条语句只改 id 是 1 的那一行。UPDATE 的 WHERE 是整本章最重要的一行字——且看下一节。

删：DELETE，删掉一行

DELETE FROM vulns WHERE id = 3;

删掉 id 是 3 的那一行。同样，WHERE 决定删谁。

老师经验：刚入行的工程师最容易在 UPDATE 和 DELETE 上栽跟头，而且栽得一模一样：忘了写 WHERE。没有 WHERE 的 UPDATE vulns SET status = '已修复'; 会把全表每一行的状态都改成已修复；没有 WHERE 的 DELETE FROM vulns; 会清空整张表。真实生产环境里我见过有人一条语句清空了几十万行用户数据，恢复靠的是前一天的备份——那次之后，我们团队立了一条铁规矩：凡是在生产库上执行 UPDATE 或 DELETE，必须先用同样的 WHERE 跑一遍 SELECT，看返回的行数对不对，确认无误再执行；而且生产库的操作一律先备份。这一条规矩，值多少钱都换不来。

动手做

只在虚拟机里做（参考第 7 课搭好的虚拟机）。虚拟机里一般自带 SQLite，或者用 sqlite3 --version 确认一下；没有就装一个，方法在第 2 章。然后：
1. 在虚拟机里跑 sqlite3 practice.db，建一张练习表：CREATE TABLE vulns (id INTEGER PRIMARY KEY, name TEXT, severity TEXT, status TEXT);
2. 用 INSERT 插 5 条你自己编的漏洞记录（弱口令、未打补丁、开放端口、过期证书、默认账号，随便编）；
3. 用 SELECT + WHERE 查出所有“高”严重程度的记录，再用 ORDER BY 按 id 倒序看一遍；
4. 用 UPDATE 把其中一条的状态改成“已修复”，再用 SELECT 验证；
5. 故意不用 WHERE 做一次 SELECT（先看全表），体会 WHERE 是“圈范围”的意思——但 UPDATE/DELETE 绝不在没有 WHERE 的情况下练手，先 SELECT 确认行数是铁规矩。
做完这五步，增删改查就上手了。下一章会把这张练习表正式建成一个“漏洞清单”练习库。

避坑

UPDATE 和 DELETE 忘写 WHERE，等于对全表开火——执行前先用 SELECT 验证 WHERE 圈住的行；字符串用单引号，数字不用，引号错了语句会直接报错；SQL 关键字不区分大小写，但表名、列名在 Linux 的 MySQL 里区分大小写，养成统一小写的习惯；别在真实网站、真实公司的数据库上练手，SQL 语句一执行就生效，没有“撤销”按钮；备份不是可选项，删改之前先确认有备份——备份方法在第 2 章。

会了增删改查，你已经能跟数据库对话了。但“对话”之前得先有数据库、有表、有数据——第 2 章：动手：建一个数据库就干这件事。而“表该怎么设计才合理”，是第 3 章的主题；“SQL 怎么被人利用”，是第 4 章的主题。

本课小结
  • 数据库里是表，表由列（属性）和行（记录）组成；SQL 是跟数据库对话的语言。
  • 查用 SELECT：SELECT 列名 FROM 表名 WHERE 条件 ORDER BY 列名，* 代表所有列。
  • 增用 INSERT INTO … VALUES …，改用 UPDATE … SET … WHERE …，删用 DELETE FROM … WHERE …。
  • UPDATE 和 DELETE 的 WHERE 是生死线：没有 WHERE 就是对全表操作，执行前先用 SELECT 验证行数。
  • 字符串用单引号、数字不用；这个单引号后面会在第 4 章变成安全漏洞的主角。
