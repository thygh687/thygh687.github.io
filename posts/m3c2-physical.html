模块三第 2 章：物理层与数据链路层

计算机网络2026-11-25 · 模块三

上一章的地图里，最底下两层是最容易被忽略的——因为平时你看不见它们。可真出了问题，十次里倒有七次栽在这两层：网线松了、Wi-Fi 信号弱了、网卡驱动坏了。更重要的是，安全上最“原始”的攻击也都发生在这里：插进一根网线、伪造一个 MAC 地址，就能碰到整个局域网。这一章把最底下两层讲清楚：0 和 1 怎么变成信号跑出去，到了同一个网里又怎么找到正确的那台电脑。

物理层：0 和 1 怎么跑出去

物理层只干一件事：把 0 和 1 变成能在介质上传输的信号，再把收到的信号还原成 0 和 1。网线里是电信号（高电平是 1、低电平是 0），光纤里是光信号（有光是 1、没光是 0），Wi-Fi 是无线电波。物理层不管这些 0 和 1 是什么意思——它只负责“送到”，送到的东西对不对、给谁的，它一概不管。

常见的介质各有脾气：双绞线（家里和办公室最常见的网线）便宜、好布线，但距离短，一般不超过 100 米；光纤快、距离远、抗干扰，是楼与楼、机房之间的主力；Wi-Fi 方便、不用线，但信号会被墙、会被干扰，速度也不稳定。排错时先看物理层最实在的证据：网口的灯亮不亮？Wi-Fi 图标有没有感叹号？网线插紧了没有？灯不亮，先别怀疑软件。

MAC 地址：网卡的“身份证号”

每块网卡出厂时就烧进一个全球唯一的地址，叫 MAC 地址（媒体访问控制地址），48 位，写成 6 组十六进制，比如 AA:BB:CC:11:22:33。前 3 组是厂商编号（这块网卡是谁家造的），后 3 组是这块网卡自己的编号。它和 IP 地址的区别要记牢：MAC 地址是“你是谁”，出厂就定死了，跟着网卡走；IP 地址是“你在哪”，会变，换个网络就换一个。

什么时候用 MAC 地址？同一个局域网里，电脑之间互相找对方，靠的就是 MAC 地址。你 ping 同一网段的另一台电脑，底层先问一句“这个 IP 对应哪个 MAC 地址”（这就是 ARP，第 6 章会讲），问到了才把帧发出去。MAC 地址只在同一个网里有效——出了这个网，路由器一转发，链路层的帧头就被换掉了，MAC 地址也就换了人。

以太网与帧：数据在局域网里的“信封”

局域网里最常见的技术是以太网。它规定了数据在网线上传输的格式，叫“帧”：一个帧由目标 MAC 地址、源 MAC 地址、类型（里面装的是什么协议，比如 IP）、数据、帧校验序列（FCS，用来检查帧在传输中有没有损坏）组成。网卡收到一个帧，先看目标 MAC 地址：是自己的就收下，不是自己的就扔掉——除非网卡开了混杂模式，什么都收（抓包工具就是这么干的）。

帧校验序列（FCS）值得单独记一笔：发送方算出一个校验值贴在帧尾，接收方重新算一遍，对不上就说明帧在传输中损坏了，直接丢弃。链路层只保证“发现错误”，不保证“重发”——重发是传输层 TCP 的事。安全上这也意味着：链路层本身没有任何身份验证，谁发一个帧、帧里写什么，全靠自觉。

交换机怎么转发：查表，不瞎猜

交换机是局域网的“交通枢纽”。它内部有一张 MAC 地址表，记着“哪个 MAC 地址在哪个口”。刚开机时表是空的，交换机不知道谁在哪，于是学：收到一个帧，先记下“源 MAC 地址是从这个口来的”，再看目标 MAC 地址在不在表里——在，就只从对应的口发出去；不在，就从除了来源口之外的所有口都发一份（这叫泛洪），等目标回话时再把表补上。

这个“查表转发”是理解交换机的关键，也直接决定了安全边界：交换机只把帧发给该去的口，别的口是看不到的——这就是为什么在交换网络里，你的电脑默认看不到别人的流量。要看，就得用特殊手段（端口镜像、ARP 欺骗），而这些手段本身就是攻击。反过来也说明：交换机不是安全设备，它只是“高效地转发”，不验证帧是谁发的、内容真不真。

冲突域与广播域：两个容易混的概念

冲突域是“会撞车的地盘”：同一时间只能有一方说话，说话撞上了就都得重发。老式集线器（Hub）把所有口连成一个冲突域，一台发，全网等；交换机把每个口隔成独立的冲突域，口与口之间互不干扰。现代网络基本全是交换机，冲突域的问题已经很少见了——但概念要留着，因为 Wi-Fi 至今还是共享介质，一个 Wi-Fi 里的设备仍然在同一个冲突域里抢着说话。

广播域是“广播能传多远”：一个广播帧能到达的所有设备，就是一个广播域。交换机转发广播（它不知道目标在哪时只能泛洪），所以交换机不隔离广播域——整个交换机连起来的局域网就是一个广播域。路由器才隔离广播域：广播帧到路由器就停了，过不去。这就是为什么大网络要划分子网、要用路由器隔开：广播太多会拖垮全网，下一章和第 4 章会接着讲。

出错意味着什么：网口灯不亮、Wi-Fi 连上却没网，先查物理层：线、信号、驱动；能连上局域网、ping 得通邻居、ping 不通外网，问题不在链路层，往上查网关和路由；同一网里一台电脑突然收不到包，先怀疑 MAC 地址表——是不是有人在伪造 MAC 地址。

老师经验：有一次客户说“办公室里有一台电脑一上网，全网都卡”。我到现场一看，交换机某个口的灯狂闪——那台电脑中了病毒，在疯狂发广播包，整个广播域都被它拖垮了。拔掉它的网线，全网立刻恢复。物理层和链路层的问题就是这么“原始”：不需要什么高级漏洞，一根线、一个口、一台发疯的电脑，就能让一个局域网瘫痪。所以机房和办公室的第一条规矩永远是：不认识的网线别乱插，空闲的交换机口要关掉或者做端口安全——链路层不认人，只认 MAC 地址，而 MAC 地址是可以随便改的。

动手做

1. 在自己的电脑上看网卡的 MAC 地址：Windows 打开命令行跑 ipconfig /all，找到“物理地址”那一行；Linux 虚拟机里跑 ip a，看 link/ether 后面的地址。抄下来，对照一下：前 3 组查一查是哪家厂商的网卡。
2. 在虚拟机里再跑 ip a，看有几块网卡：虚拟机通常有一块 NAT 网卡和一块仅主机网卡，对比它们的 MAC 地址和 IP 地址——同一台机器，不同网卡的 MAC 地址是不一样的。
3. 在自己的电脑上跑 arp -a（Windows 和 Linux 都有）：这张表就是你的电脑记下的“邻居 IP 对 MAC 地址”，下一章讲 IP 时还会回来。

避坑

别把 MAC 地址和 IP 地址混为一谈：MAC 是网卡的出厂身份，跟着硬件走；IP 是网络里的位置，会变；别以为交换机“看不见别人的流量”就是安全——交换机只是转发，它不验证，ARP 欺骗就能绕过；别用集线器的老经验套交换机：交换机每个口是独立冲突域，不会一台发全网等；广播域别搞太大：一个局域网里设备太多，广播包会拖垮全网，该分段时要分段；改 MAC 地址很容易，别拿 MAC 地址当身份验证的唯一依据。

MAC 地址只在同一个局域网里管用——出了这个网，它就失效了。那跨网怎么办？包要从你家到另一个城市、另一个国家，靠什么找路？这就是下一章的事：第 3 章：IP、子网与路由。回头看第 1 章的分层地图：我们现在站在最底下两层，下一章爬上网络层。

本课小结
  • 物理层只负责把 0 和 1 变成信号送出去，不管内容对不对、给谁的。
  • MAC 地址是网卡出厂烧进的唯一身份，跟着硬件走；IP 地址是网络里的位置，会变。
  • 以太网帧由目标 MAC、源 MAC、类型、数据、帧校验组成，网卡只收目标是自己的帧。
  • 交换机查 MAC 地址表转发：知道就只发给对应的口，不知道就泛洪，同时学着补表。
  • 交换机隔离冲突域但不隔离广播域，路由器才隔离广播域；MAC 地址出了局域网就失效。
