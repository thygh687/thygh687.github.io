模块一第 8 章：存储层次与局部性原理

组成原理2026-11-24 · 模块一

第 3 章讲了存储金字塔：越靠近 CPU 越快、越小、越贵。这一章讲它为什么能成立：程序访问数据不是随机的，而是有规律的。这个规律叫局部性原理，整个缓存体系都建立在它上面。没有局部性，缓存就是摆设；有了它，一小块高速缓存就能让整台电脑快上一个数量级。

两种局部性

时间局部性：刚用过的数据，马上又会用。比如循环里的变量，每一轮都要读；函数里反复访问的计数器，短时间内会被读几十上百次。空间局部性：用了某个数据，它旁边的数据很快也会用到。比如数组是连续存的，读了第一个元素，第二个、第三个也快了；程序的指令也是一条接一条顺序执行的，刚执行完的指令，下一条就在它旁边。

想一想为什么会这样：程序是人写的，人写代码就是循环加顺序执行——循环带来时间局部性，顺序执行和数组带来空间局部性。这不是 CPU 设计者的美好愿望，而是真实程序的统计规律。所以缓存不是“猜”程序要什么，而是顺着程序本来就有的习惯，提前把东西备好。

缓存是怎么利用局部性的

缓存一次不是搬 1 个字节，而是一整块（叫缓存行，一般 64 字节）。因为空间局部性，旁边的字节很快会用到，一次多搬点是划算的。如果 CPU 要的数据在缓存里，叫命中，直接拿，几周期；不在，叫未命中，要去内存拿，上百周期。所以缓存越大，命中率一般越高，但大到一定程度收益就很小了。

缓存长什么样：三个关键设计

第一，数据放哪：一个内存块能放进缓存的哪些位置，这叫映射方式。直接映射最简单，一个内存块只能去一个固定位置，快但容易冲突——两个总被一起用的数据偏偏抢同一个位置，就会反复互相踢出去；全相联最灵活，任何位置都能放，但找起来慢；实际用得最多的是组相联，折中：先分到某一组，组里几个位置随便放。你的 CPU 缓存一般就是组相联的。

第二，满了踢谁：缓存满了要腾位置，踢谁出去叫替换策略。最常用的是 LRU（最近最少使用）：最久没用过的先踢——符合时间局部性，刚用过的很可能马上还要用。也有随机替换，简单但效果差一点。第三，改了怎么写回内存：写直达是改缓存的同时马上写内存，简单但慢；写回是只改缓存，等这行要被踢出去时再写回内存，快得多，但断电会丢数据——这就是为什么电脑突然断电可能丢东西，而正常关机会先把缓存写回。

还有一个多核时代的问题：每个核都有自己的缓存，同一个数据可能同时在几个核的缓存里，一个核改了它，其他核手里的就过期了。硬件用缓存一致性协议（比如 MESI）保证大家看到的是一致的——代价是核与核之间要不停地“通气”，这也是多核程序有时候没有想象中快的原因之一。

命中和未命中的代价，到底差多少

第 3 章给过一组数：寄存器约 1 个周期，L1 缓存几个周期，L3 缓存几十个周期，内存上百个周期，硬盘要几毫秒——是内存的上万倍。换句话说，一次缓存未命中，CPU 要白白等上百个周期；如果程序老是未命中，CPU 有一半时间都在等数据，再高的主频也白搭。这就是为什么同样的 CPU，跑“顺序访问数组”的程序飞快，跑“随机跳着访问”的程序就慢得多——前者缓存命中率高，后者几乎每次都要去内存。

那是不是缓存越大越好？不是。缓存越大，找起来越慢、成本越高，而且命中率的提升会递减：从 32KB 加到 256KB 提升明显，从 8MB 加到 16MB 可能只多几个百分点。设计 CPU 就是在容量、速度和成本之间找甜点。买电脑时看缓存大小有意义，但别把它当成唯一标准——第 10 章会把主频、核心、缓存放在一起讲。

和安全有什么关系

缓存是 CPU 和内存之间的共享资源，不同程序会互相影响。有人发现可以通过测量缓存的命中时间，推测出另一个程序在访问什么数据——这就是缓存侧信道攻击，著名的 Spectre 和 Meltdown 漏洞就和这个有关。原理可以一句话概括：CPU 为了快，会“推测执行”还没确定的指令，把可能用到的数据提前放进缓存；推测错了，执行结果会被丢弃，但缓存里的痕迹留下了——攻击者通过测量“哪些数据还在缓存里”，就能反推出本不该看到的秘密，比如密码和密钥。

细节以后在进阶模块讲，这里先知道两个结论：第一，“缓存也会泄露信息”——共享的硬件资源就是共享的攻击面；第二，这类漏洞修起来很麻烦，因为它不是某个程序的 bug，而是 CPU 为了性能做出的设计取舍，缓解办法往往是打补丁、更新微码，代价是一部分性能。安全和性能，经常就是这样一对矛盾。

老师经验：排查“程序跑得慢”时，别只看 CPU 占用率——占用率不高但跑得慢，很可能就是卡在缓存未命中上，CPU 大半时间都在等内存。判断方法很实在：同样的计算，顺序访问数组和随机跳着访问，耗时能差出几倍甚至几十倍。安全上也要记住这个思路：凡是“大家共用的硬件资源”，都要多问一句会不会泄露信息——缓存是这样，多核共用的内存带宽、云上共用的物理机，都是同一个道理。所以特别敏感的计算，宁可放在独占的机器上跑，也别和陌生租户挤在同一台物理机上。

动手做

1. 复制一个 1GB 的大文件，记下用时；再复制 1000 个 1MB 的小文件（总量也是 1GB），比较用时。小文件慢得多，因为每个文件都要寻址和管理，开销大。
2. 打开一个大程序，第一次打开慢，关掉马上再打开就快——第二次很多东西还在缓存里。
3. 在虚拟机里写一段小程序（或请 AI 帮你写）：顺序读一个大数组计时，再随机跳着读同一个数组计时，对比两次用时——亲手验证一次“命中率高就快”，比背十遍定义都管用。

避坑

别以为内存越大越快，瓶颈要看是哪一级；缓存是自动工作的，不用手动管；“命中”和“未命中”这两个词要记住，后面讲虚拟内存和页面置换还会遇到同样的思想。另外别信“清理缓存能加速”的说法：缓存里的东西是 CPU 特意备好的，清空它只会让接下来的一段时间更慢——真正该清的是占着内存不放的无用程序，不是缓存。

本课小结
  • 局部性原理：刚用过的数据马上会再用（时间局部性），用过的数据旁边很快会用到（空间局部性）——这是缓存能成立的原因。
  • 缓存一次搬一整行（一般 64 字节），命中几周期，未命中要去内存等上百周期；随机访问比顺序访问慢得多，就是命中率的差别。
  • 缓存设计有三个关键点：数据放哪（映射方式）、满了踢谁（LRU 替换）、改了怎么写回（写直达与写回）；多核还要用一致性协议保证各核看到的数据一致。
  • 缓存是共享资源，也会泄露信息：Spectre 和 Meltdown 就是用推测执行加缓存时序偷看秘密的，修起来要以性能为代价。
