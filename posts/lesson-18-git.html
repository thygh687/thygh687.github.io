第 18 课：Git：给学习留底，代码与笔记的时光机

Git2026-11-25 · 阶段四

上一课你用 PowerShell、事件查看器和 Defender 查了一台电脑，做完还写了几行笔记。过一个月，你还记得那天最占内存的进程是谁、那次服务崩溃的事件 ID 是多少吗？大概率不记得了。学习安全就是这样：实验做得多，改坏的东西也多——配置文件改错一行，服务起不来了；脚本改错一处，昨天还能跑的命令今天报错了。没有记录，这些教训就白交了。Git 就是解决这个问题的工具：它给你的代码和笔记留底，每一次改动都记下来，改坏了能回退，想看以前的样子随时能看回去。它像一台时光机，只不过它记录的不是时间，而是你的每一次动手。

这一课只讲 Git 在本地的用法：装好它，在虚拟机里建一个练习仓库，把实验和笔记存进去，改错了回退回来。推送到网上的事——比如传到 GitHub——是后面的事，这里不讲。先把本地这一套练熟，推送只是多一行命令的事。

Git 是什么：给文件拍照的工具

Git 是一个版本管理工具。版本管理说白了就是一件事：把文件每一次改动之后的样子都存下来，并且能随时回到以前的任何一个样子。你可能已经在用土办法做这件事了：写报告时存一个“报告-最终版.docx”，改完发现不对，又存一个“报告-最终版-真的最终版.docx”，桌面上躺着七八个版本，最后分不清哪个才是最新的。Git 就是把这件土办法做成正规工具：你不用再复制一堆文件，每次改完告诉它一声“这次改好了，拍张照”，它就把当前所有文件的样子记下来，这张照片叫一次提交（commit）。提交串起来，就是一部完整的历史：哪天改了什么、为什么改，全都留着。

要注意一个容易误解的点：Git 存的不是“改了哪几行字”那个差量清单——它存的是每次提交时所有文件的完整快照。听起来很占地方，实际上 Git 很聪明：没改过的文件，它不会重复存一份，只记一个指向；改过的文件，才存新版本。所以一个仓库用上几年，体积也不会失控。

还有一点：Git 是本地工具。装好就能用，不用联网、不用注册账号、不用把东西传到任何网站上。你的提交先存在自己电脑上的一个隐藏文件夹 .git 里——这个文件夹就是仓库的“底片库”，删了它，历史就没了；留着它，历史就一直在。后面学到把仓库传到 GitHub 上时，传的也是这份历史的复制品，本地这份永远是原件。

为什么学安全要会 Git：实验可复现，改坏了能回退

学安全的人比一般人更需要 Git，原因有两条，都和实验有关。第一条是可复现：安全实验最怕“我上次明明成功了，这次怎么不行了”。上次成功的命令、配置、脚本，如果只记在脑子里，复现不了；记在 Git 里，每次实验的命令、结果、结论都跟着提交走，别人（包括一个月后的你自己）照着笔记就能把实验原样跑一遍。写渗透测试报告、写取证报告时，这种可复现性就是专业和业余的分水岭——第 16 课讲的四个方向，无论选哪个，都要交出别人能复现的过程。

第二条是改坏了能回退：安全学习就是不断地改配置、改脚本、改规则，改坏是常态。没有 Git，改坏了只能凭记忆往回改，越改越乱；有 Git，改之前先提交一次，改坏了就回到上一个好的提交，坏掉的改动就当没发生过。第 7 课的虚拟机快照也是这个思路——Git 是文件和笔记层面的快照，虚拟机是整台电脑层面的快照，两件工具互相配合：大改动之前拍虚拟机快照，日常小改动用 Git 提交。

还有一条长远的好处：以后写代码、做项目、找工作，Git 都是默认技能。面试时别人问“你做过什么”，你把仓库打开，提交历史就是你动手的证据——几点几分改了什么、为什么改、改完解决了什么问题，全在上面。这比口头说“我学过”有力得多。

装 Git for Windows

在 Windows 上装 Git，去 Git 官方网站下载 Git for Windows，装的时候一路默认就行，只有一个地方值得停下来看一眼：安装程序会问你要不要把 Git 加到系统的 PATH 里，选默认推荐的那个选项（“Git from the command line and also from 3rd-party software”），这样你在 PowerShell 和命令提示符里都能直接敲 git 命令。装完之后，打开 PowerShell——就是 第 17 课刚用过的那个窗口——敲 git --version，看到版本号（比如 git version 2.x.x），就是装好了。

装好之后先做一次身份设置，告诉 Git 提交是谁写的——这两行命令只需要敲一次：git config --global user.name "你的名字" 和 git config --global user.email "你的邮箱"。这里的名字和邮箱只会写进你本地提交的记录里，不会发到任何地方，写什么都行，用你平时用的名字和邮箱就好。以后每一行提交记录前面，都会带着这个名字——这也是别人看你的仓库时，认出“这是谁做的”的办法。

装 Git 的时候还会顺带装一个叫 Git Bash 的东西：一个长得像 Linux 终端的窗口，里面能用 ls、cd 这类 Linux 命令。这一课的练习在虚拟机里做，用虚拟机里的终端就行，Git Bash 先知道有它就够了，以后在 Windows 上练 Linux 命令时会再用到它。

在虚拟机里建一个练习仓库

练习仓库建在虚拟机里，不用真实项目练手——真实项目里的文件丢了、乱了，是真损失；虚拟机里的练习仓库弄坏了，删掉重建就行。打开虚拟机里的终端，先建一个文件夹当仓库，再进去初始化：

mkdir ~/security-notes
cd ~/security-notes
git init

git init 的意思是“从现在起，这个文件夹由 Git 管了”。执行完，文件夹里会多一个隐藏的 .git 文件夹——那就是底片库。敲 ls -la 能看到它，平时不要动它，更不要删它。

然后写点东西进去，体会一次完整的提交流程。先建一个笔记文件 notes.txt，写上今天的日期和一句话，比如“2026-11-25：第 17 课的动手结果，最占内存的进程是浏览器”。再看一眼仓库的状态：

git status

git status 是你最常用的命令，它会告诉你仓库现在是什么情况：哪些文件是新加的、哪些改过还没提交、哪些已经准备好提交了。刚建好的 notes.txt 会显示在“未跟踪的文件”里——意思是 Git 看见它了，但还没开始管它。要让 Git 开始管它，分两步：先 git add notes.txt 把它放进“暂存区”，再 git commit -m "第 17 课动手笔记" 拍下第一张照片。-m 后面跟的是这次提交的说明，写清楚这次改了什么、为什么改——以后的你，全靠这句话认出这次提交是干什么的。

暂存区是什么意思？可以这样想：git add 是“把这几样东西放进拍照框里”，git commit 才是“按下快门”。分两步的好处是，你可以一次改了十个文件，但只把其中三个放进框里先提交，剩下的七个下次再说。刚开始不用玩这么细，记住口诀就行：改完先 add，再 commit；提交之前先 status 看一眼。

提交完，再敲 git log 看历史：它会列出每一次提交，带着提交说明、作者、时间，和一串长长的提交编号（哈希值）。提交编号是每张照片的身份证号，回退的时候就靠它认人。刚开始仓库里只有一次提交，git log 只有一行；做多了实验，它会越长越长，那就是你的学习账本。

改错了怎么回退

回退分两种情况，对应两种不同的“改错了”。第一种：文件改错了，但还没提交。比如你把笔记里的命令改错了，还没 add、没 commit，想回到上次提交时的样子：git restore notes.txt，文件立刻回到上次提交的样子，没提交的改动就没了。注意，这句命令是不可逆的——没提交的改动被还原之后就找不回来了，所以敲之前先想清楚：这次改动是不是真的不要了？不确定就先提交一次再改，提交过的东西永远能找回来。

第二种：已经提交了，才发现这次提交是错的。比如你提交了一个跑不通的脚本，想回到上一次好的提交：先 git log 找到上一次好提交的编号（取前 7 位就够用了），再 git reset --soft <编号>。这句话的意思是“回到那次提交，但保留我后来改过的文件”——工作区的文件不动，只是把提交历史往回挪了一步，改坏的那次提交就从历史上消失了，文件还留在原地等你慢慢修。初学阶段只用 --soft 这一种回退就够了，它是最温和的：东西不会丢，只是提交记录往回走。还有一种 --hard 回退会连文件一起还原，破坏力大得多，这一课不练它，等你对 Git 更熟了、也清楚自己在删什么之后再学。

还有一种更常用的“后悔药”：只想看一眼以前某个提交时的文件长什么样，但不想真的回退。用 git show <编号>:notes.txt 就能把那个提交时的 notes.txt 内容打出来看看，看完什么都不用改。这就是时光机的“只看不摸”模式，最安全。

.gitignore：告诉 Git 哪些东西不要管

不是所有文件都值得 Git 管。有些文件是程序跑起来自动生成的，比如日志、临时文件、编译出来的东西——它们体积大、变化快、重新跑一次就有了，存进仓库纯属占地方。还有些文件是不能进仓库的，比如里面写了密码、密钥、令牌的配置文件——一旦提交进 Git，删都删不干净，历史里永远留着一份。解决办法是在仓库根目录建一个叫 .gitignore 的文件，每行写一个规则，告诉 Git“这些东西别管”：

*.log
*.tmp
secrets.txt

这三行的意思是：所有以 .log 结尾的日志文件别管，所有以 .tmp 结尾的临时文件别管，叫 secrets.txt 的文件别管。写好 .gitignore 之后，git status 就再也不会列出这些文件了。记住一条铁律：密码、密钥、令牌，永远不要提交进 Git——哪怕是自己本地的练习仓库也不要，因为养成习惯之后，你才会在真正的项目里也不犯这个错。以后 第 11 课讲过的密码管理、模块里讲的密钥管理，都是同一条规矩的不同说法。

分支是什么：只讲概念和新建切换

分支（branch）是 Git 里最有用的概念之一，理解它只需要一句话：分支就是一条可以独立往前走的历史线。你现在只有一条线，叫 main（有的版本里叫 master，是一个意思），所有提交都在这条线上排队。新建一条分支，就是从当前这个点分出另一条线：git branch 实验-防火墙规则 新建一条叫“实验-防火墙规则”的分支，git switch 实验-防火墙规则 切换到这条分支上。切换过去之后，你做的提交都记在这条分支上，main 那条线完全不受影响。

这有什么用？比如你想试一个新想法——改一下防火墙规则，看看会不会把自己锁在外面——在 main 上直接改，改坏了 main 也跟着坏；开一条分支改，改坏了就把这条分支删掉，main 还是好好的；改好了，再把分支合并回 main。合并（merge）是下一步的事，这一课不练，只需要先建立这个概念：分支是用来隔离实验的，主线保持能用，实验在分支上做。这和 第 7 课虚拟机快照的思路一模一样：主线是能用的系统，分支是敢折腾的试验场。以后做渗透测试、做实验，都会养成这个习惯：开分支、做实验、成了合并、不成丢掉。

一份好的实验笔记长什么样

Git 管的是文件，笔记管的是“你当时是怎么想的”。一份好的实验笔记有五个部分，缺一不可：日期、目标、命令、结果、结论。照着这个格式写，三个月后你自己看还能看懂，别人看也能复现。举个例子，就用 第 17 课的动手做当素材：

日期：2026-11-25
目标：找出最占内存的 5 个进程，确认 Windows 更新服务的状态
命令：Get-Process | Sort-Object WS -Descending | Select-Object -First 5；Get-Service wuauserv
结果：最占内存的是浏览器，占了约 2GB；更新服务状态是 Running
结论：电脑卡不是更新服务停了，是浏览器标签页开太多了；下次卡了先看进程再动手

写笔记最忌讳两种毛病：一种是只写结果不写命令——“我查过了，是浏览器的问题”，别人没法复现，你自己过几天也忘了当时敲的是什么命令；另一种是只贴命令不写结论——贴了二十行命令，没写“所以问题出在哪、下次该怎么办”，这份笔记就没有判断，只有流水账。命令是证据，结论是判断，两个都要有。笔记就存在练习仓库里，每次实验写一份，提交一次——Git 的提交说明里写“做了什么实验”，笔记文件里写“实验的完整过程”，两者合起来，就是一份随时能翻、随时能复现的学习档案。

老师经验：我带新人时，看仓库提交历史就能看出一个人靠不靠谱。靠谱的人，提交说明写得像人话：“修复登录失败重试三次的问题”，一看就知道这次改了什么；不靠谱的人，一连十次提交都叫“修改”“更新”“test”，出了问题想回退都不知道该回哪一个。还有一次事故：有人把写了数据库密码的配置文件提交进了仓库，后来才发现，删文件没用——密码还躺在提交历史里，任何人翻历史都能找到，最后只能换掉所有密码。所以我的两条规矩是：提交说明要写“改了什么、为什么改”，密码密钥永远不进仓库。这两条现在看着像小事，以后能帮你省掉大麻烦。

避坑：别用真实项目练手——练习仓库只放在虚拟机里，弄坏了删掉重建就行，真实项目的文件丢了是真损失；别把密码、密钥、令牌写进仓库——写进 .gitignore 也不等于删掉了已经提交过的，正确做法是从一开始就不提交；别用 git reset --hard——它会连文件一起还原，初学阶段只用 --soft；别在没提交的情况下还原文件——git restore 还原掉的改动找不回来，不确定就先提交一次再改；提交说明别写“修改”“更新”这种空话——要写改了什么、为什么改；也别把 Git 当成备份工具——它管的是有意义的改动历史，不是整台电脑的备份，真正的备份还是要按 第 13 课讲过的办法另外做；这一课不讲推送到 GitHub——先把本地这套练熟，推送是后面的事。

动手做

全部在虚拟机里做，不要用真实项目练手。第一步，在虚拟机里装好 Git for Windows（或 Linux 自带的 git），敲 git --version 确认装好了，再用 git config --global 设好名字和邮箱。第二步，建练习仓库 ~/security-notes，git init 初始化，写一个 notes.txt，把 第 17 课的动手结果按“日期、目标、命令、结果、结论”五个部分写进去，git add 加 git commit 提交一次，git log 看一眼历史。第三步，故意改错一次：把笔记里的一个命令改错，提交，然后用 git log 找到上一次好的提交编号，git reset --soft 回退回去，确认文件还在、坏提交不见了。第四步，建一个 .gitignore，写上 *.log 和 *.tmp，再建一个 test.log 文件，git status 看一眼——它应该不再出现了。第五步，新建一条分支 git branch 实验-笔记格式，切换过去，在分支上改一版笔记格式，提交，然后切换回 main 看一眼——主线上的笔记还是原来的样子。做完把这五步的结果写进仓库里，提交一次——这就是你的第一份 Git 学习档案。

本课小结
  • Git 是版本管理工具：每次提交都是一张完整快照，串起来就是全部历史，改坏了能回到任何一个好的提交。
  • 学安全要会 Git，是因为实验要可复现、改坏了要能回退；提交历史本身就是你动手经历的证据。
  • 基本流程：git init 建仓库，git status 看状态，git add 放进暂存区，git commit 拍照，git log 看历史；改完先 add 再 commit，提交前先 status 看一眼。
  • 改错了怎么回退：没提交的用 git restore 还原（不可逆，敲之前先想清楚）；已提交的用 git reset --soft 回到上一个好提交，初学阶段不用 --hard。
  • 密码、密钥、令牌永远不进仓库，用 .gitignore 挡住日志和临时文件；分支是隔离实验的历史线，主线保持能用，实验在分支上做；好笔记有日期、目标、命令、结果、结论五部分。
