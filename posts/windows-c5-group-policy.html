Windows 专项第 5 章：组策略深入

Windows 专项2026-11-25 · Windows 专项

如果你管过不止一台电脑，就会想：能不能写一次规则，让所有电脑都照着做？比如“所有电脑必须开防火墙”“不许用 U 盘”“密码至少 15 位”。Windows 的答案就是组策略（Group Policy）。

组策略是 Windows 最强大的集中管理工具，也是安全基线的落地工具。公司的 IT 管理员用它管几百台电脑；你自己的电脑上，它也能帮你把安全设置一次配好、长期生效。这一章讲组策略是什么、策略存在哪、怎么生效，以及排障时怎么查“这条策略到底生没生效”。

先说清范围：家用版 Windows 没有本地组策略编辑器（gpedit.msc），专业版、企业版才有。如果你用的是家庭版，本章的动手部分可以在虚拟机的专业版里做，或者只看概念、记下思路。

组策略是什么：规则写一次，到处生效

组策略是一套“配置规则 + 下发机制”。规则可以管：安全设置（密码策略、账号锁定、用户权限）、软件限制、防火墙规则、浏览器设置、驱动安装、脚本执行……几乎所有 Windows 的可配置项，都能写进策略。

策略分两级：本地组策略（一台电脑自己的策略，用 gpedit.msc 编辑，只对本机生效）和域组策略（公司域环境里，域控制器下发给所有加域电脑的策略）。本章重点讲本地组策略，因为它是你自己电脑上能直接练的；域组策略的思路是一样的，只是下发范围更大。

策略还分计算机配置（对整台电脑生效，不管谁登录）和用户配置（对某个用户生效）。比如“禁止 U 盘”可以写在计算机配置里，谁登录都禁；“桌面壁纸”写在用户配置里，不同用户可以不同。

策略存在哪：注册表 + 文件

组策略的配置，最终大部分落到注册表里：计算机策略写进 HKLM，策略相关的注册表值存在 HKLM\SOFTWARE\Policies 和 HKCU\Software\Policies 这两个专门的位置——和普通软件写注册表的位置分开，这样管理员一眼就能分清“这是策略规定的”还是“这是软件自己写的”。

另一部分策略存在文件里：比如软件限制策略、安全模板、脚本文件，存在 C:\Windows\System32\GroupPolicy\ 目录下。排障时如果策略死活不生效，可以到这个目录看看策略文件在不在、有没有损坏。

记住这个对应关系很有用：策略不是魔法，它就是“有人帮你把注册表和配置文件写好了，并且不让你随便改”。理解了这一点，策略和注册表（第 3 章）的知识就连起来了。

策略怎么生效：刷新与优先级

策略不是改完立刻生效的。默认情况下，计算机策略每 90 分钟刷新一次（加一个 0 到 30 分钟的随机偏移，避免所有电脑同时找服务器），开机和登录时也会刷新一次。想立刻生效，在管理员 PowerShell 里运行 gpupdate /force。

多条策略冲突时有优先级：本地策略最弱，域策略更强，组织单位（OU）策略最强；同一级别里，后应用的覆盖先应用的。排障时最常见的困惑就是“我明明改了本地策略，怎么没生效？”——答案常常是：上面还有一条更强的域策略把它盖住了。

查策略生效情况的工具是 gpresult /r（看应用了哪些策略）和 gpresult /h report.html（生成一份漂亮的 HTML 报告）。RSOP（策略的结果集）则是图形化的查看方式。做安全检查时，gpresult 是必跑的命令之一。

安全基线：用组策略把安全设置一次配好

安全基线就是“一台电脑上线前应该有的安全设置的清单”。用组策略落实基线，典型项目包括：密码长度至少 15 位（按 NIST SP 800-63B Rev.4 的要求，单独使用的密码至少 15 位，不迷信复杂度，强制查泄露密码库）、账号锁定阈值（输错几次锁定）、禁止自动登录、管理审核策略（登录成功和失败都要记日志）、关闭不必要的服务、开启防火墙、禁止可移动存储。

微软官方提供 Security Baselines（安全基线包），可以下载导入；CIS Benchmarks 也是业界常用的基线标准。初学者不必一开始就啃完整基线，先从本章列出的几项做起，在虚拟机里配一遍、验证一遍，就是很好的练习。

还要提醒一句：策略管得住配置，管不住人的行为。策略可以强制密码 15 位，但管不住用户把密码写在便签上贴在显示器上——技术控制和人的意识要一起抓，这也是模块六讲过的安全文化。

本章检查清单

□ 组策略是集中管理工具：本地策略管一台电脑，域策略管所有加域电脑。

□ 策略最终落到注册表 Policies 位置和 GroupPolicy 目录的文件里，不是魔法。

□ 策略默认 90 分钟刷新一次，gpupdate /force 立刻刷新，gpresult 查生效结果。

□ 多条策略冲突时 OU > 域 > 本地，本地改了不生效常常是被更强的策略盖住了。

□ 安全基线可以用组策略一次配好：15 位以上密码、账号锁定、审核日志、防火墙等。

□ 把本章的命令和检查步骤抄进自己的笔记，下次遇到同类问题直接用。

老师经验：我见过最常见的组策略事故，是管理员在域里推了一条“禁止运行某某软件”的策略，结果把财务软件也禁了，全公司停摆半小时。教训是：推策略之前，先在小范围试点，先用 gpresult 看结果集，再全量下发；推完之后，留好回滚的办法。另一个经验是：排障时先跑 gpresult /r——很多“我改了设置怎么没生效”的问题，答案都在结果集里写着：要么是被更强的策略盖住了，要么是策略根本没应用到这台电脑。先看结果集，再动手改，能省一半时间。

动手做

1. 只在你自己的虚拟机（专业版）里：按 Win+R 输入 gpedit.msc，依次展开 计算机配置 → Windows 设置 → 安全设置 → 账号策略 → 密码策略，看看密码长度、锁定阈值现在是多少，把它们记下来。
2. 在虚拟机里以管理员身份打开 PowerShell，运行 gpresult /r，看看应用了哪些策略；再运行 gpresult /h C:\Users\Public\gpresult.html，打开生成的报告，找找密码策略那几行。
3. 在虚拟机里用 gpedit 改一项无害的设置练手：比如 用户配置 → 管理模板 → 控制面板 → 个性化 → “阻止更改桌面背景”，设为已启用，运行 gpupdate /force，再看看桌面背景是不是改不动了；练完把它改回“未配置”。

避坑

家庭版 Windows 没有 gpedit.msc，别在网上找来路不明的“家庭版开启组策略”脚本乱装，练手请用虚拟机的专业版；别在真实电脑、公司电脑上乱改策略：一条策略可能影响整台电脑甚至整个域，动手只在虚拟机里做；策略改完不生效先别急：等 90 分钟刷新周期，或跑 gpupdate /force，再用 gpresult 查结果集；别把组策略当成万能：它管得住配置，管不住把密码贴在显示器上的人。

组策略是“写一次规则，到处生效”的管理工具，也是安全基线的落地办法。下一章我们换一件更顺手的工具：第 6 章 PowerShell 安全实战——用命令行查问题、抓异常，把前面几章的检查变成几行就能跑的命令。
