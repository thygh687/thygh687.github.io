第 10 课：Linux 下的网络命令

Linux2026-11-24 · 阶段二

Windows 下的 ping、ipconfig 到了 Linux 里，名字换了，干的活一样。记住这四个。它们和第 6 课的三条命令是一套排错思路，只是换了个系统再练一遍——练到在哪个系统都能顺手查，才算真会了。

ping：通不通

ping example.org，跟 Windows 里一样。注意 Linux 的 ping 默认一直发，按 Ctrl + C 停下来。想只发 4 个就停，用 ping -c 4 example.org，和 Windows 的默认行为一样。

输出要会读：64 bytes from … time=20ms 是通了，time 是来回花的时间；Destination Host Unreachable 是连第一跳都没出去，往往是本机没连上网或网关不对；ping: example.org: Name or service not known 是名字没解析出来——这是 DNS 的问题，不是路的问题，第 4 课讲过，名字变地址靠 DNS。按 Ctrl + C 停下后还会有一行统计：发了几个、收到几个、丢了几个——丢包率一高，网络就不稳，time 再小也没用。

和 Windows 一样：ping 不通不等于服务器挂了，很多服务器为了安全直接禁掉 ping，网站照常能打开。ping 是用来缩小范围的，不是用来下结论的。

ip a：看本机网络配置

ip a 相当于 Windows 的 ipconfig，看自己的 IP 地址和网卡。输出比 ipconfig 啰嗦，重点只看三行：网卡名（比如 enp0s3）、inet 后面的 IP 地址、state UP 还是 DOWN。

什么时候用 ip a？刚开机没网时先跑它；换了网络模式之后，确认地址变了没有；排错的第一步永远是它——先确认自己没问题，再去怪别人。地址如果变成 169.254.x.x 开头，说明没拿到地址，和 Windows 里是一样的意思。网关用 ip route 看，输出里 default via 10.0.2.2 那一行就是出门的大门——NAT 模式下它通常是 10.0.2.2。

顺带认一个老命令：ifconfig 是 ip a 的前辈，很多老教程还在用它。新系统默认可能没装它，看到教程里写 ifconfig，知道它就是 ip a 的旧名字就行，不用特意去装。

curl：发个请求看返回

curl example.org 会把那个网页的 HTML 直接打出来。加 -I 只看响应头，包括状态码。curl -I example.org 返回 HTTP/1.1 200 OK，说明网站正常；返回 404 是页面不存在，301/302 是跳转，500 是服务器那边出错了。

什么时候用 curl？浏览器打不开网站时，先用 curl 试一次：curl 能拿到内容、浏览器打不开，问题在浏览器或本机设置；curl 也拿不到，再往网络和 DNS 上查。它和 ping 是搭档：ping 只问“路通不通”，curl 问的是“网站能不能正常回答”。路通了、网站没回答，和路根本不通，是两回事。

还有一个安全上的用途：curl 只发请求、不执行网页里的任何东西。浏览器打开一个可疑页面可能会跑脚本、弹窗口，curl 只是把原始内容打出来给你看。所以检查一个不确定的链接时，先 curl 看一眼，比直接用浏览器打开要稳妥得多——当然，只在虚拟机里做，而且只看 example.org 这类无害的地址练手。

ss：谁在监听端口

ss -tlnp 列出本机正在监听的端口和对应的程序。这是以后查“这台机器开了什么服务”的基本功。

四个字母各管一件事：-t 只看 TCP，-l 只看正在监听的，-n 显示数字端口不翻译成名字，-p 显示是哪个程序在监听。输出里重点看两列：Local Address:Port（监听在哪个地址和端口，比如 0.0.0.0:22 就是所有地址的 22 端口）和最后一列的程序名。看到不认识的端口先别慌，记下来，再去查它是谁开的、该不该开。

一个权限细节：-p 要看别人的程序，需要管理员权限。直接跑 ss -tlnp，别人的程序那一列可能是空的；加 sudo ss -tlnp 才能看全。这正是第 9 课讲的道理——输出少了一块，不一定是没东西，很可能是权限不够。

老师经验：查一台机器“开了什么服务”，先 ss -tlnp 再看别的——多一个监听端口，就多一个入口。很多安全检查的第一步就是这条命令：把输出截下来，一个一个问“这个端口是谁、该不该开、能不能关”。刚装好的 Ubuntu 默认几乎不监听什么端口，这是好事；装的软件越多，开的端口越多，清单就要越勤快地对。还有一条：ss 看到端口，不等于从外面能连上——中间还有防火墙那一关，第 15 课会讲防火墙；现在先把“本机开了什么”这张清单练熟。

避坑：一是 Linux 的 ping 默认不停，忘记按 Ctrl + C 会一直刷屏，养成用 ping -c 4 的习惯；二是 ss 不加 -p 看不到程序名，不加 sudo 看不全，别把“看不到”当成“没有”；三是别拿 curl 去碰来路不明的链接练手，课程里只用 example.org 这类无害地址，所有实验都在虚拟机里做。

动手做

在虚拟机里跑一遍：curl example.org 看返回；ss -tlnp 看本机开了哪些端口，记下来。再按排错链走一遍：ip a 看地址、ping -c 4 8.8.8.8 看外网通不通、ping -c 4 example.org 看名字能不能解析、curl -I example.org 看网站能不能回答。把每一步的结果记下来——这就是你在 Linux 下的第一份网络体检报告，下一阶段（第 11 课起）查账号和服务安全时，还会回到这张清单上。

本课小结
  • ping 问路通不通：Linux 默认一直发，用 -c 4 只发 4 个；不通时先看报错，名字问题和路的问题要分开。
  • ip a 是 Linux 的 ipconfig：看网卡名、IP 地址和 UP/DOWN；网关用 ip route 看；NAT 下的地址通常是 10.0.2.15。
  • curl 发请求看返回：-I 只看响应头，200 是正常，404 是页面不存在；它只取内容、不执行网页，适合先看一眼再决定。
  • ss -tlnp 查本机监听的端口和程序：想看全要加 sudo；多一个端口就多一个入口，清单要勤对。
  • 排错是一条链：ip a → ping 网关 → ping 外网 → ping 域名 → curl，哪一步断了，问题就在哪一段。
