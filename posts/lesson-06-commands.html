第 6 课：动手：ping、ipconfig、nslookup

动手2026-11-24 · 阶段一

前面五课的概念，用这三个命令一次验证完。先按 Win + R，输入 cmd 回车，打开命令行。

ping：先问一句“你在吗”

ping 是网络排错的第一句话。遇到“上不了网”“打不开网站”，先 ping 一下，就能把问题缩小一半。它回答三个问题：对方在不在？路通不通？要多久？

ping example.org

通了，说明什么？收到 4 个回复（Reply from …），time=20ms 左右。说明：你的网卡没问题、网关通、中间的路通、对方也回话了——整条路是好的。

不通，说明什么？先看报错长什么样，不同的报错指向不同的问题：

  • 请求超时（Request timed out）：包发出去没回来。可能对方关机了，或者对方的防火墙把 ping 挡了，或者中间某段路断了。
  • 无法访问目标主机（Destination host unreachable）：连第一跳都没出去，往往是你这边的网关不对，或者本机根本没连上网。
  • 找不到主机（Ping request could not find host）：名字都没解析出来，这是 DNS 的问题，不是路的问题——第 4 课讲过，名字变地址靠 DNS。

什么时候用 ping？上不了网的时候第一个就用它；怀疑某个服务器挂了，先 ping 一下；打游戏卡、视频卡，ping 一下看看延迟是不是飙到几百毫秒。

老师经验：ping 不通不等于服务器挂了——很多服务器为了安全直接禁掉 ping，网站照常能打开。ping 是用来缩小范围的，不是用来下结论的。

ipconfig：先看看自己是谁

出问题先看自己：有没有拿到地址？网关对不对？DNS 是谁？这三个问题，一条命令全答了。第 3 课的四个概念，就是在这里对上号的。

ipconfig

重点看两行异常：IPv4 地址如果变成 169.254.x.x 开头，说明没拿到地址——DHCP 没配上，先检查网线、Wi-Fi，重启路由器；默认网关如果是 0.0.0.0，说明没配网关，包出不去。

什么时候用 ipconfig？刚连上网却没网时先跑它；换了 Wi-Fi、换了网络之后，确认地址变了没有；排错的第一步永远是它——先确认自己没问题，再去怪别人。

nslookup：专门问 DNS 要地址

nslookup example.org

直接问 DNS 服务器：这个域名对应哪个 IP。返回的地址应该和 ping 显示的那个一致。它和 ping 是一对搭档：ping 域名时报“找不到主机”，但 nslookup 查得到地址，说明 DNS 没问题，问题在路上；nslookup 也查不到，那 DNS 本身就有问题。

排错思路：三条命令是一条链

上不了网的时候，按这个顺序查，每一步通了再往下一步，哪一步断了，问题就在哪一段：

这条链就是前面五课串起来的：第 3 课的地址和网关、第 4 课的 DNS、第 5 课的网站打开过程。到了模块三，还会再回来——用 Wireshark 把这些包亲眼抓下来看。

避坑：别拿 ping 当“网站挂没挂”的唯一标准；ping 域名和 ping IP 结果不一样时，先怀疑 DNS，不要怀疑路。

动手做

三条命令各跑一遍，把结果记下来：你的 IP 是多少，网关是多少，example.org 的 IP 是多少。再故意断一次网（拔网线或关 Wi-Fi），看 ipconfig 和 ping 的报错怎么变——报错长什么样，下次一眼就认出来。
