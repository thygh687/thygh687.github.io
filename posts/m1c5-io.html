模块一第 5 章：总线与输入输出

组成原理2026-11-24 · 模块一

CPU、内存、硬盘、显卡之间要传数据，走的都是总线。总线就是电脑里的路，路越宽、一次能运的东西越多。这一章要讲清楚：数据是怎么在“路”上走的、CPU 是怎么知道设备有事的、以及为什么输入输出是安全上最容易被忽视的攻击面——CPU 和内存有层层保护，设备和驱动往往没有。

三种总线：路、门牌号、命令

数据总线运数据，地址总线指明数据要去哪个地址，控制总线发命令（读还是写）。三条线各管一件事，缺了哪条都走不通：只知道运什么、不知道运到哪，不行；知道运到哪、没人下命令，也不行。地址总线的宽度决定了 CPU 能管多大的内存：32 位地址最多管 4GB 内存，64 位地址就大得用不完了，这也是 32 位系统认不出 4GB 以上内存的原因——不是内存条插不上去，是地址线数不过来。

带宽和延迟是两回事：路宽决定一次能运多少（带宽），路长和红绿灯决定一趟要多久（延迟）。总线升级大多是在加宽路：从并行总线（多根线同时传，但线一多就互相干扰）到串行总线（PCIe、USB、SATA 一次传一位，但频率高、抗干扰），路变“窄”了反而更快——这就是为什么现在的高速总线全是串行的。看设备性能时，先分清卡的是带宽还是延迟：拷大文件卡带宽，打开小文件多、反应慢卡延迟。

输入输出设备：两种打交道的方式

键盘、鼠标、显示器、网卡、硬盘都是输入输出设备。CPU 通过端口跟它们打交道：往端口写数据就是发命令，从端口读数据就是收结果。还有一种方式叫内存映射 I/O，就是把设备的端口当成内存地址来访问，写内存就等于在操作设备。两种方式结果一样，只是“地址”的叫法不同：独立编址是设备有自己的一套端口号，内存映射是设备借用内存地址空间里的一段。

为什么安全上要关心这个？因为内存映射意味着：能写某段“内存”的程序，就能操作对应的设备。如果权限没管好，一个普通程序写到映射了网卡寄存器的地址，就能改网卡的配置；写到映射了显存的地址，就能在屏幕上画东西。设备和内存之间没有天然的墙，墙是操作系统和内存管理单元（MMU）后加上去的——墙有没有、严不严，决定了设备是不是攻击面。模块二第 7 章讲虚拟内存时，会讲这堵墙是怎么砌的。

中断：有事再叫我

设备有事的时候会打断 CPU 一下：比如你敲了一个键，键盘就发个中断，CPU 停下手里的活，先处理这个按键，再回去继续。这比轮询好得多——轮询是 CPU 不停地问每个设备“有事吗”，大部分时间都在白问；中断是“有事设备自己会说”，CPU 可以安心干别的。

中断发生时 CPU 要做的事，和第 4 章的函数调用很像：先把当前现场（程序计数器、寄存器）压进栈，再跳到中断处理程序，处理完再弹出来、回去继续。区别是：函数调用是程序自己约好的，中断是设备随时打进来的，CPU 事先不知道什么时候来。所以中断处理程序必须快、必须能随时被打断后恢复——这也是中断处理里最容易出 bug 的地方：现场没保存全，回去就接着错的地方继续跑。第 9 章会把中断和 DMA 展开细讲，包括中断的优先级和中断向量表。

什么时候用轮询，什么时候用中断？设备很少有事、来了就要马上处理（键盘、鼠标），用中断；设备一直在高速吐数据、等不起（高速网卡、硬盘），轮询反而更划算，因为中断本身也有开销——中断太频繁，CPU 光处理中断就忙不过来了。没有哪种方式永远更好，看的是设备的性子。

DMA：大块搬运不用 CPU 盯着

从硬盘读一个大文件，不用 CPU 一点一点盯着，DMA 控制器直接在内存和硬盘之间搬，搬完告诉 CPU 一声就行。省下来的 CPU 时间可以干别的。DMA 的代价是：搬运的时候，设备能直接读写内存，不经过 CPU——这就带来一个安全问题：如果一个恶意设备（比如来路不明的扩展卡、带 DMA 能力的外部接口设备）能直接读写内存，它就能绕过 CPU 和操作系统的检查，直接改内存里的数据、偷内存里的密钥。这类攻击叫 DMA 攻击，防御靠 IOMMU：给 DMA 也加一道“你能碰哪段内存”的门禁。现代电脑一般都有，但老设备和没开这个功能的机器，就是敞开的。

驱动：设备和系统之间的翻译官，也是攻击面

操作系统不直接跟五花八门的设备说话，中间隔着驱动程序：驱动把操作系统的通用命令，翻译成某个具体设备的方言。驱动跑在很高的权限上——因为它要直接操作硬件、响应中断、做 DMA。所以驱动出问题，影响比普通程序大得多：一个有漏洞的驱动，等于给攻击者开了一扇直通内核的门。装驱动只装官方的、只装需要的、及时更新，不是洁癖，是安全习惯。设备管理器里带黄色感叹号，先看驱动，别急着重装系统；反过来，一个来路不明的设备、一个随手装的驱动，也别急着点“下一步”。

老师经验：修电脑时，设备问题我先分三层：线和接口（插紧了没有、换个口试试）、驱动（设备管理器里有没有感叹号、驱动是不是官方的）、设备本身（换台机器试试还认不认）。十次有八次是前两层。安全上我多一层：来路不明的 U 盘和扩展设备，先别往主力机上插——U 盘能伪装成键盘（插上就自己“打字”执行命令），能伪装成网卡（插上就劫持网络），这些都不是科幻，是真实存在的手法。真要看里面的东西，先在断网的虚拟机里挂载，只读打开。还有，雷电接口这类支持 DMA 的口子，陌生设备别乱插，IOMMU 不是每台机器都默认开着的。

动手做

1. 右键“此电脑” → 管理 → 设备管理器，看一眼自己电脑的设备：处理器、磁盘驱动器、网络适配器都在。
2. 插拔一次 U 盘，看设备管理器里是不是多了一个设备又消失了。
3. 打开任务管理器 → 性能 → 磁盘，复制一个大文件，看读写速度的变化——这就是 DMA 在替 CPU 搬运。

注意：插拔 U 盘只用自己的、确认干净的 U 盘做；来路不明的设备不要往主力机上插，真要检查，先在虚拟机里、断网、只读挂载。

避坑

设备管理器里带黄色感叹号先看驱动，别急着重装系统；中断和 DMA 知道是干什么的就行，不用背细节；32 位和 64 位的区别先记住“内存寻址”这一条就够了；最容易错的是以为“设备只是外设，跟安全没关系”——驱动跑在高权限上，能 DMA 的设备能直接读写内存，外设就是攻击面。

下一章回到最底层：第 6 章：逻辑门与布尔代数，看看 CPU 里的部件本身是由什么拼出来的。回头看第 4 章的栈，中断发生时 CPU 压栈的也是同一套动作。

本课小结
  • 总线分三种：数据总线运数据、地址总线指明去哪、控制总线发命令；地址线宽度决定能管多大的内存。
  • CPU 跟设备打交道有两种方式：独立端口和内存映射 I/O；映射意味着能写那段地址就能操作设备。
  • 中断是“有事设备自己说”，发生时 CPU 要压栈保存现场，处理完再恢复——和函数调用是同一套动作。
  • DMA 让设备直接在内存和外设之间搬数据，省了 CPU 的时间，但也绕过了 CPU 的检查，要靠 IOMMU 设门禁。
  • 驱动跑在高权限上，是翻译官也是攻击面；来路不明的 U 盘和扩展设备别往主力机上插。
