模块二第 18 章：文件系统内部：inode、日志与崩溃一致性

操作系统2026-11-25 · 模块二

第 9 章讲过文件系统与权限：文件有名字、有权限、有所有者，目录是一棵树。那一章讲的是“用起来什么样”，这一章讲的是“存在磁盘上到底长什么样”。这件事对安全人员特别重要，因为取证的入口就在这里：删掉的文件为什么能恢复？一个文件被改过之后，磁盘上会留下什么痕迹？系统突然断电，文件系统怎么保证自己不被写坏？答案都在 inode、日志和崩溃一致性这三个词里。

先建立一个基本图像：磁盘是一块块固定大小的“块”（block，一般 4KB），文件系统的工作，就是把“文件”这个逻辑概念，翻译成“哪些块、按什么顺序、归谁管”这个物理现实。文件名和文件内容是分开存的——文件名存在目录项里，文件内容存在数据块里，中间由一个叫 inode 的结构牵线搭桥。

inode：文件的“身份证 + 藏宝图”

inode（index node，索引节点）是 Unix/Linux 文件系统的核心结构。每个文件对应一个 inode，里面存着文件的元数据：文件类型（普通文件、目录、链接）、权限位、所有者、大小、时间戳（创建时间、修改时间、访问时间），以及——最关键的——指向数据块的指针。文件名不在 inode 里，文件名存在目录项（directory entry）里，目录项就是一张“名字 → inode 编号”的对照表。一个目录本身也是一个文件，它的数据块里装的就是一张张目录项。

inode 里的指针分三档：直接指针（一般 12 个），直接指向存数据的数据块；一级间接指针，指向一个“装满了指针的块”，那个块里的每个指针再指向一个数据块；二级、三级间接指针再往上套一层。这样的设计很巧妙：小文件只用直接指针，又快又省；大文件靠间接指针一路套上去，能撑到几 TB。算一笔账就明白了：块大小 4KB，直接指针 12 个能管 48KB；一级间接指针指向的块里能装 1024 个指针，能管 4MB；二级能管 4GB；三级能管 4TB。

“文件名和内容分开存”这个设计，解释了好几个日常现象。第一，同一个文件可以有多个名字：硬链接就是在目录项里多加一条“新名字 → 同一个 inode 号”的记录，两个名字指向同一个文件，改一个等于改另一个，删一个另一个还在——只有当所有名字都删掉、且没有进程还开着它时，文件的数据块才真正被释放。第二，mv 改名飞快：同一文件系统里移动文件，只是改目录项里的名字，不用搬数据；跨文件系统移动就慢得多，因为要实打实地复制数据块。第三，ls -i 能看到每个文件的 inode 编号，两个文件的 inode 号相同，它们就是同一个文件的两个名字。

三个时间戳也要分清：mtime 是内容最后修改的时间，ctime 是 inode 本身最后改变的时间（比如改权限、改名字都会更新 ctime），atime 是最后访问（读取）的时间。取证时这三个时间要一起看：一个文件的 mtime 是上周、ctime 是昨天凌晨三点，说明昨天有人改了它的权限或名字，但没改内容——这本身就是一条线索。注意，现代系统为了性能，atime 默认不是每次读都更新（relatime 模式），所以 atime 只能做参考，不能当铁证。

ext4 与 NTFS 的盘上结构

Linux 最常用的文件系统是 ext4，它的盘上结构是：引导块、块组描述符、inode 表、数据块区。磁盘被分成若干个块组，每个块组里都有自己的 inode 表和数据块，这样文件和它的 inode 离得近，读写快。ext4 支持日志（下面讲）、支持大文件、支持区段（extent）：一个区段记录“从第几块开始、连续多少块”，比一个一个指针省空间，大文件的读写也更快。

Windows 的 NTFS 思路不同，但核心问题一样：元数据放哪、数据块怎么找。NTFS 的核心是一张主文件表（MFT，Master File Table）：磁盘上的每个文件在 MFT 里都有一条记录，记录里存着文件名、权限、时间戳和数据的位置。小文件（一般小于 1KB 左右）干脆直接把内容存在 MFT 记录里，叫常驻数据；大文件的内容存在 MFT 记录指向的数据区里，叫非常驻数据。NTFS 的目录也是 MFT 里的一条记录，里面存着文件名到 MFT 记录号的索引——和 inode + 目录项是同一个思路，换了个名字和实现。

对取证来说，MFT 和 inode 表都是必看的地方：文件删了，MFT 记录和 inode 不会立刻清零，只是被标记成“空闲”，名字、时间戳、数据块指针往往还留在原地——这就是下一节“删掉的文件为什么能恢复”的答案。还有一个 NTFS 特有的点：备用数据流（ADS，Alternate Data Stream），一个文件除了主内容，还可以挂几个“暗格”里的数据流，资源管理器里看不到文件大小变化，但数据确实存在磁盘上——恶意软件藏东西的经典手法之一。

日志与崩溃一致性：断电了，文件系统怎么不坏

写一个文件，文件系统要在磁盘上做不止一件事：分配数据块、写数据、更新 inode 的大小和时间、更新目录项。问题是，磁盘写入不是原子的：写到一半突然断电，磁盘上可能只完成了一半——数据写进去了，inode 没更新；或者 inode 更新了，数据还没写进去。文件系统就处在一种“半成品”状态，这叫不一致（inconsistency）。

日志（journaling）是解决这个问题的标准办法，思路像记账本：正式改磁盘之前，先在日志区写一条“接下来我要做什么”，写完日志、确认落盘了，再去改真正的数据区；改完了，在日志里记一笔“做完了”。断电重启后，文件系统先读日志：做到一半的操作，按日志重做一遍（redo）；没来得及做的，按日志撤销（undo）。因为日志是按顺序追加写的、而且写日志本身很快，恢复的时间大大缩短。ext4 默认开日志，NTFS 也有自己的日志（$LogFile），思路一样。

没有日志的文件系统（比如早期的 ext2、FAT32），断电后只能全盘扫描修复：fsck（Linux）或 chkdsk（Windows）把整个磁盘扫一遍，找出不一致的地方修好——磁盘越大扫得越久，而且有些损坏修不好，只能把文件丢进 lost+found（Linux）或直接删掉。所以服务器和重要数据一定要用带日志的文件系统；U 盘用的 FAT32/exFAT 没有日志，拔盘之前要点“安全删除硬件”，就是因为它没有这道保险。

删除的文件为什么能恢复：取证的入口

删除一个文件，操作系统做的事情比你想象的少得多：它只是在目录项里把名字删掉、在 inode 或 MFT 记录里把“已分配”标记改成“空闲”，数据块本身一个字节都没动。只要这些数据块还没被新文件覆盖，数据就还在磁盘上躺着，等着被恢复工具按 inode/MFT 里残留的指针找回来。这就是文件恢复软件的原理，也是取证的入口：删掉不等于销毁。

真正销毁数据要做两件事：覆盖和验证。覆盖是把数据块用随机数据或全零重写一遍（甚至多遍）；验证是读回来确认确实写上了。Windows 的 cipher /w、Linux 的 shred、专业擦除工具，做的就是这个。只格式化、只删文件、只清空回收站，都不等于销毁——格式化只是重建了文件系统的元数据区，数据块也还在原地躺着。卖旧硬盘、旧 U 盘之前，先想清楚这一点：要么全盘覆盖擦除，要么物理销毁，别只删文件就出手。

老师经验：取证第一课就是“别在原盘上操作”。有一次用户误删了一个重要文件，自己先装了个恢复软件在同一块盘上，又往盘里拷了几个文件，然后才来找我——恢复软件的安装和新拷入的文件，恰好覆盖了他要恢复的文件的数据块，神仙也救不回来。正确的做法是：立刻停用这块盘，挂到另一台机器上只读挂载，或者先做一个整盘镜像，在镜像上恢复。还有一次查一台可疑机器，MFT 里一条记录的文件名是正常的，但它的备用数据流里藏了一个可执行文件，资源管理器里完全看不见——ADS 这种“暗格”一定要专门查。时间戳也要三看：mtime、ctime、atime 一起看，单个时间戳很容易被改（touch 命令就能改 mtime），三个时间互相印证才可信。

动手做

全部在虚拟机里做，不要动真实数据盘。1. 在虚拟机里的 Linux 上跑 ls -li，看每个文件前面的 inode 编号；再跑 ln 原文件 硬链接名 建一个硬链接，ls -li 再看一次：两个名字的 inode 号是不是一样？改其中一个文件的内容，另一个变不变？2. 跑 stat 文件名，读出 Access、Modify、Change 三个时间，再跑 chmod +x 文件名 改一下权限，stat 再看一次：哪个时间变了、哪个没变？3. 在虚拟机里建一个测试文件，写点内容，记下它的 inode 号（ls -i），删掉它，再跑 debugfs -R "stat <inode号>" /dev/你的虚拟机磁盘 看看（只读查看，不要写操作）——体会“删了之后元数据还在”。如果 debugfs 不好操作，改做第 4 步也行。4. 在 Windows 虚拟机或自己的 Windows 上，对一个 U 盘文件点右键 → 属性，看 NTFS 文件的“以前的版本”有没有内容，再想一想：为什么 U 盘（FAT32/exFAT）没有这个功能？

避坑

删文件不等于销毁数据：想销毁要覆盖重写并验证，只删文件、只格式化都不可靠；取证和恢复要在只读挂载或整盘镜像上做，不要在原盘上装软件、拷文件，会覆盖要找的数据；时间戳单个不可信：mtime 可以用 touch 改，mtime、ctime、atime 要一起看；硬链接和软链接不是一回事：硬链接是多一个名字指向同一个 inode，软链接是一个指向路径的小文件，删原文件软链接就断了；U 盘不要直接拔：FAT32/exFAT 没有日志，断电或直接拔盘最容易丢数据，先点“安全删除硬件”。

磁盘上的结构讲完了，下一章讲操作系统怎么跟硬件打交道：第 19 章：I/O 子系统与驱动模型——系统调用、驱动、控制器和设备之间，数据是怎么流动的。

本课小结
  • inode 是文件的身份证加藏宝图：存元数据和指向数据块的指针，文件名存在目录项里；硬链接就是多一个名字指向同一个 inode。
  • ext4 用 inode 表加区段管文件，NTFS 用主文件表 MFT 管文件；小文件可以直接存在 MFT 记录里，NTFS 还有备用数据流这种“暗格”。
  • 日志是崩溃一致性的保险：先写日志再改数据，断电重启后按日志重做或撤销；没有日志的文件系统断电后只能全盘扫描修复。
  • 删除文件只删目录项和分配标记，数据块还在原地——这就是文件能恢复、也是取证的入口；真正销毁要覆盖重写并验证。
  • 三个时间戳要一起看：mtime 改内容，ctime 改 inode，atime 是最后读取；单个时间戳可以被改，不能当铁证。
