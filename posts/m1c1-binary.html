模块一第 1 章：二进制与数据表示

组成原理2026-11-24 · 模块一

电脑里只有两种状态：晶体管导通、有电，是 1；断开、没电，是 0。一位这样的数叫 bit，8 位叫一个 byte。电脑里的一切——数字、文字、图片、声音——最后都是 0 和 1 的排列。学安全的第一步，就是学会像电脑一样看数据：你以后天天要看的十六进制、内存转储、网络抓包，全是这一章的延伸。

为什么偏偏是二进制

为什么不用十进制？因为硬件只认“有电 / 没电”这两种状态，而且两种状态最不容易认错：电压高一点低一点、受一点干扰，十进制的“7”和“8”可能就分不清了，二进制只有两种可能，容错空间大得多。晶体管只有开和关，开关的组合只能数出 0 和 1——二进制不是人挑的，是硬件逼出来的。理解了这一点就明白：电脑不是“喜欢”二进制，而是只能这样。

但这也带来一个代价：人类习惯的十进制数，在电脑里要先翻译成二进制；电脑算完，还得再翻译回来给你看。翻译的规则，就是本章要讲的数据表示。规则一旦定错，翻译就会出错——很多安全漏洞的根子就在这里：程序以为一个数是这个意思，电脑存的却是那个意思。

二进制和十进制一个道理

十进制里，263 是 2 个一百、6 个十、3 个一，每一位是 10 的倍数。二进制也一样，只是每一位是 2 的倍数：101 就是 1 个四、0 个二、1 个一，加起来是 5。再比如 10110111：1×128 + 0×64 + 1×32 + 1×16 + 0×8 + 1×4 + 1×2 + 1×1 = 183。

什么时候用二进制，什么时候用十六进制？人读二进制太累了，8 位一串、32 位四串，眼睛一花就数错。所以日常用十六进制：每 4 位二进制正好对应 1 位十六进制（0–9、A–F），10110111 就是 B7。内存地址、文件头、抓包结果，安全工作中见到的几乎全是十六进制——它不是新东西，只是二进制的“压缩写法”。练的时候可以这样换算：先 4 位一组，再查表（1011 = B，0111 = 7）。

同一串 0 和 1，意思可以完全不同

这是本章最重要的一句话。10110111 只是 8 个开关的状态，它是 183（无符号数）、还是 -73（有符号补码）、还是字母？只看这一串 0 和 1 是分不出来的，意思取决于程序按什么规则去解读它。CPU 不知道它在算什么，它只按电路做事；是程序员在某个地方决定了“这一字节是有符号数”还是“这一字节是个字符”。两个人对同一串数据的理解不一样，漏洞就从这里来。

负数怎么存：补码

电脑里负数用补码存。8 位数里，-3 的补码是 11111101（十进制 253）。好处是加减法能用同一套电路算：5 + (-3) 就是 5 + 253 = 258，超过 8 位的进位丢掉，得 2，答案是对的。

补码是怎么来的？别死记“取反加一”，理解它是一套“钟表算术”：8 位数就像一个只有 256 个刻度的钟，从 0 转一圈回到 0。-3 就是“从 0 往回拨 3 格”，落在 253 的位置，所以 -3 存成 253。取反加一只是算出这个位置的快捷办法：3 是 00000011，取反 11111100，再加 1 得 11111101。最高位是 1 的数就是负数，最高位是 0 的是正数——所以 8 位有符号数只能表示 -128 到 127，装不下 128。

出错意味着什么：溢出。8 位有符号数里，127 + 1 不等于 128，而是 -128——因为 01111111 加 1 变成 10000000，最高位翻成 1，电脑按负数去读了。这就是整数溢出。程序里它可能只是算错一个数，也可能变成安全漏洞：比如程序先检查“长度不能超过 127”，检查通过后一加，长度变成负数，绕过了检查，后面按这个长度去复制数据，就会把内存写坏。历史上不少漏洞就是这么来的：检查时是一个意思，真正用的时候是另一个意思。

常见误区：以为“负数就是前面加个减号”。电脑里没有减号这个东西，负号是靠补码这个约定硬造出来的。另一个误区是把“无符号”和“有符号”混着用：同一个字节 11111101，无符号读是 253，有符号读是 -3——程序里一个地方按无符号比较、另一个地方按有符号比较，判断结果会完全相反，这正是很多整数符号混淆漏洞的成因。第 4 章的汇编里会亲眼看到：同一条比较指令，有符号和无符号的跳转条件是不一样的。

小数和文字：精度有限，编码有约

小数用浮点数存（IEEE 754 标准），由符号位、指数和尾数三部分组成，精度有限，所以 0.1 + 0.2 在电脑里不等于 0.3——这是正常的，不是 bug。为什么？因为 0.1 在二进制里是无限循环小数，就像十进制里 1/3 写不尽一样，电脑只能存一个近似值，两个近似值一加，误差就露出来了。

什么时候要当心：凡是不能差一分钱的地方（金额、计费），都不要用浮点数直接算；凡是拿浮点数做“相等”判断的地方（if (a == 0.3)），都可能因为误差而失败。正确的做法是比较“差值够不够小”，或者干脆用整数存最小单位（比如用“分”而不是“元”）。安全上也有影子：有的程序用浮点数算权限、算余额、算次数，误差一攒，就可能被钻空子——钱和权限，永远别交给近似值。

文字也是数字：编码表规定每个字符对应哪个数字，ASCII 里大写 A 是 65；中文用 UTF-8，一个汉字一般占 3 个字节。UTF-8 是变长编码：英文 1 个字节，中文一般 3 个字节，生僻字和表情可能 4 个字节。所以“一个字符几个字节”没有固定答案，得看是哪个字符。安全上要记住两点：第一，编码不对就会乱码——收到一串字节，先得知道它按什么编码读，读错了就是另一串字；第二，程序按“字符数”检查、按“字节数”存，长度一不一致，截断的地方就可能出问题。以后看日志、看抓包、看文件头，看到的乱码先问一句：这是什么编码？

容量单位：1024 和 1000 的两本账

1 KB 是 1024 个字节，1 MB 是 1024 KB，1 GB 是 1024 MB，1 TB 是 1024 GB。买硬盘时说的 500GB，电脑里显示会少一点，是因为厂家按 1000 算，电脑按 1024 算。严格说，1024 的单位该叫 KiB、MiB、GiB，1000 的才叫 KB、MB、GB，但日常大家混着用。知道有两本账就够了：看到容量数字先问“按谁算的”，别以为硬盘少给了你空间，也别以为内存条标错了。

老师经验：排错和取证时，天天都在跟数据表示打交道。看十六进制转储，先认文件头几个字节（比如可执行文件开头常是 4D 5A，也就是字母 MZ）；看日志里的长度字段，先问一句“这是有符号还是无符号”——我见过太多问题，根子就是一段程序按无符号读长度、另一段按有符号读，检查和实际使用对不上。还有一条：凡是程序里出现“0.1 + 0.2 不等于 0.3”这种事，别当 bug 修，先想想是不是浮点数精度——修错地方，越修越乱。

动手做

1. 打开 Windows 计算器 → 左上角菜单 → 程序员，在十进制和二进制之间切换，输几个数看它们怎么互相转换；再切换到十六进制，看 183 是不是显示为 B7。
2. 新建一个记事本，输入一个字母 A 保存，看文件大小是 1 字节；再输入一个汉字“中”保存，看文件大小是 3 字节。
3. 算一算：二进制 1100100 是多少？（答案：100。）再算一道：8 位有符号数里，127 + 1 是多少？（答案：-128，溢出了。）

动手做的时候在虚拟机里练也行——这一课的操作本身没有风险，但从现在起养成习惯：凡是实验、凡是来路不明的程序，都只在虚拟机里做，绝不在真实系统和真实网站上练手。

避坑

别背二进制表，重点是理解“每一位是 2 的倍数”这个道理；补码先会用，不用死磕推导，但要记住最高位是符号位、8 位有符号数只能到 127；容量单位记住 1024 就够了，不用纠结硬盘标称和实际显示差多少；最容易错的是把“同一串 0 和 1”当成只有一个意思——意思永远取决于解读规则。

下一章看这些 0 和 1 是怎么被一条一条执行起来的：第 2 章：CPU 是怎么执行指令的。补码和溢出到了第 4 章汇编还会再见一次，那时你能亲手算出来。加法器、乘法器这些硬件到底是怎么把加减乘除算出来的，浮点运算在电路里又是怎么实现的，是第 16 章：计算机运算的事。

本课小结
  • 电脑只认 0 和 1，是晶体管只有开和关逼出来的；十六进制只是二进制的人类友好写法。
  • 同一串 0 和 1 可以是 183、-73 或一个字母，意思取决于解读规则——这是很多漏洞的根子。
  • 负数用补码存，8 位有符号数范围是 -128 到 127；127 + 1 变成 -128，这就是整数溢出。
  • 浮点数精度有限，0.1 + 0.2 不等于 0.3；钱和权限别交给近似值。
  • 文字是按编码表变成数字的，UTF-8 里英文 1 字节、汉字一般 3 字节；容量单位有 1024 和 1000 两本账。
